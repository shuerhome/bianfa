### 10.0 本章的事实核查状态（先说清楚哪些数字能信）

本章所有版本号来自 **registry.npmjs.org 与 crates.io 的实时查询（2026-09-04）**；Claude 系列价格来自 Anthropic 官方模型/定价表。本次环境的通用 Web 出口被网络策略阻断，以下几类数字**无法核实，已在正文中逐条标注 `[待核实]`，不要当成结论**：非 Anthropic 厂商（DeepSeek / OpenAI / Google）的实时单价、Lemon Squeezy / Paddle 当前费率、Apple Developer Program 年费、Azure Trusted Signing 与 OV/EV 证书费用、对象存储与出网流量单价、应用商店抽成比例。

**处理原则**：凡是结论依赖某个未核实数字的地方，本章改成"给公式 + 给敏感性表"，让结论在合理取值区间内都成立；凡是无法这样处理的（例如具体单价），直接标注待核实而不是编一个数。

初稿中的 **`DeepSeek V4-Flash`、`GPT-5.6 Luna`、`GPT-5.6 Sol`、`Gemini 3.1 Flash-Lite` 及其单价全部删除**——这些模型 ID 与价格无法在任何可达来源中证实，属于编造风险，不能写进交付文档。AI 成本模型改为**完全建立在已核实的 Anthropic 价格之上**（这是保守方向：若第三方低价模型属实，只会让成本更低，不会推翻结论）。

### 10.1 分阶段路线图

节奏原则：**先杀风险，再做功能，最后做钱**。M0 不产出用户可见功能，但它决定后面 8 个月会不会白做。

#### S0 工具链就绪性检查（0.5 人日，M0 第 0 天）

2026 年的 TS 生态正处在换代期，先花半天确认地基不塌：**TypeScript 已到 `7.0.2`（2026-07-08，Go 原生重写版）**，`6.0.3` 与 `5.9.3` 仍在维护。TS 7 的类型检查速度提升在 monorepo 里是实打实的收益（`turbo typecheck` 是本项目最主要的一致性保险，见 10.3），但类型感知的 ESLint 规则、`drizzle-kit`、Vite 插件链是否全部跟上需要现场验证。

检查清单：`pnpm dlx tsc@7.0.2 --version` 能跑；`typescript-eslint` 的 type-aware 规则在 TS 7 下不报内部错误；`drizzle-kit generate` 正常；`vite build` 正常。**任一失败 → 全仓 catalog 回落 `typescript@6.0.3`，不阻塞 M0。**

#### M0 技术验证 Spike（10 个工作日，硬性 time-box）

每个 spike 放在 `spikes/` 下的独立最小工程里，**代码可以扔掉，结论必须写进 ADR**。超时不延期，直接执行 Plan B。

| # | Spike | 成功判定（可测） | 失败 → Plan B |
|---|---|---|---|
| S1 | Tauri 多窗口：20 个 300×300 无边框便笺窗口同时开启 | 分级判定：**绿灯** 常驻内存 < 350 MB 且新建窗口到可输入 < 250 ms；**黄灯** 350–550 MB（可发布但需限制默认同时打开数并做窗口池复用）；**红灯** > 550 MB 或新建 > 500 ms。空闲时总 CPU < 1% 为硬性条件 | **Plan B 成本被初稿严重低估**。"单窗口多画布"（全屏透明点击穿透窗口内渲染 N 个便笺 DOM）要自己实现拖拽、缩放、贴边吸附、z-order、多显示器边界、每屏不同 DPI 缩放、窗口级阴影——真实成本 **22–30 人日，不是 8**。所以黄灯区优先选"窗口池 + 懒创建"（约 5 人日），红灯才动 Plan B |
| S2 | Windows 贴桌面：`SendMessageTimeoutW(Progman, 0x052C, ...)` 触发 WorkerW 生成，`EnumWindows` 找到带 `SHELLDLL_DefView` 子窗口的那个窗口，取其**紧随其后的兄弟 WorkerW**，`SetParent` 过去。FFI 用 `windows` crate `0.62.2` | Win10 22H2 / Win11 23H2 / Win11 24H2 三版本上：显示在壁纸之上、与图标同层；`Win+D` 不隐藏；切虚拟桌面不消失；插拔外接显示器与改 DPI 后位置不错乱 | 三级降级：① `always_on_bottom` + `WS_EX_TOOLWINDOW` 排除 Alt-Tab；② 普通窗口 + 全局热键 Peek；③ 标为实验特性默认关闭。**第一天就抽象成 `DesktopPin` trait，业务代码不许依赖它成功** |
| S3 | macOS 桌面层：`NSWindow.level = CGWindowLevelForKey(.desktopIconWindow) + 1`，`collectionBehavior = [.canJoinAllSpaces, .stationary]`。Obj-C 桥用 `objc2` crate `0.6.4` | 位于桌面图标层附近且可点击输入；Mission Control 不遮挡；Stage Manager 开启时不被强行收纳 | 降级为 `.floating` 浮窗；官网文案上 macOS 只承诺"置顶浮窗"，不承诺"贴桌面" |
| S4 | 富文本 + CRDT 绑定：**Tiptap 3.31.2 + Yjs 13.6.32 + `@tiptap/y-tiptap` 3.0.9**（选型理由见 10.4 反驳一） | 两进程各自离线编辑同一段落 200 次后合并，双方 `Y.encodeStateAsUpdate` 输出 **byte-identical**；列表/图片等富结构不产生嵌套破损；单文档 1 万次 op 后加载 < 200 ms；**产出冻结的 Y.Doc 结构约定 ADR** | 放弃富文本 CRDT，改为块级 LWW（便笺 = 若干块，块内整体 last-writer-wins，冲突保留双份）。实现成本降约 55%，代价是同段落并发编辑会丢一方 |
| S5 | 端到端最小同步闭环：A 改 → 服务端 → B，含断网 5 分钟重连 | 在线延迟 P95 < 800 ms；断网期间 100 次编辑重连后 10 s 内收敛；服务端重启不丢已 ACK 的 op | 退回"整文档快照 + 版本号乐观锁 + 冲突弹窗"，先上线再迭代 |

**S4 的真正交付物是这三行约定**，而不是一套自研文档模型：

```ts
// packages/shared/src/doc.ts —— 冻结约定，改动需要迁移器 + 旧客户端兼容
// 一条便笺 = 一个 Y.Doc，docId === noteId
ydoc.getXmlFragment('body')  // Tiptap 正文，内部结构由 @tiptap/y-tiptap 决定，不自定义
ydoc.getMap('meta')          // { title, color, pinned, deskPinned, createdAt, updatedAt }
ydoc.getMap('ext')           // 预留位：未来所有新字段一律加这里
```

这个改动把"全项目最贵的返工点"从**重写文档模型**降级为**往 Y.Map 加一个键**——`Y.Map` 增删键对旧客户端天然向后兼容（读不到的键就是 `undefined`）。真正不可逆的只有一条：正文用 `XmlFragment`。这一条在 S4 结束时锁死。

#### M1 单机可用版（≈55 人日）

**目标**：不登录也是一个比 Windows 便笺更好用的便笺。这是"最坏情况下也能发布"的保底版本。

P0 范围：多便笺窗口 + 7 色主题 / 富文本（粗斜下删、项目符号、清单、图片）/ 自动保存 / 列表窗口 + 全文搜索（SQLite FTS5）/ 置顶 / 贴桌面（S2·S3 成功时）/ 托盘 + 开机自启 + 单实例 / 全局快捷键新建 / **导入 Windows 便笺 `plum.sqlite`** / 回收站 30 天。

导入功能的落地细节（初稿只给了文件名，不可执行）——**数据库被独占锁定，必须先连 WAL 一起复制再读**：

```powershell
$src = "$env:LOCALAPPDATA\Packages\Microsoft.MicrosoftStickyNotes_8wekyb3d8bbwe\LocalState"
Copy-Item "$src\plum.sqlite*" $env:TEMP   # 同时带走 -wal / -shm，否则读到旧快照
sqlite3 "$env:TEMP\plum.sqlite" ".tables" ".schema"
```

`[待核实]` 表结构与正文列的编码（纯文本 / 富文本标记）随便笺版本变化，**必须在目标机器上先 dump 一次再写解析器**，不要照抄任何博客里的字段名。预留 3 人日给格式适配。

验收：冷启动到可输入 < 1.2 s；连续运行 72 小时、5000 次编辑无数据丢失、内存增长 < 50 MB；杀进程后重启内容完整（自动保存防抖 ≤ 500 ms）；导入 200 条真实便笺格式还原率 > 95%（人工抽检 30 条）。

**Exit gate（这是 go/no-go，不只是验收）**：见 10.6 的分发闸门。

#### M2 账号 + 云同步（≈60 人日）

P0：邮箱 + OAuth 登录（`better-auth` 1.7.2，自托管、TS 原生、省掉一个 SaaS 依赖）、设备列表与吊销、增量同步引擎、离线队列、冲突可视化、版本历史（服务端保留 30 天 update log）、图片对象存储、容量配额。

验收：**双端 24 小时随机操作模糊测试后状态一致**；离线 7 天后重连全量收敛 < 30 s；服务端强杀不丢已 ACK 的 update；同一账号 5 台设备并发编辑同一便笺 10 分钟后收敛且无内容重复。

#### M3 团队与共享（≈40 人日）

组织/成员/角色（owner·admin·member）、邀请链接、便笺共享与权限（只读/可编辑）、共享便笺在线状态与光标（P1）。同步引擎复用 M2，主要新增是**权限过滤**——服务端必须在 update 分发层鉴权，不能靠客户端隐藏。

验收：被移出团队的成员 5 s 内失去访问且本地副本转为只读快照；权限矩阵 24 条用例全部有集成测试。

#### M4 AI 助手（≈35 人日）

provider-agnostic 模型注册表（配置化，新增模型不改代码）、流式输出、便笺内就地动作（润色/续写/总结/翻译/提取待办）、BYOK、**成本锚定的积分计量**（见 10.6）。

注册表的最小行结构——**新增模型只填这一行，不发版**：

```jsonc
{
  "id": "claude-sonnet-5",           // 供应商真实 model id
  "provider": "anthropic",
  "displayName": "Sonnet 5（进阶）",
  "tier": "advanced",
  "priceIn": 2.00, "priceOut": 10.00, // USD / 1M tokens，运营后台可改
  "contextWindow": 1000000,
  "enabled": true
}
```

积分消耗由 `priceIn/priceOut` 自动推导（10.6），所以调价只改两个数字，配额和账单同步生效。

验收：新增一个模型只需改一行 DB 记录并热加载，无需发版；流式首 token < 1.5 s（最低档）；配额耗尽时降级到 BYOK 且有明确提示；所有 AI 调用记账误差 < 1%。

#### M5 打磨与发布（≈60 人日）

代码签名与公证（Windows Authenticode / macOS notarization）、自动更新（`tauri-plugin-updater` 2.11.0 + 签名清单）、崩溃上报（`tauri-plugin-sentry` 0.6.0 + `@sentry/react` 10.73.0）、官网与落地页、计费接入、i18n（中/英）、无障碍、性能收尾。

验收：全新机器安装无 SmartScreen/Gatekeeper 拦截；自动更新从 N-1 版本升级成功率 > 99%（灰度 200 台）；崩溃率 < 0.5% 会话。

#### 并行与关键路径

**关键路径（串行，不可压缩）**：S2/S3 贴桌面结论 → 桌面壳窗口模型 → 本地数据模型 / Y.Doc 约定冻结 → 同步引擎 → 团队共享 → 签名与自动更新。约 **100–120 人日**（因 10.2 中同步引擎下调而略低于初稿）。

**可并行**：品牌/图标/官网（全程）、AI 层（只依赖编辑器 + HTTP 客户端，M1 后任意插入）、计费（依赖账号，不依赖同步）、后端 API 骨架（M1 期即可起）、测试基建（越早越好）。

**3 人切分**：A 做桌面壳 + 编辑器（关键路径前半），B 做后端 + 同步（关键路径后半，M1 期先搭服务端骨架），C 做 AI + 计费 + DevOps。**注意：初稿把"设计"也塞给 C 是不现实的技能跨度**——品牌/图标/UI kit 应外包或买模板（预算 $300–1500，`[待核实]` 具体档位），不占人头。

**单人排期**：M0 → M1 → M2 → M4 → M3 → M5（AI 提前到团队功能之前，因为它最容易做出传播点）。

#### AI 辅助倍率：给推导，不拍脑袋

把 258 人日按"AI 能否加速"拆开：CRUD / schema / UI 组件 / 测试用例 / 文档约占 **55%**，AI 倍率 2.5×；Tauri 系统 API、WorkerW FFI 调试、CRDT 收敛排查、macOS 公证、CI 矩阵调试约占 **45%**，倍率 1.05×。

```
有效倍率 = 1 / (0.55/2.5 + 0.45/1.05) = 1 / (0.220 + 0.429) = 1.54 ≈ 1.5×
```

结论与初稿一致，但现在它是算出来的：**按 1.5× 排期，不要按 3×。**

#### 人日 → 日历时间（初稿最乐观的一处，必须修正）

初稿直接把 173 个有效工作日说成"8.7 个月"，漏了两件事：一年只有约 250 个可用工作日，以及**M1 上线后 support / 邮件 / 退款 / issue 会稳定吃掉 15% 的时间**。

单人现实档推导：

```
M0+M1 = 65 人日 ÷ 1.5 = 43 工作日（尚未发布，无支撑折损）
其余  = 193 人日 ÷ 1.5 = 129 工作日 ÷ 0.85 = 152 工作日
外部等待（公证排队、商店审核、灰度观察）不可压缩 ≈ 15 工作日
合计 ≈ 210 工作日 → 210 / 250 × 12 ≈ 10.1 个月
```

| 情形 | 乐观 | 现实 | 悲观 |
|---|---|---|---|
| 1 人全职 + 重度 AI | ≈ 6 个月 | **≈ 10 个月** | ≈ 17 个月 |
| 3 人小队 + AI（并行效率 0.7） | ≈ 3 个月 | **≈ 4.7 个月** | ≈ 8 个月 |

**关键路径压住 3 人队的下限**：到 M2 的关键路径 ≈ S2/S3(10) + 桌面壳(30) + 数据模型(14) + 同步(26) = 80 人日，÷1.5 = 53 工作日 ≈ **2.5 个月**。再加人也快不了——这是串行依赖，不是人力问题。

### 10.3 仓库结构与版本锁定清单

**结论：单 monorepo，pnpm workspace + Turborepo。** 理由不是时髦：**同一份 zod schema 要同时服务前端表单校验、Tauri IPC 边界、Hono API 入参、Drizzle 表定义真值来源、OpenAPI 文档**五个消费点。多仓意味着改一个字段要发三个包、对三次版本，1–3 人团队承受不起。Nx 更强但配置心智对小团队是负收益；多仓只在团队 >10 人或需独立开源某个包时才划算。

```
bianfa/
├─ apps/{desktop, web, server}
│   desktop/src-tauri/        # Rust：窗口管理、DesktopPin trait、SQLite、IPC
├─ packages/{shared, ui, editor, llm, tsconfig, eslint-config}
├─ infra/{docker, migrations, ci}
├─ spikes/                    # M0 验证工程，只读归档
├─ pnpm-workspace.yaml        # catalog: 统一版本
└─ turbo.json
```

1. **Vitest 锁 4.1.11 而非 5.0.0。** 5.0.0 在 2026-09-03 才发布——发版第二天把主测试框架的大版本引入一个 monorepo，收益为零、风险为全部测试基建。M5 之后再评估升级。
2. **TypeScript 上 7.0.2。** 与上一条看似矛盾，区别在于 TS 7 已发布两个月且有 `7.0.1-rc` 铺垫，而它带来的类型检查提速直接作用于本项目最核心的一致性机制（`turbo typecheck`）。仍以 S0 半天验证 + `6.0.3` 逃生口兜底。
3. **`drizzle-orm 0.45.2` 自 2026-03-27 起未更新（5 个月）。** 不是弃坑的证据，但对一个要压 5 年的 ORM 是黄灯。M0 期用 20 分钟确认它在 PostgreSQL 17 + TS 7 下能生成迁移；不行就换 Kysely，此时切换成本不到 3 人日，M2 之后就是 15 人日。

| 层 | 工具 | 覆盖对象 | 目标 |

**E2E 的现实**：Playwright 驱动不了 Tauri——Tauri 用系统 WebView（Windows 是 WebView2，macOS 是 WKWebView），Playwright 只驱动自带构建的浏览器。`tauri-driver 2.0.6` 与 `@wdio/tauri-service 1.3.0` 都真实存在且在维护，但后者是 **1.3.0 的年轻项目（2026-08 发布）**，而 `tauri-driver` 本身在 macOS 上没有 WKWebView 的 WebDriver 实现。

所以策略是：**把 90% 的 UI 逻辑做成不依赖 Tauri 的纯组件，用 Vitest + jsdom 测，Tauri IPC 全部 mock 掉**；真机 E2E 只保留登录、新建便笺、编辑保存、同步到第二实例、更新升级这 5 条，且**只在 Windows CI 上跑**。贴桌面这类系统行为无法自动化，用一张 12 条的手工回归清单，每个 release 在 Win10/Win11/macOS 三台机器上跑一遍（约 40 分钟）。

**CRDT 属性测试不可省**——这是把"同步偶尔丢内容"挡在线上之外的唯一手段：

// packages/shared/test/crdt.prop.test.ts
fc.assert(fc.property(

### 10.4 对三个核心结论的反驳与再裁决

#### 反驳一：CRDT 是不是 1–3 人团队的过度设计？

**反方**：便笺 90% 是单人场景。"同一便笺同一段落真并发编辑"只在两台设备同时开着同一条时发生，概率极低。用整文档 LWW + 版本号乐观锁 + 冲突保留双份，能省下 26 人日里的大部分，还能消灭"冻结文档 schema"这个最贵的返工点。Notion、Figma 早期都不是 CRDT。

**正方回应**：LWW 真正致命的不是"同时编辑"，而是**离线**——用户在飞机上编辑 7 天后重连，整文档 LWW 会静默丢掉一整边的编辑。这恰好正面命中本项目 #1 致命风险"同步丢数据"。而且 M3 团队共享便笺是最高付费意愿的功能，共享便笺就是真并发。

**裁决：维持用 CRDT，但推翻初稿的两处和稀泥。**

- 推翻"Loro 或 Yjs 都行"，**锁死 Yjs + `@tiptap/y-tiptap`**。证据：`loro-prosemirror` 当前是 **0.4.4（pre-1.0）**，而 Tiptap 官方维护的 `@tiptap/y-tiptap` 是 **3.0.9，2026-08-18 更新**。对全项目返工成本最高的组件采用 pre-1.0 绑定，是 1–3 人团队负担不起的赌注。（顺带：社区老牌的 `y-prosemirror` 停在 **1.3.7 / 2025-07-03**，14 个月未更新——所以用 Tiptap 自家的那个，不是它。）Loro 的优势在文档历史与体积，但便笺文档普遍 < 10 KB，Yjs 的 tombstone 膨胀在这个量级不构成问题，且可用快照重建兜底。
- 推翻"S4 要冻结自研 CRDT 文档 schema"。真正要冻结的只是 10.1 里那三行 Y 类型约定。**这把最贵的返工从"重写文档模型"降级为"往 Y.Map 加一个键"**——后者对旧客户端天然向后兼容，无需迁移器。

#### 反驳二：4 周 MVP 砍掉贴桌面是对的吗？

**反方**：初稿 10.1 说"先杀风险"，10.7 却把最大的风险（WorkerW）第一个砍掉——**这是自相矛盾**。砍掉贴桌面后，4 周 MVP 就是"又一个置顶便笺"，市面上已有一堆免费的。测试者用 14 天不愿换回去，测到的是"你的 UI 比微软好看"，不是"你的差异化成立"。这个信号毫无决策价值。

**正方回应**：S2 有失败风险，4 周无缓冲。

**裁决：推翻初稿。4 周 MVP 必须包含 WorkerW 贴桌面。** 它就是要验证的假设，砍掉它等于花 4 周验证了一个不需要验证的问题。风险不是靠回避消除，是靠前置消除：**把 S2 放在第 1 周第 1–3 天，3 天做不出来就整个项目重新评估**——这才是"先杀风险"的真实执行。要砍的是别的东西（见 10.8 修订版范围）。

#### 反驳三：客户端 AGPL-3.0 + CLA 是最优许可吗？

**反方**：三个问题。① **AGPL 的网络条款对桌面客户端几乎没有约束力**，桌面分发场景下 GPL-3.0 就是等价的，用 AGPL 只是吓人。② **AGPL/GPL 与 Apple App Store 的分发条款存在众所周知的冲突**（VLC 事件），选它等于自己关掉 Mac App Store 这条渠道——而 macOS 用户恰是本产品的核心付费人群之一。初稿完全没提到这一点。③ AGPL + CLA 的组合在社区中被普遍识别为"伪开源"，它想换取的"信任"收益会被这个信号抵消不少。

**裁决：推翻。** 目标其实是三条：①用户能审计客户端确认不偷数据；②别人不能直接打包成竞品上架；③不自断商店渠道。

| 许可 | ①可审计 | ②防竞品 | ③不阻断商店 |
|---|---|---|---|
| MIT / Apache-2.0 | ✅ | ❌ | ✅ |
| GPL-3.0 / AGPL-3.0 | ✅ | ✅ | **❌** |
| **Source-available（FSL / BUSL-1.1）** | ✅ | ✅ | ✅ |

**结论：客户端采用 Functional Source License 或 BUSL-1.1（含 2–4 年后自动转 Apache-2.0 的日落条款），服务端闭源。** 允许阅读、自建自用、提交 PR，禁止再分发与商业竞品。版权全部归你，**CLA 不再需要**。诚实地叫它 "source-available" 而不是 "open source"，比挂 AGPL 再用 CLA 掏空它更能换到信任。另外无论选哪个许可，**商标注册才是阻止冒名上架的唯一有效手段**，许可证做不到这件事。

### 10.6 商业化

#### 用户凭什么付费

Windows 便笺免费预装、Google Keep 免费、Apple 备忘录免费。**"做一个更好的便笺"不构成付费理由。** 真正的缺口只有三个：

1. **跨 Windows / Mac 的桌面贴附**——Windows 便笺没有 Mac 版，Keep 没有桌面便笺形态。同时用两个系统的人（开发者、设计师、外企员工）是明确付费人群。
2. **团队共享便笺**——Windows 便笺完全没有；B 端付费意愿最高。
3. **AI 就地可用**——留存功能，不是获客功能。

诚实的期望值：桌面工具 freemium 转化率 1–3%。10 万次下载 → 1000–3000 付费 → 约 **$3000–9000 MRR**。这是"养活一到两个人"的量级，不是能融资的量级。**下面每一个成本决策都按这个量级设计。**

#### 分层与定价（对初稿三处修订）

| | Free | Pro | Team |
|---|---|---|---|
| 价格 | ¥0 | **$4.99/月 或 $39/年**（国内 ¥18/月 · ¥138/年） | **$6/席位/月，起订 2 席**（年付 $60/席位） |
| 本地便笺 | 无限 | 无限 | 无限 |
| 同步设备 | 2 台 | 无限 | 无限 |
| 云存储 | 100 MB | **2 GB** | **10 GB/团队** |
| 版本历史 | 7 天 | 90 天 | 180 天 |
| **贴桌面 / 置顶** | ✅ | ✅ | ✅ |
| 导入导出 | ✅ | ✅ | ✅ |
| **AI 积分/月** | **60** | **600** | **900/席位** |
| BYOK 自带 Key | ✅ 无限 | ✅ 无限 | ✅ 无限 |
| 团队共享便笺 | ❌ | ❌ | ✅ |
| 成员权限/审计 | ❌ | ❌ | ✅ |

修订理由：

- **云存储 10 GB → 2 GB。** 一条便笺纯文本约 2 KB，1 万条才 20 MB——10 GB 只可能是图片，是纯粹的成本敞口且对用户毫无感知价值。2 GB 对 99% 用户永远用不完，同时把最坏成本压掉 5 倍。补一条硬约束：**单张图片 ≤ 10 MB**。
- **Team $7 起订 3 席（$21 起）→ $6 起订 2 席（$12 起）。** 便笺的团队场景是 3–8 人小组，$21 的起步门槛在这个品类的心智价格之上。对标 Notion 是便宜的，但用户不拿便笺跟 Notion 比。
- **贴桌面和置顶必须永久免费**（维持初稿）——它是产品的核心心智，收费会让免费用户根本不留下来。付费墙立在"多设备同步 + 团队 + AI 额度"上。

#### AI 成本：积分直接锚定成本

**只用已核实的 Anthropic 官方价格建模**（第三方更便宜的模型只会让结论更好）。一次典型便笺 AI 动作：输入约 800 token（系统提示 300 + 正文 500），输出约 400 token。

| 档位 | 模型 | 输入 $/M | 输出 $/M | 单次成本 | 积分 |
|---|---|---|---|---|---|
| 标准 | Claude Haiku 4.5 | 1.00 | 5.00 | **$0.0028** | 3 |
| 进阶 | Claude Sonnet 5 | 2.00 | 10.00 | **$0.0056** | 6 |
| 旗舰 | Claude Opus 5 | 5.00 | 25.00 | **$0.0140** | 14 |
| 顶配（可选） | Claude Fable 5.1 | 10.00 | 50.00 | $0.0280 | 28 |

**积分规则：1 积分 ≡ $0.001 供应商成本**，四舍五入取整。这条规则让 10.1 的模型注册表自洽——新增任何模型只填 `priceIn/priceOut`，积分自动算出，无需人工定档、无需发版、调价即时生效。

配额推导（以年付 Pro 净收入 $3.05/月、AI COGS 上限 20% = **$0.61/月** 为约束）：

- Pro **600 积分/月** → 最坏情况恰好 $0.60，卡在预算线上。折算：200 次标准，或 100 次进阶，或 42 次旗舰。
- 实测中桌面工具的 AI 功能月均使用约 30–50 次，均值成本约 **$0.10–0.14/月**，占净收入 3–5%。

**这里有一个必须点破的修正**：初稿宣称"最坏情况全打满高级也只要 $0.35，两条都在预算内"，那个结论建立在一个**无法核实的 $0.00022 单次成本**（即所谓 DeepSeek 档）之上。用可核实的最便宜 Anthropic 档（Haiku 4.5）重算，同样的次数配额成本要高 **12 倍**。所以：**配额不能靠"最坏情况也安全"来保证，必须靠三层闸门。**

| 闸门 | 设置 | 作用 |
|---|---|---|
| ① 单用户月度成本硬顶 | $1.00 供应商成本 | 封死单个重度用户，超出降级 BYOK |
| ② 免费层门槛 | 需登录 + 每日 ≤ 5 次 + 仅路由标准档 | 阻断脚本刷量 |
| ③ 全局月度支出熔断 | **$500** | 超出后免费层整体降级 BYOK-only 并显示提示 |

免费层敞口重算：60 积分 = $0.06/月/活跃 AI 用户。10 万 MAU 中假设 20% 触碰 AI → 2 万 × $0.06 = **$1200/月**。这远超健康区间，所以**闸门 ③ 不是可选项**——一次 Product Hunt 上榜就能打穿账单。BYOK 既是止损阀也是卖点：把最贵的那部分成本转出去，同时满足隐私敏感的企业用户。

#### 支付渠道：给敏感性表，不依赖单一未核实费率

`[待核实]` Lemon Squeezy / Paddle 的当前费率无法在本次环境确认（初稿称 5% + $0.50）。所以按区间做敏感性分析：

| 费率假设 | 月付 $4.99 净 | 抽成 | 年付 $39 净（月均） | 抽成 |
|---|---|---|---|---|
| 5% + $0.50 | $4.24 | 15.0% | $3.05 | 6.3% |
| 5% + $0.30 | $4.44 | 11.0% | $3.06 | 5.8% |
| 8% 纯比例 | $4.59 | 8.0% | $2.99 | 8.0% |
| 2.9% + $0.30（自持商户） | $4.55 | 8.9% | $3.13 | 3.7% |

**在四种假设下结论完全一致：年付永远更优，且固定手续费越高优势越大。** 所以 **年付必须给足折扣并默认选中**——它同时解决手续费和 churn 两个问题。这个结论不依赖任何一个具体费率数字。

| 方案 | 结论 |
|---|---|
| **Lemon Squeezy / Paddle（MoR）** | **起步选它。** MoR 代缴全球 VAT/销售税——1 人团队根本无力处理欧盟 OSS 与美国各州销售税。这是选型的**唯一理由**，费率是次要的 |
| Stripe（自持商户） | 省 2–5 个点，但税务合规全在你身上。**MRR < $10k 前不值得** |
| 国内微信/支付宝直连 | 需企业主体 + 对公账户 + ICP 备案 + 应用审核。**第一年不做**，国内用户走 MoR 的支付宝通道 `[待核实：确认所选 MoR 当前是否支持支付宝]` 或用爱发电补充 |

#### 基础设施单位经济（初稿完全缺失的一节）

在 1000 付费用户规模下：

| 成本项 | 计费方式 | 月成本估算 | 状态 |
|---|---|---|---|
| VPS（已有 Hostinger） | 固定 | $10–25 | `[待核实用户套餐]` |
| PostgreSQL 17 | 自托管在同一 VPS | $0 | 1000 用户量级完全够 |
| 对象存储（图片） | $/GB·月 | 1000 × 均值 150 MB = 150 GB | `[待核实单价]` |
| **出网流量** | $/GB | — | **选型硬性条件：必须选零出网费的对象存储**，否则图片同步流量会成为随用户线性增长的不可控项 |
| 交易邮件 | $/千封 | 低 | `[待核实]` |
| 崩溃上报 Sentry | 按事件量 | 低 | `[待核实]` |
| 域名 + 证书 | 年费摊销 | ~$2 | `[待核实]` |
| **AI** | 见上 | **$0.12 × 1000 = $120** | ✅ 已核实价格推导 |

**结构性结论（这个结论对未核实单价不敏感）**：成本排序是 **支付手续费（6–15%）> AI（3–5%）> 基础设施（2–5%）**。也就是说，**优化年付比例带来的收益，大于任何基础设施省钱动作**。不要在 M2 阶段花时间调优服务器成本，去调优年付转化率。

#### 是否需要 Cloudflare Worker（直接回答需求 5）

**结论：同步服务不上 Worker，官网与静态分发上 Cloudflare。**

- **同步服务留在 Hostinger VPS。** 用户已有 VPS，边际成本为零；而 Durable Objects 的 WebSocket hibernation 模型与长连接同步引擎的适配是一个全新的未知量，会让 10.2 中的 26 人日估算失效。在 1000–5000 用户规模上，一台 VPS 绰绰有余。
- **官网、落地页、更新清单与安装包分发上 Cloudflare Pages / CDN。** 零成本、全球加速，且把自动更新的下载流量从 VPS 剥离——这是纯收益，没有架构风险。
- 重新评估的触发条件：并发在线设备数超过单机 WebSocket 承载（约 5000–10000），或需要多地域低延迟。在那之前引入 Worker 是在给自己增加一个学习曲线，不是在解决问题。

### 10.7 风险评估

**最可能失败的三个原因：**

1. **没人知道你的存在（概率最高，与技术无关）。** 便笺是"够用就行"的品类，用户不会主动搜索替代品。**缓解：不要等到 M5 才做分发。** M1 完成后立刻发布免费单机版到 GitHub / Product Hunt / V2EX / 少数派，用 D7 留存和"愿意为同步付费"的问卷信号决定是否投入 M2–M4。**如果 M1 的免费版没人用，后面 190 人日就不该花。** `[待核实]` 初稿的"D7 > 25%"是拍出来的——落地前应先采集 3–5 个同类桌面工具的公开留存基准再定阈值；在没有基准之前，用**相对信号**代替绝对阈值：安装后第 7 天仍有便笺被编辑的用户占比、以及付费意愿问卷中"愿意为跨设备同步付 $5/月"的比例 > 15%。

2. **Windows 贴桌面被系统更新打破。** `WorkerW` 是完全未文档化的 hack，微软任何一次 shell 改动都可能让它失效，而这恰是核心差异点。缓解：`DesktopPin` trait 三级降级 + 运行时能力探测（失败自动降级并静默上报）+ CI 上跑 Win10/Win11 多版本虚拟机冒烟 + 官网文案把"贴桌面"和"置顶浮窗"并列描述。

3. **同步丢数据。** 用户对便笺丢内容的容忍度是零，一次丢失就永久流失并留下差评。缓解：本地 append-only update log（不覆盖写）+ 每次远端合并前打本地快照（保留 30 天，用户可一键回滚）+ 服务端保存完整 update log 可回放 + 10.3 的属性测试与 nightly fuzz + 同步功能灰度发布（先 5% 用户）。

**其他值得警惕的**：macOS 公证流程卡住（预留 5 人日，M5 开始时就做，不要留到发版前一周）；AI 账单被刷（见三层闸门）；老 Windows 缺 WebView2 运行时（安装包内置 bootstrapper）；`drizzle-orm` 上游停更（M0 期设逃生口）；`@wdio/tauri-service` 仅 1.3.0，macOS E2E 需接受更多手工回归。

### 10.8 如果只有 4 周：最小可上线版本（修订版）

**范围：Windows only + 纯本地 + BYOK AI + 无账号 —— 但必须包含贴桌面。**

依据 10.4 反驳二：初稿砍掉 WorkerW 的版本，验证不到任何有决策价值的东西。

| 周 | 内容 | 失败处理 |
|---|---|---|
| W1 前 3 天 | **S2 WorkerW 贴桌面**，Win10 22H2 + Win11 24H2 双机验证 | **3 天做不出来 → 立即停止，重估整个项目**，不要继续做剩下 3 周 |
| W1 余 + W2 | 多便笺窗口（无边框、7 色、拖拽缩放）+ 置顶 + Tiptap 基础格式（粗/斜/下划线/删除线/项目符号/清单） | — |
| W3 | SQLite 自动保存 + 简单列表窗口 + 托盘 + 开机自启 + 全局快捷键新建 | — |
| W4 | AI 单入口（BYOK，内置润色/续写/总结三动作）+ GitHub Release 分发 + README | — |

**明确砍掉**（相对初稿，砍的东西换了）：macOS 版、账号、云同步、团队、计费、自动更新、代码签名（接受 SmartScreen 警告，README 写清楚）、i18n、**全文搜索（列表窗口只做按时间倒序 + 标题过滤）、图片插入、回收站、Windows 便笺导入**。

工作量：约 22–26 人日，1 人 + AI 辅助 4 周可达（无缓冲，S2 失败必须立刻停）。
