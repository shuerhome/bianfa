# bianfa 最终视觉方向与设计系统规范

## 1. 最终方向：**淡彩纸 / Tinted Paper**

> **一句话定位**：界面骨架是一张暖中性的素纸，便笺身份是一整张淡彩纸——**桌面上是纸，列表里是墨线**；颜色只承载分类，一个比特都不承载可读性。

### 1.1 为什么这样融合

三位评审的共识是清晰的：**方向 2 三票垫底**（工程预算花在主场景 15% 的像素上、品牌为零、以 Windows 中文可读性换材质），**方向 1 三票稳居第二**（光学功力最强但 220px 上兑现不了、圆角是死结），方向 3 拿下 craft/feasible 两票第一，方向 4 拿下 fit 票第一。

**主干取方向 3（纸感极简）**：它的三条资产是正交于审美的纯收益——暖中性灰轴（`#FCFCFB` 而不是 `#FFFFFF`，成本 0）、overlay chrome 的密度手法（滚动条压 padding / 标题栏 absolute / 首行即标题，白拿 25–30 字）、BF Punct 标点子集（唯一让两个引擎走同一条中文排版路径的方案）。它的失败模式是"无聊"，不是"廉价"——对一个没有专职设计师的团队，这是决定性的。

**嫁接方向 4 的核心机制，并用它修掉方向 3 的致命伤**：fit 评审对方向 3 最狠的一刀是"3px 色带 = 便笺表面积的 1.4%，把便笺唯一的零成本信息架构压到失效阈值以下"。这一刀成立，但它的解不是"整个产品都染色"。**最终方案把染色语境化**：

| 语境 | 着色策略 | 理由 |
|---|---|---|
| 桌面独立便笺窗口 | **整面淡彩纸**（`--note-paper`） | 15 张浮在花壁纸上，需要前注意（pre-attentive）的大面积色块才能 0.5 秒定位 |
| 主列表 / 团队墙 / 回收站 | 中性卡片 + **3px 左色条 + 8px 色点** | 50 条同屏，整块着色会变拼布被 |
| AI 面板 / 设置 | 纯中性，零着色 | 流式长文在中性灰底上最好读 |

这条分界线来自方向 4 的原则五（大面积极低饱和 / 小面积高饱和，中间地带非法），它同时满足了 craft 的"不要拼布被"和 fit 的"必须能一眼找到"。

**嫁接方向 4 的明度锁定 + 生成器**：10 色便笺全部锁在同一 OKLCH 明度（亮 `L=0.915` / 暗 `L=0.290`），正文墨色锁在另一条（亮 `L=0.300` / 暗 `L=0.905`）。实测正文对比度极差只有 **0.35**（10.47–10.82:1）。token 由 `tokens.mjs` 从 5 个明度常数 + 10 行 `(name, hue, m)` 表生成，CI 跑全矩阵对比度门禁——**生成器 > lint**，这是三位评审里唯一被点名"可持续"的维护模型。

**嫁接方向 1 的光学三条**：① 墨色继承纸色相（环境色反射，真纸与塑料色块的分界线）；② 阴影必须有 blur ≤ 1px 的接触阴影层 + 全部大模糊层带负 spread + 阴影色不是纯黑；③ 工具栏双条件触发（`聚焦 AND 悬停`），一次性解掉方向 3 自述的"鼠标扫过 15 个窗口像波浪"。另加它的 Windows 推论链：**不透明 → ClearType → 接受直角**。

**放弃的**：
- **整个方向 2**。平台分叉预算、Mica/Vibrancy、系统强调色桥、双基准字号，全部不要。只保留三条**合规项**（不是方向）：Win11 caption 46×32 / 关闭红 `#C42B1C`、Snap Layouts 的 `HTMAXBUTTON`、macOS 小窗自绘单个关闭点。
- **方向 1 的纹理系统**：feTurbulence 噪声、vignette、翻角、手写体。220px 下不可辨，却要付栅格缓存 + DPR 切换重绘 + 双主题双 tile 的全额成本。有成本无收益比有争议更该砍。
- **方向 4 的 13 色与全局等色度**。C=0.044 被最窄色相靛蓝绑架，橙和红分不清是逻辑自伤。改为：**同明度 + 各色相取该明度下 sRGB 最大在色域色度的 75%**（再乘 Helmholtz–Kohlrausch 补偿系数 m）。实测色度落在 0.013–0.090，与方向 1 的手挑纸色同一量级。色数砍到 **10**（9 色相 + 石墨），最小 Δh = 30°，映射 `Ctrl/Cmd+1~9` + `Ctrl/Cmd+Shift+0`（石墨；`Ctrl/Cmd+0` 让给「界面缩放复位 100%」，见 §2.3 与 §7）。
- **方向 3 的 Tint 三档设置项**。默认态解决不了的问题不许外包给设置。

## 2. Design Token 体系

### 2.1 三层命名规范

```
L1  --p-*     Primitive   原始灰阶 / 色相原料 / 数列。组件禁止直接引用。（CI: grep -rn 'var(--p-' src/components/ 必须为空）
L2  --c-* --fs-* --sp-* --r-* --sh-* --dur-* --delay-* --z-*   Semantic   角色语义。组件唯一可用层。
L3  --note-* --btn-* --input-*  Component   组件/实例局部变量，只在组件内部定义，只引用 L2。
```

唯一例外：`--note-paper/-ink/-ink2/-line/-dot` 与协作者色 `--note-dot-user` 由 JS 按便笺颜色 / `userId` 赋值，从 L1 色板直通 L3，不经过语义层——它是产品身份，不参与主题重映射。

**全部 L1/L2 由 `tokens.mjs` 生成**，输入 = 5 个明度常数 + 10 行 `(name, hue, m)` + 语义色表，输出 = `tokens.css` + 一份「每个前景 × 每个背景」的 WCAG 矩阵报告。

**对比度门禁按「对类」给阈值，不是一条全局 4.5。** 一条全局 `任何一对跌破 4.5:1 即 fail build` 会把本规范里最扎实的一层判死（10 色 `dot/paper` 3.50–3.94、`focus ring/paper` 4.08–4.28、`line/paper` 1.24–1.34、`--c-text-disabled` 3.30/2.91、分隔线 <1.5，全部是按 WCAG 1.4.11 的 3:1 门槛或"不承载信息"有意设计的值，会产出 100+ 对假失败）；同时它**放过**真正该更严的地方——便笺 ink 的承诺是 ≥10:1，4.5 抓不住"某个色相的 ink 掉到 8:1"这种真实退化。所以按对类给阈值**不是放松，是同时收紧和放宽**：

| 对类 | 内容 | 阈值 | 门禁 |
|---|---|---|---|
| `body-text` | `--c-text-1/-2` × 各表面（含 hover/active 合成底） | ≥ **4.5** | fail |
| `tertiary-text` | `--c-text-3` × **T3_BG 白名单**底面 | ≥ **4.5** | fail |
| `note-ink` | 10 色 `ink` × `paper`（亮/暗） | ≥ **10** | fail |
| `note-ink2` | 10 色 `ink2` × `paper`（亮/暗） | ≥ **4.5** | fail |
| `on-accent` | `#FFF` × `--c-accent(-hover/-active)` / `--c-danger` / **`--c-danger-hover`** / **`--c-danger-active`** / `--c-success` / `--c-warning` | ≥ **4.5** | fail |
| `semantic-text` | 语义色文字 × 对应 `*-subtle` 底 | ≥ **4.5** | fail |
| `tooltip` | `--c-tooltip-text` × `--c-tooltip-bg` | ≥ **4.5** | fail |
| `note-mark` | 10 色 `ink` × `--note-mark`（搜索命中高亮底） | ≥ **4.5** | fail |
| `note-sel` | 10 色 `ink` × `--note-sel`（选区底） | ≥ **4.5** | fail |
| `note-dot` | 10 色 `dot` × `paper` / `#FFFFFF` | ≥ **3**（1.4.11） | fail |
| `focus-ring` | `--c-focus` × 10 张纸 | ≥ **3**（1.4.11） | fail |
| `disabled` | `--c-text-disabled` × 各表面 | — | **只报告** |
| `borders` | `--c-border-subtle/-/-strong` × 各表面 | — | **只报告** |
| `note-line` | 10 色 `line` × `paper`（同色相实色描边，低对比是设计意图） | — | **只报告** |

**`warn` 档**：实测 ≥ 门槛但余量 < 0.25 → CI 输出警告并在 PR 里注释，不 fail。当前会命中 `note-ink2`（4.63–4.79，余量 0.13）与暗色 `--c-text-2` on `--c-active`@`surface-3`（4.69，余量 0.19）——这条能在有人微调 `L.ink2` 常数时提前报警，而不是等到跌破才红。`report:true` 的三个对类在 `contrast-matrix.md` 里**单独成节，每节带「不门禁的理由」一行**，否则它们迟早会被当成"漏测"再加回门禁。

两条必须同时执行的算法约束：

1. **半透明底的合成基底按模式取最亮表面，不得一律用 `canvas`。** 暗色取 `--c-surface-3`、亮色取 `#FFFFFF`（`--c-overlay`）。`--c-hover:rgba(255,255,255,.045)` / `--c-active:rgba(255,255,255,.075)` 压在**最亮**表面上才是最坏情形：`--c-text-2 #A3A299` on `--c-active` over `canvas` = 6.00（余量充裕），over `surface-3` = **4.69**（余量 0.19）；`--c-text-3 #96958B` 同样从 5.11 掉到 **3.99**。用 canvas 合成会让门禁失去它本该有的余量警报。
   > **`T3_BG` 白名单**（`--c-text-3` 的合法底面）= `--c-canvas` / `--c-surface-1` / `--c-surface-2` / `--c-surface-3` / `--c-overlay`（暗色另含 `--c-selected`）。**排除 `--c-hover` 与 `--c-active`**——暗色 3.99、亮色 4.23，都不合格；需要在这两个底面上出现的次级文字（菜单/popover 的右对齐快捷键）一律改用 `--c-text-2`。
2. **所有对比度注释一律必须带底面名，且由生成器自动写入而非人手标注。** 历史教训：`--c-text-3:#8B8A81; /* 5.02:1 */` 没写底面名，导致下游把 5.02 误当成 canvas 上的值（实为 surface-1；canvas 是 5.36），并因此漏掉了 surface-3 上的 4.36 ✗。注释应当是 formatter 的产出物，形如 `/* 5.02 on surface-3 · 6.17 on canvas · 合法底面白名单 T3_BG */`。

### 2.4 最低运行基线与三层特性规则

**最低支持基线 = macOS 14.4 / WebKit ≡ Safari 17.4；Windows = WebView2 Evergreen ≥ Chromium 140。**

```jsonc
// tauri.conf.json
"bundle": { "macOS": { "minimumSystemVersion": "14.4" } }
// vite.config.ts
build: { target: ['chrome140', 'safari17.4'] }
```

**为什么是 14.4 而不是 14.0**：macOS 14.0 出厂的是 Safari 17.0，没有 `linear()`。14.4（2024-03）是 Safari 17.4 的系统切点，且任何还在收 Apple 更新的 macOS 14 机器早已越过它（终版 14.7.x ≡ Safari 18.6）。选 14.4 让「基线」是一个数，而不是「一个 OS 版本加一串特性例外」。macOS 13 Ventura 自 2025-09 起已不再收到安全更新，而 WKWebView 是**系统组件、只随 OS 更新**——我们会把 AI 供应商返回的 Markdown 渲染进这个引擎，这是安全问题，不是兼容问题。Tauri v2 本身支持 macOS 10.15+，**框架不构成任何约束**，约束 100% 来自 WebKit 特性与安全窗口。

**Windows 三条必须落到工程里的推论**（否则「Evergreen 基本不存在问题」会变成「偶发存在」）：
1. 安装器必须带 **Evergreen Bootstrapper**；启动时用 `GetAvailableCoreWebView2BrowserVersionString` 检查 runtime ≥ **140.0.0.0**，低于则引导更新。不假设「Win11 一定有」。
2. **禁止 Fixed Version 分发模式**——它会把 Chromium 冻结在打包那天，等于自造第二条 macOS 式的老基线，还额外付 ~180MB 体积。CI：`grep -rn 'WEBVIEW2_BROWSER_EXECUTABLE_FOLDER\|fixed[-_.]version' src-tauri/ apps/` 必须为空。
3. 企业组策略可以延迟/固定 Evergreen 更新，所以**运行时版本检查是必需的**，不能靠「Evergreen 永远最新」写代码。

**三层特性规则（机械可执行，写进 review checklist）**

| 层 | 范围 | 用法 |
|---|---|---|
| **无条件可用** | Safari ≤ **17.4** 已 ship | 直接写，不加 `@supports` |
| **允许但必须带降级** | Safari 17.5 – 18.6 | 必须 `@supports` / `CSS.supports()`，且**降级路径不得改变换行结果**（红线 3） |
| **禁止** | Safari ≥ 26 独有 | 一律不用，**不做双路径** |

**落到具体特性：**

| 特性 | 层 | 处置 |
|---|---|---|
| `linear()` 缓动（Safari 17.2） | 无条件 | 可用；仍加 3 行 `@supports` 兜住 14.0–14.3 长尾（§2.2 已实现） |
| container queries / `:has()` / `oklch()` / `color-mix()` / `@property` / `overflow:clip` / `cq` 单位 | 无条件 | 可用 |
| `light-dark()`（17.5） | 带降级 | 已按 §6.2 走三段式选择器，本来就不作为唯一机制 ✓ |
| `text-box-trim`（18.2） | 带降级 | 仅 `.btn/.tab/.badge`，用 `@supports (text-box: trim-both cap alphabetic)` 包住；不支持时行盒略高，**不改宽度、不改换行** ✓ |
| **CSS Anchor Positioning（26.0）** | **禁止** | 单路径 Floating UI，见下 |
| `text-spacing-trim` / `hanging-punctuation` / `field-sizing` / `scrollbar-color` | 禁止 | 维持 §3.3 的既有裁定 |

**降级路径 ①：`linear()` 不可用时** —— 见 §2.2 的 `--ease-spring` 两段式。CSS 与 WAAPI 共用同一条字符串，禁止两处各写各的：

```ts
// packages/ui/src/motion.ts
const SPRING_LINEAR =
  'linear(0, 0.164, 0.470, 0.746, 0.931, 1.026, 1.057, 1.053, 1.037, 1.020, 1.007, 1.000, 1)';
export const EASE_SPRING =
  CSS.supports('transition-timing-function', 'linear(0, 1)')
    ? SPRING_LINEAR
    : 'cubic-bezier(.34, 1.30, .52, 1)';
export const DUR_SPRING = 360;   // --dur-5，两条分支同时长；差别只是尾部没有二次回弹
```

两条分支同时长、同起止值，只有 5.8% 超调后的尾部形状不同，位移量 ~13px（§5.7 的 `scale(.94)→1`），肉眼不可分。**代价是 3 行 CSS + 1 个三元表达式，买断整条尾巴。**

**降级路径 ②：Anchor Positioning → 单路径 Floating UI，不做双实现。** 理由不是「省事」：Anchor Positioning 与 Floating UI 的翻转/推挤语义不同（`position-try-fallback` 的 `flip-block` vs `flip()` middleware 的候选序），双路径会让同一条格式浮条在 macOS 26 与其它环境上**落在不同位置**——这正是 §3.3 那条「要么两平台都开、要么两平台都关」所禁止的分叉类型。全 app 唯一的浮层定位入口是 `useAnchored()`（`strategy:'fixed'` + `autoUpdate` + `offset/flip/shift/size`）。两条必须写进代码注释的约束：① 浮层必须 portal 到 `.note-shell` 的兄弟节点 `#float-root`，**不得挂在 `.ai-stream` 内部**（`contain: layout style` 会成为 `position:fixed` 的包含块）；② 任何祖先上残留的 `transform`（**包括 `scale(1)`**）同样会成为包含块——动画结束必须写 `transform: none`，不是 `scale(1)`。

> **一句话结论：Windows 的下限是一个我们随时可以抬高的构建常量；macOS 的下限是一个只能靠放弃用户才能抬高的系统版本。所以整个产品的特性基线 = macOS 基线，Windows 侧永远只做「不低于 macOS 基线」的运行时检查，不单独开任何特性。**

## 3. 中英文混排规范

### 3.1 字体栈与字重

Windows 主力实为 `Segoe UI`（`Segoe UI Variable Text` 在 webview 里按名字取不到，写在栈首是零成本白赚），中文走 `Microsoft YaHei UI`；macOS 走 `-apple-system` + `PingFang SC`。**西文必须排在中文之前**——否则英文和数字会用苹方/雅黑自带的西文字形渲染，字宽明显更松。

**字重现实**：`Microsoft YaHei` 只有 400 / 700（Win11 另有 Light 300），**没有 500/600**。写 `font-weight:600` 会触发合成假粗，13px 中文笔画糊成一团——这是中文界面显廉价的头号来源。因此：全局 `font-synthesis-weight:none`；`[data-os="windows"]` 下 `--fw-medium:400`（用颜色提一级补偿）、`--fw-strong:700`。**字距不做平台分叉——两平台一律 `letter-spacing:.01em`**（改字距会改行盒宽度进而改换行位置，违反红线 3）。**推论必须一起接受：层级靠「字号 + 颜色 + 字距」建立，不靠字重。**

内嵌字体只有两个，合计 ≤ 55 KB：`BF Punct`（标点子集，见 3.3）与 `Inter` 拉丁子集（可选，统一两平台数字字面）。**一个中文正文字节都不嵌**——Noto Sans SC 单字重 woff2 ≈ 1.5 MB，会让 Tauri 安装包翻倍。

|---|---|---|---|
| `--fs-2xs` 11 | 11 | 1.45 / 16px | 时间戳、快捷键、计数 |
| `--fs-xs` 12 | 12 | 1.5 / 18px | 工具栏标签、徽标 |

西文可以 1.4–1.5，中文方块字没有 x-height 提供的呼吸，**正文最低 1.62**。所有时间戳、计数、字数一律 `font-variant-numeric: tabular-nums`——列表里数字跳动会直接破坏静态感。中文正文 `letter-spacing:.01em`，`:lang(en)` 段落归零。

### 3.3 标点与自动间距：当前 CSS 支持（2026-09 核实）与本方案的决策

| 特性 | Chromium / WebView2（Windows） | WebKit / WKWebView（macOS） | 所属层（§2.4） |
|---|---|---|---|
| `text-autospace`（中西自动间隙） | 仅实验/子集实现，`ideograph-alpha` 不认 | Safari 18.4+ 已 ship，**初值被设为 `no-autospace`**，需显式声明才生效 | **无条件**（我们只声明 `no-autospace`；不认这个属性的引擎本就不自动加间隙，两边结果一致） |
| `text-spacing-trim`（全角标点挤压） | Chrome 123+ 支持，默认 `normal` 即已挤压 | **至今未 ship**（Safari 26.x 正式版无；STP 250 里的是另一个属性 `white-space-trim`） | **禁止依赖**（仅用于写 `space-all` 关掉 Chromium 的引擎级挤压，挤压交给字体层） |
| `text-box-trim`（光学基线裁切） | Chrome/Edge 133+ | Safari 18.2+ | **带降级**（`@supports` 包住，仅 `.btn/.tab/.badge`；不支持时行盒略高，不改宽度不改换行） |
| `hanging-punctuation` | 从未实现 | Safari 16+ | **禁止** |
| `scrollbar-color` | 支持 | 名义 26.2+，**BCD #29315 实测 26.3 macOS 无效** | **禁止**（stylelint 拦截，见 §5.5） |

**决策（这是本规范里最硬的一条）**：任何会改变行盒宽度、进而改变换行位置的特性，**要么两平台都开、要么两平台都关**，绝不做"哪边支持哪边开"的渐进增强。同一张便笺在两台电脑上换行位置不同，对同步型产品是正确性缺陷，不是审美差异。

```css
.bf-prose{                       /* 唯一的正文排版类；便笺正文 DOM 为 <div class="note-body bf-prose"> */

  text-spacing-trim:space-all;   /* 关掉 Chromium 的引擎级挤压，交给字体层 */
  letter-spacing:.01em;          /* 中西之间的呼吸由字距提供，两平台完全一致、无 [data-os] 分叉 */
  line-break:strict;             /* 中文禁则：。，、」不落行首 */
  word-break:normal; overflow-wrap:anywhere;   /* 220px 下长 URL 必须能断 */
}
code,pre,kbd,.tabular{ font-family:var(--f-mono); letter-spacing:0; }
```

## 4. 核心组件规范

**控件尺寸不分叉**（这是放弃方向 2 的直接结果）：`--h-ctl-sm:24px / --h-ctl-md:28px / --h-ctl-lg:32px`。仅 window chrome 分叉。图标 16px / `stroke-width:1.5`，命中区 ≥28×28（便笺窗内 26×26 例外）。

**统一 focus ring**（所有组件同一条，不许各写各的）：

```css
:focus{outline:none}
:focus-visible{
  outline:2px solid var(--c-focus); outline-offset:2px; border-radius:inherit;
}
/* 便笺窗内 overflow:hidden 会裁掉 4px 光晕 → 聚焦元素必须预留 4px 内边距 */
.note :focus-visible{ outline-offset:1px; box-shadow:0 0 0 1px var(--note-paper); }
```
只用 `:focus-visible`，鼠标点击不出环。**所有 hover-only 的 UI 必须同时绑 `:focus-within`**，否则纯键盘用户永远看不到工具栏。

**底部中央不是两个自由浮层，是一个栈**（Toast 与批量操作条的位置协商交给布局引擎，不交给运行时 if）：

```css

  transform: translateX(-50%);
  display: flex; flex-direction: column-reverse;          /* 批量条永远贴底，Toast 向上生长 */
  align-items: center; gap: var(--sp-4);                  /* 8 */
  z-index: var(--z-toast);
  pointer-events: none;                                   /* 子元素各自开 auto */
}
.bottom-dock > *{ pointer-events: auto; }
/* dock 成员进出时，其余成员用 transform 平移，绝不过渡 bottom（红线 2：只动 transform/opacity） */
```

### 5.2 表面与边界（红线：便笺表面必须自足）

```css
.note-window{                       /* 只做窗口填充：一整面淡彩纸，不承载形状与阴影 */
  background: var(--note-paper);      /* 整面淡彩，100% 不透明 */
  color: var(--note-ink);
}
.note-shell{                        /* .note-window 内的第一层，承载形状 / 阴影 / 入场与关闭变换 */
  border-radius: var(--r-window);
  box-shadow: var(--sh-window);       /* 第 1 层 = 1px 同色相实色描边 --note-line */
  /* motion 全章的入场、关闭、折叠、"退半步"变换一律作用在这一层；
     浮层 portal 的锚点 #float-root 是它的兄弟节点（见 §2.4 降级路径 ②） */
}
.note[data-color="citron"]{
  --note-paper:var(--p-citron); --note-ink:var(--p-citron-ink);
  --note-ink2:var(--p-citron-ink2); --note-line:var(--p-citron-line);
  --note-dot:var(--p-citron-dot);
  --note-rule:color-mix(in oklab, var(--note-ink) 12%, transparent);
  --note-sel: color-mix(in oklab, var(--note-dot) 22%, transparent);
  --note-mark:color-mix(in oklab, var(--note-dot) 30%, transparent);

```
窗口边界由**表面自身颜色 + 1px 同色相实色描边**建立，不由阴影建立——阴影只做增强。这解掉方向 3 的 1.27:1 hairline 在浅色壁纸/白色 Word 上消失的问题。

### 5.3 「退半步」机制（同屏 15 张的层级）

```css
/* 禁止 filter：会给每个窗口建独立渲染面，并打断 position:fixed 的包含块 */
.note-window[data-focused="false"]{
  --note-paper:var(--note-paper-dim);   /* 生成器产出：L+0.006, C×0.80 */
  --note-ink:var(--note-ink-dim);
}                                        /* 例：柠檬 #EBE7A4 → #EBE8B3 */
.note-shell[data-focused="true"]{
  box-shadow: var(--sh-window),
    0 8px 28px -10px color-mix(in oklab, var(--note-dot) 30%, transparent);
}
```
一屏 15 张，恒定只有 1 张带自己颜色的柔光。变量切换只触发 paint，不创建合成层。**聚焦柔光的出现/消失走两层伪元素 crossfade，不过渡 `box-shadow` 本身**（红线 2）。

### 5.4 底部操作工具栏：双条件触发 + 双模式

```
显示 = 窗口已聚焦 AND (鼠标在窗内 OR 有文本选区 OR 光标在编辑器内且 3s 内有输入)
隐藏 = 失焦 var(--delay-toolbar-blur)(200ms) 后 · 或 鼠标离开且无选区 var(--delay-toolbar-leave)(800ms) 后
```
`聚焦 AND 悬停`两个条件都要——这一条直接解掉"鼠标横扫桌面触发 15 次淡入淡出"的波浪效应。800ms 延迟防边缘闪烁。工具栏 `position:absolute; bottom:0`，配 44px 渐隐遮罩；内容已滚到底时才给正文加 `padding-bottom:32px`。220px 宽只放 4 个 26×26：`◉换色 ⇧置顶 ✦AI ⋯更多`。

**双模式（底部只有一条物理工具栏）**：

```
.note-toolbar[data-mode="object"]   ◉换色  ⇧置顶  ✦AI  ⋯更多            42 字
.note-toolbar[data-mode="format"]   ⟨返回  B I U S  ☐  ≔  🔗            ✦
```

- **只有一条 DOM 元素、一个高度（`--note-toolbar-h`）、一个 `bottom:0`。** 两组图标预置在同一条上，`data-mode` 在 `object`（`◉ ⇧ ✦ ⋯`）与 `format`（`B I U S ☐ ≔ 🔗 ✦`）之间用 **`opacity` crossfade（`--dur-2`）** 切换，**条高不变、内容区 `padding-bottom` 不变 ⇒ 零 layout shift、零额外高度占用**。
- `Cmd/Ctrl+E` 的语义统一定义为「**切换底部条的模式**」，不是「唤起第三条栏」；再按一次或 `Esc`（Esc 链第 5 级之前）回到 `object` 模式。任何情况下都不会出现两条 32px 条同时贴底。
- **≥380px（底部条已常驻且已含 Markdown 组）**：`Cmd/Ctrl+E` 不切模式，改为把焦点送进常驻条的第一个格式按钮（roving tabindex）；再按或 `Esc` 把焦点还给编辑器并还原光标位置。**有选区时**：焦点直接送进已浮出的浮动格式条，同样不切模式。

**触屏（`pointer:coarse`）分支**：无 hover，标题栏常驻 `⋯`，长按 500ms 唤出全部操作的 sheet；resize 手柄常驻 `opacity:.5`。

### 5.6 断点行为（容器查询，不用媒体查询）

`.note{ container:note / size; }` —— 同一组件既是独立窗口，也是主列表的预览卡片。

**全部阈值单位为 `rem`，不是 `px`** —— `rem` 在容器查询条件里按**根元素**字号解析（我们控制的 `calc(16px * var(--ui-scale))`），这样断点与 `--ui-scale` 同步。否则 130% 下 234px 宽的最小窗口会被 px 断点判成「常规 sm」，compact 档永远进不去。**配套门禁**：`/dev/sizes` 面板 × 四档 scale × Playwright 断言每个断点的实际切换点；若某引擎解析行为不符，退路是 JS 在 `<html>` 写 `data-nw="xs|sm|md|lg|xl"`（ResizeObserver + scale 计算）、CSS 改用属性选择器——**不要**在 `@container` 条件里写 `var()`，那是非法的。

**标题栏高度不随「窗口尺寸」线性缩放**（只有 ≥20rem 高时一次性 28→32），窗口 chrome 是 OS 级一致性；但它**必须随 `--ui-scale` 缩放**（§2.2 的 `max(28px,1.75rem)`，见 §7）。最小窗口 **180×140 @100%**（130% 下 234×182）。

### 5.7 微交互（全 app 仅 3 处 spring）

- **新建**：`scale(.94) rotate(.8deg)` → `scale(1) rotate(0)`，**`--dur-5`(360ms) `var(--ease-spring)`**；`opacity` 只占前 `--dur-3`（透明度先到位，形变继续回弹）。
- **删除**：`translateY(-6px) rotate(-1.2deg) scale(.98)`，随后整体 `opacity:0`，**`--dur-2 var(--ease-in)`**（出场 = 进场降一级，motion §1.1 原则 3）。**不做撕纸锯齿动画**。
- **待办打勾**：`stroke-dasharray:16 → dashoffset:0`，180ms `--ease-out` delay 40ms + 方框 `scale(.9)→1` spring。

**三处涉及阴影变化的关键帧（新建的 `--sh-3`→`--sh-window`、删除的升至 `--sh-3`、§5.3 的聚焦柔光）一律改为两层伪元素 crossfade**，不得过渡 `box-shadow` 本身——红线 2 / motion §1.4。

## 6. 暗色模式与跟随系统

### 6.1 六条策略（不是反色）

1. **明度不对称**：亮色纸 `L=0.915` → 暗色纸 `L=0.290`（不是 `1−0.915`）。反色会得到近黑的纸，OLED 上涂抹且色相消失。
2. **色相角完全不变**，只动 L 与 C。柠檬永远 h105，危险永远 h28。用户在暗色下认得出的黄便笺，切回亮色还是同一张。
3. **色度反向**：纸面 C 上限 0.090 → 0.060（暗底下人眼对色度不敏感，但纸面不能太艳）；墨色 C 0.050 → 0.032（亮字高饱和会"振动"）；强调色 L 0.545→0.740、C 0.190→0.150。
4. **不用纯黑不用纯白**：canvas `#131312`、正文 `#EDEDEA`（15.85:1）。密排汉字在纯黑白极端对比下 halation 会填平笔画间的白隙。
5. **层级从阴影切到明度 + 内高光**：`#131312 → #1A1A18 → #201F1D → #272623`，ΔL≈0.023/0.021（暗端步进比亮端更密，人眼在低亮度对亮度差更敏感）。每个抬升面加 `inset 0 1px 0 rgba(255,255,255,.07)`——这 1px 是暗色 UI 里"有形体"和"是个洞"的分界。
6. **边框从压暗翻转为提亮且改半透明**：`--c-border` 亮色 `#D3D3CD`（固定 hex）→ 暗色 `rgba(255,255,255,.10)`，这样同一 token 在任意 surface 层级上自动保持相对关系。

### 6.2 跟随系统的实现

```css
:root{ color-scheme:light dark; }            /* 原生滚动条/select/选区跟随 */
```
用户三档：`跟随系统 / 浅色 / 深色` → `<html>` 上分别为无属性 / `data-theme="light"` / `data-theme="dark"`。CSS 三段式：裸 `:root`（亮）→ `@media (prefers-color-scheme:dark){ :root:not([data-theme="light"]) }` → `:root[data-theme="dark"]`。**§2.2 与 frontend_stack 的 formatter 逐字复现这三段，不使用任何第四种选择器写法。不把 `light-dark()` 作为唯一机制**（属"带降级"层，见 §2.4）。

**十几个窗口必须同帧切换**，否则一半亮一半暗极其刺眼：
1. Rust 侧监听系统主题（Win `WM_SETTINGCHANGE` / mac `AppleInterfaceThemeChangedNotification`），并调 `window.set_theme()` 同步原生右键菜单、IME 候选框、滚动条；
2. 主进程一次性广播 `theme-changed` 到全部窗口；
3. 各窗口在同一个 `requestAnimationFrame` 里改 `data-theme`，并挂 200ms 的 `[data-theme-switching] *{transition:none!important}`——避免 15 个窗口各跑 200ms 颜色补间造成掉帧。

### 6.3 Windows 的不透明约束（红线，必须现在写进设计）

Chromium 在带 alpha 的合成面上退回灰度抗锯齿，放弃 ClearType，13px 中文明显变虚；而正文是产品 80% 的像素。因此 **Windows 便笺窗口 `transparent:false`，禁止 Mica / Acrylic / 整窗 opacity**。而 `decorations:false` 的无边框窗口 DWM 不保证给圆角、且无 API 可查——**Windows 便笺窗口是直角（`--r-window:0`），这是既定结果，不得为了圆角开透明**。macOS 系统级早无亚像素 AA，透明零成本，`transparent:true` + CSS `border-radius:10px` + `overflow:hidden`。毛玻璃只允许出现在设置窗口与 AI 面板。

**窗口控件**：

| | macOS 便笺窗 | Windows 便笺窗 |
|---|---|---|
| caption | 自绘**单个 12px 关闭点**，**左**缘内缩 8px（macOS 约定） | 自绘**单枚 `✕`**，`--caption-btn-w` × 满栏高，**右**缘齐边、零内边距（Windows 约定） |
| 关闭态 | hover `--c-danger`，无红底 | hover 底 `#C42B1C` + 白字（5.66:1），active `#B22A1B`（6.48:1） |
| 颜色点位置 | **让位到右侧组首位**（`⊙` 左边） | 保持左缘 |
| 最小化 | 用系统 `⌘M`（进 Dock，可恢复） | **无按钮、无键位** |

其余按钮 hover `rgba(0,0,0,.05)`。**Windows 便笺窗取消最小化**的三条理由：① 品类领先者 Windows 便笺本身的便笺窗就只有 `⋯` 和 `✕`，没有最小化；② 便笺窗为 `skipTaskbar:true`（否则 15 张便笺淹没任务栏预览与 Alt+Tab），而 `skipTaskbar` 窗口最小化后**没有任何可恢复的入口**，是一个会丢窗口的功能；③「让开」这个需求已有两条更好的路径——**双击顶栏折叠为标题条** 与**托盘「隐藏全部便笺」**；切换需求由 `Ctrl+Tab` 缩略图 HUD 承接。

主窗口 `46×32` 三枚 + Snap Layouts（子 HWND 对 `WM_NCHITTEST` 返回 `HTMAXBUTTON`，不做会被当成 bug）——`46×32` 是 Win11 对**系统绘制**主窗标题栏的规范，只在主窗遵守。**便笺窗的 caption 是我们自绘的 HTML 元素，不是 OS 约定，因此必须随 `--ui-scale` 缩放**（§2.2 的 rem/clamp 版；否则 130% 下正文字号 ×1.3、唯独关闭按钮还是 40×28，成了全窗最小的点击目标）。macOS 主窗口用原生红绿灯（`titleBarStyle:"Overlay"` + `hiddenTitle` + `trafficLightPosition`），便笺小窗自绘单个 12px 关闭点（三键 + 安全区吃掉 220px 的 31%，且 Apple 自家 Stickies 就是单键）。

## 8. 三条工程红线（写进 CI，不是写进文档）

1. **Windows 上承载中文正文的窗口必须不透明**，禁止一切需要 `transparent:true` 的效果落在便笺窗口上；推论（直角）一并接受。
2. **每个便笺窗口静止态常驻 GPU 成本为零**：禁止常驻 `filter` / `backdrop-filter` / `mix-blend-mode` / `will-change`；**`will-change` 仅允许经 `useTransientHint()` 在运行时设置，并在 `transitionend` / `animationend` / `transitioncancel` / 硬超时四重收回**（静态检查只能证明"没人写"，运行时残留断言才能证明"没人留"）；hover/focus 过渡只允许动 `opacity` 与 `transform`（`box-shadow` 过渡改两层伪元素 crossfade）；失焦 3s 后停止所有 `animation` 与 `rAF`。**且不得以 `set_visible(false)` 代替 `close()` 来实现「收起」**——隐藏的 webview 仍占约 **79%** 的 RSS（渲染进程、V8 isolate、DOM 与 JS 堆均不释放），**两个平台都不会自动回收**；唯一确定性的回收方式是销毁它。
3. **平台分叉只允许发生在 chrome 层**，且不得改变内容的换行结果。所有 `[data-os]` 选择器集中在 `src/platform/` 并在清单登记；`grep -rn 'data-os' src/components/` 必须为空；stylelint 禁止 `scrollbar-width` / `scrollbar-color`；`grep -rn 'var(--p-' src/components/` 必须为空（便笺色与协作者色一律走 L3 的 `--note-dot` / `--note-dot-user`，由容器 JS 赋值）。

**Sources:** [WebKit Features in Safari 18.4](https://webkit.org/blog/16574/webkit-features-in-safari-18-4/) · [caniuse: text-autospace](https://caniuse.com/?search=text-autospace) · [WebKit Features in Safari 26.0](https://webkit.org/blog/17333/webkit-features-in-safari-26-0/) · [Release Notes for Safari Technology Preview 250](https://webkit.org/blog/18191/release-notes-for-safari-technology-preview-250/) · [BCD #29315 · scrollbar-color 在 macOS Safari 26.3 无效](https://github.com/mdn/browser-compat-data/issues/29315) · [MDN ::-webkit-scrollbar](https://developer.mozilla.org/en-US/docs/Web/CSS/::-webkit-scrollbar)
