# bianfa 最终视觉方向与设计系统规范

## 1. 最终方向：**淡彩纸 / Tinted Paper**

> **一句话定位**：界面骨架是一张暖中性的素纸，便笺身份是一整张淡彩纸——**桌面上是纸，列表里是墨线**；颜色只承载分类，一个比特都不承载可读性。

### 1.1 为什么这样融合

三位评审的共识是清晰的：**方向 2 三票垫底**（工程预算花在主场景 15% 的像素上、品牌为零、以 Windows 中文可读性换材质），**方向 1 三票稳居第二**（光学功力最强但 220px 上兑现不了、圆角是死结），方向 3 拿下 craft/feasible 两票第一，方向 4 拿下 fit 票第一。

**主干取方向 3（纸感极简）**：它的三条资产是正交于审美的纯收益——暖中性灰轴（`#FCFCFB` 而不是 `#FFFFFF`，成本 0）、overlay chrome 的密度手法（滚动条压 padding / 标题栏 absolute / 首行即标题，白拿 25–30 字）、BF Punct 标点子集（唯一让两个引擎走同一条中文排版路径的方案）。它的失败模式是"无聊"，不是"廉价"——对一个没有专职设计师的团队，这是决定性的。

**嫁接方向 4 的核心机制，并用它修掉方向 3 的致命伤**：fit 评审对方向 3 最狠的一刀是"3px 色带 = 便笺表面积的 1.4%，把便笺唯一的零成本信息架构压到失效阈值以下"。这一刀成立，但它的解不是"整个产品都染色"。**最终方案把染色语境化**：

| 语境 | 着色策略 | 理由 |
|---|---|---|
| 桌面独立便笺窗口 | **整面淡彩纸**（`--note-paper`） | 15 张浮在花壁纸上，需要前注意（pre-attentive）的大面积色块才能 0.5 秒定位 |
| 主列表 / 团队墙 / 回收站 | 中性卡片 + **3px 左色条 + 8px 色点** | 50 条同屏，整块着色会变拼布被 |
| AI 面板 / 设置 | 纯中性，零着色 | 流式长文在中性灰底上最好读 |

这条分界线来自方向 4 的原则五（大面积极低饱和 / 小面积高饱和，中间地带非法），它同时满足了 craft 的"不要拼布被"和 fit 的"必须能一眼找到"。

**嫁接方向 4 的明度锁定 + 生成器**：10 色便笺全部锁在同一 OKLCH 明度（亮 `L=0.915` / 暗 `L=0.290`），正文墨色锁在另一条（亮 `L=0.300` / 暗 `L=0.905`）。实测正文对比度极差只有 **0.35**（10.47–10.82:1）。token 由 `tokens.mjs` 从 5 个明度常数 + 10 行 `(name, hue, m)` 表生成，CI 跑全矩阵对比度门禁——**生成器 > lint**，这是三位评审里唯一被点名"可持续"的维护模型。

**嫁接方向 1 的光学三条**：① 墨色继承纸色相（环境色反射，真纸与塑料色块的分界线）；② 阴影必须有 blur ≤ 1px 的接触阴影层 + 全部大模糊层带负 spread + 阴影色不是纯黑；③ 工具栏双条件触发（`聚焦 AND 悬停`），一次性解掉方向 3 自述的"鼠标扫过 15 个窗口像波浪"。另加它的 Windows 推论链：**不透明 → ClearType → 接受直角**。

**放弃的**：
- **整个方向 2**。平台分叉预算、Mica/Vibrancy、系统强调色桥、双基准字号，全部不要。只保留三条**合规项**（不是方向）：Win11 caption 46×32 / 关闭红 `#C42B1C`、Snap Layouts 的 `HTMAXBUTTON`、macOS 小窗自绘单个关闭点。
- **方向 1 的纹理系统**：feTurbulence 噪声、vignette、翻角、手写体。220px 下不可辨，却要付栅格缓存 + DPR 切换重绘 + 双主题双 tile 的全额成本。有成本无收益比有争议更该砍。
- **方向 4 的 13 色与全局等色度**。C=0.044 被最窄色相靛蓝绑架，橙和红分不清是逻辑自伤。改为：**同明度 + 各色相取该明度下 sRGB 最大在色域色度的 75%**（再乘 Helmholtz–Kohlrausch 补偿系数 m）。实测色度落在 0.013–0.090，与方向 1 的手挑纸色同一量级。色数砍到 **10**（9 色相 + 石墨），最小 Δh = 30°，映射 `Ctrl+1~9` + `Ctrl+0`。
- **方向 3 的 Tint 三档设置项**。默认态解决不了的问题不许外包给设置。

## 2. Design Token 体系

### 2.1 三层命名规范

```
L1  --p-*     Primitive   原始灰阶 / 色相原料 / 数列。组件禁止直接引用。（CI: grep -rn 'var(--p-' src/components/ 必须为空）
L2  --c-* --fs-* --sp-* --r-* --sh-* --dur-* --z-*   Semantic   角色语义。组件唯一可用层。
L3  --note-* --btn-* --input-*  Component   组件/实例局部变量，只在组件内部定义，只引用 L2。
```

唯一例外：`--note-paper/-ink/-ink2/-line/-dot` 由 JS 按便笺颜色赋值，从 L1 色板直通 L3，不经过语义层——它是产品身份，不参与主题重映射。

**全部 L1/L2 由 `tokens.mjs` 生成**，输入 = 5 个明度常数 + 10 行 `(name, hue, m)` + 语义色表，输出 = `tokens.css` + 一份「每个前景 × 每个背景」的 WCAG 矩阵报告。CI 中任何一对跌破 4.5:1 即 fail build。

## 3. 中英文混排规范

### 3.1 字体栈与字重

Windows 主力实为 `Segoe UI`（`Segoe UI Variable Text` 在 webview 里按名字取不到，写在栈首是零成本白赚），中文走 `Microsoft YaHei UI`；macOS 走 `-apple-system` + `PingFang SC`。**西文必须排在中文之前**——否则英文和数字会用苹方/雅黑自带的西文字形渲染，字宽明显更松。

**字重现实**：`Microsoft YaHei` 只有 400 / 700（Win11 另有 Light 300），**没有 500/600**。写 `font-weight:600` 会触发合成假粗，13px 中文笔画糊成一团——这是中文界面显廉价的头号来源。因此：全局 `font-synthesis-weight:none`；`[data-os="windows"]` 下 `--fw-medium:400`（用颜色提一级补偿）、`--fw-strong:700`；`:lang(zh)` 补 `letter-spacing:.008em`。**推论必须一起接受：层级靠「字号 + 颜色 + 字距」建立，不靠字重。**

内嵌字体只有两个，合计 ≤ 55 KB：`BF Punct`（标点子集，见 3.3）与 `Inter` 拉丁子集（可选，统一两平台数字字面）。**一个中文正文字节都不嵌**——Noto Sans SC 单字重 woff2 ≈ 1.5 MB，会让 Tauri 安装包翻倍。

### 3.2 字号与行高（中文行高必须大于西文）

| token | px @scale=1 | line-height | 用途 |
|---|---|---|---|
| `--fs-2xs` 11 | 11 | 1.45 / 16px | 时间戳、快捷键、计数 |
| `--fs-xs` 12 | 12 | 1.5 / 18px | 工具栏标签、徽标 |
| `--fs-sm` 13 | 13 | **1.62 / 21px** | UI 正文、列表摘要 |
| `--fs-md` 14 | 14 | **1.70 / 23.8px** | **便笺正文（地板，不得更小）** |
| `--fs-lg` 15 | 15 | 1.62 / 24px | 便笺标题（首行） |
| `--fs-xl` 17 | 17 | 1.5 / 25px | 面板/对话框标题 |
| `--fs-2xl` 20 / `--fs-3xl` 24 / `--fs-4xl` 32 | | 1.4 / 1.35 / 1.25 | 分区、空态、品牌 |

西文可以 1.4–1.5，中文方块字没有 x-height 提供的呼吸，**正文最低 1.62**。所有时间戳、计数、字数一律 `font-variant-numeric: tabular-nums`——列表里数字跳动会直接破坏静态感。中文正文 `letter-spacing:.01em`，`:lang(en)` 段落归零。

### 3.3 标点与自动间距：当前 CSS 支持（2026-09 核实）与本方案的决策

| 特性 | Chromium / WebView2（Windows） | WebKit / WKWebView（macOS） |
|---|---|---|
| `text-autospace`（中西自动间隙） | 仅实验/子集实现，`ideograph-alpha` 不认 | Safari 18.4+ 已 ship，**初值被设为 `no-autospace`**，需显式声明才生效 |
| `text-spacing-trim`（全角标点挤压） | Chrome 123+ 支持，默认 `normal` 即已挤压 | **至今未 ship**（Safari 26.x 正式版无；STP 250 里的是另一个属性 `white-space-trim`） |
| `text-box-trim`（光学基线裁切） | Chrome/Edge 133+ | Safari 18.2+ |
| `hanging-punctuation` | 从未实现 | Safari 16+ |
| `scrollbar-color` | 支持 | 名义 26.2+，**BCD #29315 实测 26.3 macOS 无效** |

**决策（这是本规范里最硬的一条）**：任何会改变行盒宽度、进而改变换行位置的特性，**要么两平台都开、要么两平台都关**，绝不做"哪边支持哪边开"的渐进增强。同一张便笺在两台电脑上换行位置不同，对同步型产品是正确性缺陷，不是审美差异。

```css
.prose,.note-body,.list-item{
  text-autospace:no-autospace;   /* 显式钉死，防 Safari/Chrome 未来默认值漂移 */
  text-spacing-trim:space-all;   /* 关掉 Chromium 的引擎级挤压，交给字体层 */
  letter-spacing:.01em;          /* 中西之间的呼吸由字距提供，两平台完全一致 */
  line-break:strict;             /* 中文禁则：。，、」不落行首 */
  word-break:normal; overflow-wrap:anywhere;   /* 220px 下长 URL 必须能断 */
}
code,pre,kbd,.tabular{ font-family:var(--f-mono); letter-spacing:0; }
.btn,.tab,.badge{ text-box:trim-both cap alphabetic; }  /* 仅西文为主的 UI 元素，中文正文禁用 */
```

**`font-feature-settings:"palt"/"halt"` 一律不用**：苹方有、雅黑没有，开了必然两平台错位。

**标点挤压由字体层统一**：`BF Punct` = 取 Noto Sans SC（OFL）→ `pyftsubset` 裁到约 50 个中文标点字形 → **把闭合类标点（`。，、；：！？」』）》】`）的 advance 静态设为 0.5em 并调 LSB**，开合类保持全宽。产物 woff2 ≈ 5–8 KB，`font-display:block`（标点必须避免 FOUT 抖行），排在字体栈首。因为是静态字宽而非 OpenType feature，**不依赖 `text-spacing-trim` 或 `chws` 激活，两个引擎逐像素一致**。

> **第 1 周必做 spike**：WebView2 与 WKWebView 各渲染 `他说：「明天（周三）14:00 开会。」`，像素比对 + 换行位置比对。不成立就退回"两平台都不挤压"，绝不单边开。残余风险：标点字形来自 Noto、正文来自雅黑/苹方，笔画粗细在 ≥24px 时会露馅——`.display` 类关闭 BF Punct。

### 5.2 表面与边界（红线：便笺表面必须自足）

```css
.note-window{
  background: var(--note-paper);      /* 整面淡彩，100% 不透明 */
  color: var(--note-ink);
  border-radius: var(--r-window);
  box-shadow: var(--sh-window);       /* 第 1 层 = 1px 同色相实色描边 --note-line */
}
.note[data-color="citron"]{
  --note-paper:var(--p-citron); --note-ink:var(--p-citron-ink);
  --note-ink2:var(--p-citron-ink2); --note-line:var(--p-citron-line);
  --note-dot:var(--p-citron-dot);
  --note-rule:color-mix(in oklab, var(--note-ink) 12%, transparent);
  --note-sel: color-mix(in oklab, var(--note-dot) 22%, transparent);
  --note-mark:color-mix(in oklab, var(--note-dot) 30%, transparent);
}
```
窗口边界由**表面自身颜色 + 1px 同色相实色描边**建立，不由阴影建立——阴影只做增强。这解掉方向 3 的 1.27:1 hairline 在浅色壁纸/白色 Word 上消失的问题。

### 5.3 「退半步」机制（同屏 15 张的层级）

```css
/* 禁止 filter：会给每个窗口建独立渲染面，并打断 position:fixed 的包含块 */
.note-window[data-focused="false"]{
  --note-paper:var(--note-paper-dim);   /* 生成器产出：L+0.006, C×0.80 */
  --note-ink:var(--note-ink-dim);
}                                        /* 例：柠檬 #EBE7A4 → #EBE8B3 */
.note-window[data-focused="true"]{
  box-shadow: var(--sh-window),
    0 8px 28px -10px color-mix(in oklab, var(--note-dot) 30%, transparent);
}
```
一屏 15 张，恒定只有 1 张带自己颜色的柔光。变量切换只触发 paint，不创建合成层。

### 5.4 工具栏：双条件触发

```
显示 = 窗口已聚焦 AND (鼠标在窗内 OR 有文本选区 OR 光标在编辑器内且 3s 内有输入)
隐藏 = 失焦 200ms 后 · 或 鼠标离开且无选区 800ms 后
```
`聚焦 AND 悬停`两个条件都要——这一条直接解掉"鼠标横扫桌面触发 15 次淡入淡出"的波浪效应。800ms 延迟防边缘闪烁。工具栏 `position:absolute; bottom:0`，配 44px 渐隐遮罩；内容已滚到底时才给正文加 `padding-bottom:32px`。220px 宽只放 4 个 26×26：`◉换色 ⇧置顶 ✦AI ⋯更多`。

**触屏（`pointer:coarse`）分支**：无 hover，标题栏常驻 `⋯`，长按 500ms 唤出全部操作的 sheet；resize 手柄常驻 `opacity:.5`。

### 5.5 滚动条（只有一条路径）

```css
.note-body{ padding:30px 8px 12px 14px; }   /* 右侧 8px 即滚动条槽，内容宽恒定 198px */
.note-body::-webkit-scrollbar{width:8px}
.note-body::-webkit-scrollbar-track{background:transparent}
.note-body::-webkit-scrollbar-thumb{
  background:transparent; border:2px solid transparent; background-clip:content-box;
  border-radius:4px; transition:background var(--dur-1) linear;
}
.note-window:hover .note-body::-webkit-scrollbar-thumb{
  background-color:color-mix(in oklab,var(--note-ink) 22%,transparent); background-clip:content-box;
}
```
**stylelint 全局禁止 `scrollbar-width` 与 `scrollbar-color`**：一旦代码库任何一处出现，Chromium 会整体忽略所有 `::-webkit-scrollbar` 规则，两平台滚动条当场分叉；且 `scrollbar-color` 在 macOS Safari 26.3 实测无效。

### 5.6 断点行为（容器查询，不用媒体查询）

`.note{ container:note / size; }` —— 同一组件既是独立窗口，也是主列表的预览卡片。

| 条件 | 变化 |
|---|---|
| `< 200px` 或 `< 160px` 高 | compact：正文 13px/1.62，padding 10px，工具栏只留 `◉ ⋯` |
| `≥ 300px` | padding → 16px 18px；标题 15→17px |

| `≥ 380px` | **工具栏常驻**（`opacity:1`，`position:static`，高 40px，`border-top:1px var(--note-rule)`），撤掉渐隐遮罩；出现 Markdown 组 `B • ☐ </> 🔗` |

## 6. 暗色模式与跟随系统

### 6.1 六条策略（不是反色）

1. **明度不对称**：亮色纸 `L=0.915` → 暗色纸 `L=0.290`（不是 `1−0.915`）。反色会得到近黑的纸，OLED 上涂抹且色相消失。
2. **色相角完全不变**，只动 L 与 C。柠檬永远 h105，危险永远 h28。用户在暗色下认得出的黄便笺，切回亮色还是同一张。
3. **色度反向**：纸面 C 上限 0.090 → 0.060（暗底下人眼对色度不敏感，但纸面不能太艳）；墨色 C 0.050 → 0.032（亮字高饱和会"振动"）；强调色 L 0.545→0.740、C 0.190→0.150。
4. **不用纯黑不用纯白**：canvas `#131312`、正文 `#EDEDEA`（15.85:1）。密排汉字在纯黑白极端对比下 halation 会填平笔画间的白隙。
5. **层级从阴影切到明度 + 内高光**：`#131312 → #1A1A18 → #201F1D → #272623`，ΔL≈0.023/0.021（暗端步进比亮端更密，人眼在低亮度对亮度差更敏感）。每个抬升面加 `inset 0 1px 0 rgba(255,255,255,.07)`——这 1px 是暗色 UI 里"有形体"和"是个洞"的分界。
6. **边框从压暗翻转为提亮且改半透明**：`--c-border` 亮色 `#D3D3CD`（固定 hex）→ 暗色 `rgba(255,255,255,.10)`，这样同一 token 在任意 surface 层级上自动保持相对关系。

### 6.2 跟随系统的实现

```css
:root{ color-scheme:light dark; }            /* 原生滚动条/select/选区跟随 */
```
用户三档：`跟随系统 / 浅色 / 深色` → `<html>` 上分别为无属性 / `data-theme="light"` / `data-theme="dark"`。CSS 三段式：裸 `:root`（亮）→ `@media (prefers-color-scheme:dark){ :root:not([data-theme="light"]) }` → `:root[data-theme="dark"]`。**不把 `light-dark()` 作为唯一机制**（macOS 14.5 以下 WKWebView 不支持）。

**十几个窗口必须同帧切换**，否则一半亮一半暗极其刺眼：
1. Rust 侧监听系统主题（Win `WM_SETTINGCHANGE` / mac `AppleInterfaceThemeChangedNotification`），并调 `window.set_theme()` 同步原生右键菜单、IME 候选框、滚动条；
2. 主进程一次性广播 `theme-changed` 到全部窗口；
3. 各窗口在同一个 `requestAnimationFrame` 里改 `data-theme`，并挂 200ms 的 `[data-theme-switching] *{transition:none!important}`——避免 15 个窗口各跑 200ms 颜色补间造成掉帧。

### 6.3 Windows 的不透明约束（红线，必须现在写进设计）

Chromium 在带 alpha 的合成面上退回灰度抗锯齿，放弃 ClearType，13px 中文明显变虚；而正文是产品 80% 的像素。因此 **Windows 便笺窗口 `transparent:false`，禁止 Mica / Acrylic / 整窗 opacity**。而 `decorations:false` 的无边框窗口 DWM 不保证给圆角、且无 API 可查——**Windows 便笺窗口是直角（`--r-window:0`），这是既定结果，不得为了圆角开透明**。macOS 系统级早无亚像素 AA，透明零成本，`transparent:true` + CSS `border-radius:10px` + `overflow:hidden`。毛玻璃只允许出现在设置窗口与 AI 面板。

窗口控件：Windows 便笺 `40×28` 两枚（`─ ✕`，无最大化），hover `rgba(0,0,0,.05)`，关闭 hover `#C42B1C` + 白字（5.66:1）、active `#B22A1B`；主窗口 `46×32` 三枚 + Snap Layouts（子 HWND 对 `WM_NCHITTEST` 返回 `HTMAXBUTTON`，不做会被当成 bug）。macOS 主窗口用原生红绿灯（`titleBarStyle:"Overlay"` + `hiddenTitle` + `trafficLightPosition`），便笺小窗自绘单个 12px 关闭点（三键 + 安全区吃掉 220px 的 31%，且 Apple 自家 Stickies 就是单键）。

## 7. 无障碍

| 项 | 目标 / 实现 |
|---|---|
| **对比度** | 正文（含 10 色纸上的墨色）≥ **10:1**（远超 AA，便笺是余光扫读场景）；次级文字 ≥ 4.5:1（实测 4.63–4.79）；三级文字 `--c-text-3` ≥ 4.5:1（5.02 on canvas，4.55 on surface-3——**禁止用于 surface-3 以下的更暗底**）；图标/边界/色点 ≥ 3:1（实测 3.50–3.94）。CI 跑 `10 色 × 5 层文字 × 2 模式` 全矩阵，任何一对跌破即 fail。 |
| **颜色非唯一线索** | 便笺颜色必带名称文字；可绑 emoji；「用图案区分颜色」开关叠加 10 种 4×4px 微纹理；列表排序/筛选不得仅依赖颜色（WCAG 1.4.1）。 |
| **focus 可见性** | 全局 `:focus-visible` 一条规则：`outline:2px solid var(--c-focus); outline-offset:2px`。对 10 张纸实测 4.08–4.28:1（亮）/ 5.37–5.66:1（暗），一个环走遍全色板。便笺窗 `overflow:hidden` 会裁光晕 → 聚焦元素预留 4px 内边距，并叠一圈 1px `--note-paper` 内环保证在深色纸上也分离。**所有 hover-only UI 必须同时绑 `:focus-within`**。 |
| **键盘导航** | `Tab` 顺序 = 视觉顺序；`Esc` 逐级收起（浮层 → 工具栏 → 失焦，**不关闭便笺**，避免丢内容）；`Ctrl/Cmd+W` 关闭、`Ctrl/Cmd+Shift+N` 新建、`Ctrl/Cmd+K` 命令面板、`Ctrl/Cmd+1~9`+`0` 换色、`Ctrl/Cmd+P` 置顶。菜单/列表支持 `↑↓ Home End` + 首字母跳转。对话框焦点陷阱 + 关闭后焦点还原。文本编辑快捷键完全跟随系统（mac 的 `Ctrl+A` 是行首不是全选，不处理会被当 bug）。 |
| **reduced-motion** | `@media (prefers-reduced-motion:reduce)`：所有 `--dur-*` → 1ms，`--ease-spring` → `--ease-out`，旋转/位移归零，`animation-iteration-count:1`；**保留工具栏的 100ms opacity 过渡**（硬闪现更刺眼）；Skeleton 改静态。 |
| **字号缩放** | 全部字号用 `rem`，`:root{font-size:calc(16px * var(--ui-scale))}`，设置提供 **90% / 100% / 115% / 130%** 四档。缩放同时驱动 Tauri 窗口最小尺寸（`180×140 × scale`）与默认新建尺寸（`220×220 × scale`），避免 130% 下正文只剩 4 行。**便笺正文字号地板 14px @100%，不许用降字号换密度。** |
| **减少透明度** | WebKit 未实现 `prefers-reduced-transparency` → Rust 侧读系统设置下发 `data-reduce-transparency="1"`；本方案便笺本就不透明，只影响设置窗口/AI 面板的 backdrop-filter。 |
| **语义** | 便笺窗 `role="application"` 内正文用 `contenteditable` + `aria-label`；Toast `aria-live`；Skeleton `aria-busy`；置顶状态用 `aria-pressed` 而非仅图标。 |

## 8. 三条工程红线（写进 CI，不是写进文档）

1. **Windows 上承载中文正文的窗口必须不透明**，禁止一切需要 `transparent:true` 的效果落在便笺窗口上；推论（直角）一并接受。
2. **每个便笺窗口静止态常驻 GPU 成本为零**：禁止常驻 `filter` / `backdrop-filter` / `mix-blend-mode` / `will-change`；hover/focus 过渡只允许动 `opacity` 与 `transform`（`box-shadow` 过渡改两层伪元素 crossfade）；失焦 3s 后停止所有 `animation` 与 `rAF`。
3. **平台分叉只允许发生在 chrome 层**，且不得改变内容的换行结果。所有 `[data-os]` 选择器集中在 `src/platform/` 并在清单登记；`grep -rn 'data-os' src/components/` 必须为空；stylelint 禁止 `scrollbar-width` / `scrollbar-color`；`grep -rn 'var(--p-' src/components/` 必须为空。
