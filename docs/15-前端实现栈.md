# 前端实现栈与设计落地方案

> 本章所有版本号、包体积、字体切片大小均为 **2026-09-04 实测**（npm registry / crates.io 查询 + esbuild 生产构建 + gzip -9 实际压缩）。凡标注"实测"的数字，可在本机复现。
>
> **本章与设计系统章的关系**：设计系统章（「淡彩纸 Tinted Paper」）是 token 的**规范源**，本章是它的**落地管线**。本章不定义任何新的 L1/L2 token 值，只定义「这些值如何从一份源生成、如何被 CSS / TS / Rust 三端消费、如何在 CI 里防止漂移」。凡出现色值/字号/间距的地方，一律引用基准 §2.2 的 `--p-* / --c-* / --fs-* / --lh-* / --sp-* / --r-* / --sh-* / --dur-* / --ease-* / --z-*`。

## 0. 实测基线数据

所有框架/库的体积争论，先用真实构建数据钉死。以下为最小可运行 app 的 esbuild `--bundle --minify --format=esm` 产物：

| 构建对象 | 版本 | min (raw) | **gzip** |
|---|---|---|---|
| React + react-dom/client 计数器 | 19.2.8 | 189.6 KB | **58.9 KB** |
| Vue runtime-only（三个 flag 全关） | 3.5.42 | 52.7 KB | **20.9 KB** |
| Svelte（`mount` + 1 个 rune 组件） | 5.57.0 | 43.5 KB | **16.4 KB** |
| SolidJS（`render` + signal） | 1.9.15 | 12.1 KB | **4.9 KB** |
| lucide-react，30 个图标（不含 react） | 1.40.0 | 9.5 KB | **3.5 KB** |
| @tiptap/react + StarterKit（不含 react） | 3.31.2 | 390 KB | **123 KB** |
| Tiptap 最小扩展集（无 React 绑定） | 3.31.2 | 323 KB | **99.4 KB** |
| CodeMirror 6 + lang-markdown | — | 595 KB | **202 KB** |
| Noto Sans SC 单字重 woff2 全量（101 片） | v40 | — | **2.30 MB** |
| **BF Punct**（Noto Sans SC → 52 个中文标点子集，改 advance） | 本地构建 | 6.4 KB | **6.4 KB**（woff2 已压） |
| Inter 拉丁子集（400，U+0000–00FF + 常用符号） | 4.1 | 46.2 KB | **46.2 KB** |

三个立刻改变架构的结论：

1. **ProseMirror 的地板是 ~99 KB gzip**，砍扩展只省 24 KB。编辑器不可能"瘦身进便笺窗口"，只能改变**何时加载**（§7 两级编辑器）。
2. React 比 Svelte 贵 42.5 KB gzip / 146 KB 解析量，**每个窗口都要重付一遍**（webview 之间不共享 JS 堆）。15 个便笺窗口 = 多 2.2 MB 解析工作 + 约 30–45 MB 常驻堆。
3. **全量中文字体是数量级问题，不是优化问题**：2.30 MB 对 6.4 KB。基准 §3.1 的"一个中文正文字节都不嵌"不是审美取舍，是把安装包从 5–15 MB 拉到 20 MB+ 与否的区别。本章 §5 把它做成 CI 门禁，而不是口头约定。

## 1. 框架选型

Tauri v2（`tauri` crate **2.11.5**，`@tauri-apps/api` **2.11.1**，`wry` **0.56.1**）的多窗口模型是：每个 `WebviewWindow` 一个独立 webview，**独立 JS 堆、独立解析、独立 GC**。HTTP 层面共享缓存（同一 asset URL 只读一次磁盘），但 JS 必须逐窗口解析执行。

| 维度 | React 19.2.8 | Svelte 5.57.0 | SolidJS 1.9.15 | Vue 3.5.42 |
|---|---|---|---|---|
| 每窗口 gzip（实测） | 58.9 KB | 16.4 KB | 4.9 KB | 20.9 KB |
| 每窗口解析量 | 190 KB | 43 KB | 12 KB | 53 KB |
| 15 窗口增量堆（估） | ~40 MB | ~12 MB | ~6 MB | ~15 MB |
| 富文本生态 | `@tiptap/react` **官方**，与核心同版本发布（2026-09-03） | 仅社区 `svelte-tiptap@3.0.1`，**上次发布 2025-10-28，落后 11 个月** | 无官方绑定 | `@tiptap/vue-3` 官方 |
| 无头组件 | Base UI `@base-ui/react@1.7.0`、Radix `radix-ui@1.6.7`、Ark UI 5.39.1 | bits-ui 2.19.0 / Ark UI Svelte 5.24.1 | Ark UI（较薄） | Ark UI Vue |
| AI 流式渲染 | `startTransition` + `useDeferredValue` 可把 token 流降级为低优先级更新；React Compiler 免手写 memo | 细粒度更新天然不掉帧，但无优先级调度 | 最快，但无调度 | 中 |
| 团队熟悉度 | 最高 | 中 | 低 | 中 |

**结论：React 19.2.8 + React Compiler**，但**便笺窗口走独立入口 + 极简依赖**。

理由排序：

1. **富文本是这个产品的心脏，而 Tiptap 的 Svelte 绑定实际上处于半废弃状态**（11 个月未跟版）。用一个便笺应用去赌社区维护者，风险与收益不成比例。这一条压倒了体积。
2. 40 MB 是可以工程化解决的（见 §7 两级编辑器 + §8 分入口），11 个月的生态债不是。
3. React Compiler 消除了 React 在流式场景最大的痛点（手写 `memo`/`useMemo` 的心智负担），AI 面板每秒 30–60 次 token 更新在 `useDeferredValue` 下不会阻塞光标。

**与基准红线二的对齐**：基准 §8 要求"便笺窗口静止态常驻 GPU 成本为零 / 失焦 3s 后停止所有 `animation` 与 `rAF`"。这在 React 侧的具体落地是：便笺入口禁止任何常驻 `requestAnimationFrame` 循环（包括 Framer Motion 之类的动画运行时——**不引入动画库**，全部过渡走 CSS `transition`），`tauri://blur` 后 3s 调 `editor.destroy()` 与 `qc.getQueryCache().clear()` 之外还要 `cancelAnimationFrame` 所有登记句柄，由 `useRafRegistry` 统一持有并在 `/dev/perf` 面板可见。

**改选 Svelte 5 的触发条件**（写进 ADR，季度复查）：`svelte-tiptap` 恢复跟版且连续 2 个季度 ≤2 周延迟；或我们决定自研编辑器（放弃 ProseMirror）。届时每窗口省 42.5 KB gzip 值得一次迁移。

**SolidJS 不选**：4.9 KB 很美，但无 Tiptap 官方绑定 + 无头组件库薄 + 团队零经验，三项叠加。

## 2. 样式方案与 token 管线

**结论：Tailwind CSS v4.3.3 作为 utility 层 + 纯 CSS 文件承载 `.bf-prose` 与窗口级 chrome。不引入 vanilla-extract / Panda CSS。**
**关键约束：Tailwind 的 `@theme` 里不允许出现任何字面色值/尺寸，它只能是基准 token 的别名层（`@theme inline`）。**

* vanilla-extract 1.21.2 / Panda 1.12.0 的零运行时 CSS-in-TS 在**多入口场景下反而制造问题**：4 个 HTML 入口各自生成 CSS，跨入口去重靠 bundler，Rolldown 下的 CSS 代码分割行为还在演进。
* Tailwind v4 的 `@theme` 编译产物就是原生 CSS 变量，天然跨 webview、可被 Rust 端读取同一份 hex 值。
* CSS Modules 只在 `.bf-prose` 这种"要写 30 条选择器覆盖 ProseMirror DOM"的地方用。

### 2.1 Token 单一来源管线（本章最重要的产出）

**用 Style Dictionary 5.5.2，而不是手写。判据不是"多平台"，而是我们有第三个消费端：Rust。**

Tauri 创建窗口时必须在 Rust 侧设置 `background_color`。这不是锦上添花：`WebviewWindowBuilder` 先创建原生窗口、再挂 webview、webview 再解析 HTML/CSS 并首次绘制，这中间有 1 帧（16.7 ms，冷启时更长）窗口是**平台默认白**。在「淡彩纸」方向下这一帧尤其致命——用户新建的是一张柠檬色 `#EBE7A4` 的纸，看到的却是一帧纯白，暗色模式下是一帧刺眼白闪。所以 Rust 必须先知道 `--p-citron` 的值：

```rust
// src-tauri/src/window/note.rs
let (r, g, b) = tokens::note_paper(color, theme.is_dark());
WebviewWindowBuilder::new(app, label, WebviewUrl::App("note.html".into()))
    .background_color(Color(r, g, b, 255))   // alpha 恒为 255，见基准 §8 红线一
    .transparent(cfg!(target_os = "macos"))  // Windows 必须 false
    .decorations(false)
    .build()?;
```

同一份色值还要给：托盘菜单图标着色、macOS `NSVisualEffectView` 的 vibrancy 底色（仅设置窗/AI 面板）、以及主题切换时的 `window.set_background_color()`（十几个窗口同帧切换，见基准 §6.2）。**手写 CSS 变量 + TS 常量的方案会在这里出现第三份漂移**，而且漂移的表现是"新建便笺闪一下别的颜色"，最难被测试发现、最容易被当成"webview 就是这样"。

**与基准 §2.1 生成器的分工**（这是两章唯一的接缝，必须写清）：

```
palette.config.mjs      20 行色名表 (name, hue, tier) + OKLCH 目标表 + 语义色表   ← 人手维护的唯一输入
        ↓  palette.mjs（OKLCH → sRGB：浅色档按「给定相对亮度取最大彩度」反解，浓色档走另一条带，基准 §2.3）
src/gen/*.json          DTCG 格式（$value/$type），进 git，PR 里可 diff 色值
        ↓  Style Dictionary 5.5.2（build.mjs）
dist/tokens.css         基准 §2.2 逐字节等价的产物
dist/tokens.ts          TS 常量（/dev 面板、Playwright 断言）
dist/tokens.rs          Rust 常量（背景色、托盘、vibrancy）
dist/contrast-matrix.md 每个前景 × 每个背景的 WCAG 对比度矩阵（基准 §2.1 要求）
dist/contrast-matrix.json  给 /dev/tokens 面板渲染
```

基准 §2.1 说"全部 L1/L2 由 `tokens.mjs` 生成"——`palette.mjs` 就是那个 `tokens.mjs`，只是它的输出不再直接是 CSS，而是 DTCG JSON，再由 Style Dictionary 扇出到三个消费端。**生成器负责"值从哪来"，Style Dictionary 负责"值到哪去"**，两者不重叠，也不产生第二份真相。

### 2.3 生成器：OKLCH 色板（基准 §1 的"同明度 + 75% 在色域最大色度 × m"）

```js
// packages/tokens/src/palette.config.mjs
// 5 个明度常数 × 2 主题。这些数字由 fixtures/design-system-2.3.json 反解并锁定：
// 生成器必须逐位复现基准 §2.3 表里的 30 个色值，否则 build 失败。
export const L = {
  light: { paper: 0.915, ink: 0.300, ink2: 0.500, line: 0.845, dot: 0.545 },
  dark:  { paper: 0.290, ink: 0.905, ink2: 0.660, line: 0.360, dot: 0.720 },
}
// 色度上限（基准 §6.1 的色度反向）
export const C_CAP = {
  light: { paper: 0.090, ink: 0.050, ink2: 0.028, line: 0.070, dot: 0.150 },
  dark:  { paper: 0.060, ink: 0.032, ink2: 0.020, line: 0.048, dot: 0.130 },
}
// name, hue, m = Helmholtz–Kohlrausch 补偿系数（黄绿区人眼觉得更亮 → 压色度）
export const HUES = [
  ['graphite',  96, 0.10], ['rose',    358, 1.00], ['coral',    28, 1.00],
  ['amber',     68, 0.95], ['citron', 105, 0.88], ['fern',    145, 0.92],
  ['teal',     188, 0.95], ['azure',  232, 1.00], ['violet',  288, 1.00],
  ['fuchsia',  328, 1.00],
]
// 快捷键映射：Ctrl+1..9 → HUES[1..9]，Ctrl+0 → graphite（基准 §7 键盘导航）
```

```js
// packages/tokens/src/palette.mjs
import { converter, formatHex } from 'culori'          // devDependency，零运行时
import { L, C_CAP, HUES } from './palette.config.mjs'
const toRgb = converter('rgb')

const inGamut = (l, c, h) => {
  const { r, g, b } = toRgb({ mode: 'oklch', l, c, h })
  const eps = 1e-6
  return r >= -eps && r <= 1 + eps && g >= -eps && g <= 1 + eps && b >= -eps && b <= 1 + eps
}
/** 该明度/色相下 sRGB 内的最大色度（二分，24 次 ≈ 1e-8 精度） */
const maxChroma = (l, h) => {
  let lo = 0, hi = 0.4
  for (let i = 0; i < 24; i++) { const mid = (lo + hi) / 2; inGamut(l, mid, h) ? (lo = mid) : (hi = mid) }
  return lo
}
const solve = (l, h, m, cap) => formatHex({
  mode: 'oklch', l, h,
  c: Math.min(cap, 0.75 * maxChroma(l, h) * m),        // 基准 §1：不做全局等色度
})

export function buildNotePalette(theme) {
  const out = {}
  for (const [name, hue, m] of HUES) {
    out[name] = {
      paper: { $type: 'color', $value: solve(L[theme].paper, hue, m, C_CAP[theme].paper) },
      ink:   { $type: 'color', $value: solve(L[theme].ink,   hue, m, C_CAP[theme].ink)   },
      ink2:  { $type: 'color', $value: solve(L[theme].ink2,  hue, m, C_CAP[theme].ink2)  },
      line:  { $type: 'color', $value: solve(L[theme].line,  hue, m, C_CAP[theme].line)  },
      dot:   { $type: 'color', $value: solve(L[theme].dot,   hue, m, C_CAP[theme].dot)   },
      // 基准 §5.3「退半步」：L+0.006, C×0.80，只在亮色需要（暗色靠 line 分层）
      'paper-dim': { $type: 'color', $value: solve(L[theme].paper + 0.006, hue, m * 0.80, C_CAP[theme].paper) },
    }
  }
  return { note: out }
}
```

`pnpm -F tokens test` 跑一条断言：`buildNotePalette('light')` 与 `buildNotePalette('dark')` 的 60 个色值必须与 `fixtures/design-system-2.3.json` **全等**。任何人动了明度常数或 `m`，基准 §2.3 的表就必须同步改——这条 fixture 就是"设计文档"和"代码"之间的物理锁。

### 2.4 Style Dictionary：命名转换 + 三个 formatter

Style Dictionary 默认的 `name/kebab` 会产出 `color-semantic-text-1` 这种名字，与基准的 `--c-text-1` 不符。**不允许改基准的 token 名去迁就工具**，所以写一个命名转换：

```js
// packages/tokens/build.mjs  — style-dictionary@5.5.2
import StyleDictionary from 'style-dictionary'
import { promises as fs } from 'node:fs'
import { writePalette } from './src/palette.mjs'
import { contrastFormat, gateFailures } from './contrast.mjs'

await writePalette()   // 先跑生成器，产出 src/gen/*.json

/** DTCG path → 基准 §2.2 的 CSS 变量名。dark 前缀在这里被剥掉，由 formatter 分组。 */
function bfName(path) {
  const p = path[0] === 'dark' ? path.slice(1) : path
  const [group, ...rest] = p
  switch (group) {
    case 'gray':     return `p-w-${rest[0]}`                                   // p-w-500
    case 'note':     return rest[1] === 'paper' ? `p-${rest[0]}`               // p-citron
                          : `p-${rest[0]}-${rest[1]}`                          // p-citron-ink2
    case 'semantic': return `c-${rest.join('-')}`                              // c-text-1 / c-border-strong
    case 'font':     return rest[0] === 'size'   ? `fs-${rest[1]}`
                          : rest[0] === 'weight' ? `fw-${rest[1]}`
                          :                        `f-${rest[1]}`              // f-sans / f-mono
    case 'line':     return `lh-${rest[0]}`
    case 'letter':   return `ls-${rest[0]}`
    case 'space':    return `sp-${rest[0]}`
    case 'radius':   return `r-${rest[0]}`                                     // r-md / r-window
    case 'border':   return `bw-${rest[0]}`
    case 'shadow':   return `sh-${rest[0]}`                                    // sh-1..3 / sh-window
    case 'duration': return `dur-${rest[0]}`
    case 'easing':   return `ease-${rest[0]}`
    case 'z':        return `z-${rest[0]}`
    case 'geometry': return rest.join('-')                                     // note-titlebar-h 等
    default: throw new Error(`unmapped token group: ${p.join('.')}`)
  }
}

StyleDictionary.registerTransform({
  name: 'name/bianfa', type: 'name',
  transform: token => bfName(token.path),
})

StyleDictionary.registerTransformGroup({
  name: 'bianfa/css',
  transforms: ['attribute/cti', 'name/bianfa', 'color/css', 'time/seconds', 'size/rem'],
})

const isDark = t => t.path[0] === 'dark'
const decl = t => `  --${t.name}:${t.$value};`

StyleDictionary.registerFormat({
  name: 'css/bianfa-tokens',
  format: async ({ dictionary, options }) => {
    const tail = await fs.readFile(new URL('./src/static-tail.css', import.meta.url), 'utf8')
    const light = dictionary.allTokens.filter(t => !isDark(t))
    const dark  = dictionary.allTokens.filter(isDark)
    return [
      '/* ============ bianfa · 淡彩纸 Tinted Paper · tokens v1.0（生成产物，勿手改）',
      '   对比度均由 WCAG 2.2 相对亮度公式实测计算，见 contrast-matrix.md ============ */',
      ':root {',
      '  color-scheme: light dark;',
      ...light.map(decl),
      `  font-size:calc(16px * var(--ui-scale));`,
      '}',
      '',
      '/* 暗色：不是反色，只动 L 与 C，色相角不变（基准 §6.1） */',
      ':root[data-theme="dark"] {',
      '  color-scheme: dark;',
      ...dark.map(decl),
      '}',
      '@media (prefers-color-scheme: dark) {',
      '  :root:not([data-theme="light"]) {',
      '  color-scheme: dark;',
      ...dark.map(decl),
      '  }',
      '}',
      '',
      tail,           // [data-os="windows"] 覆盖 + font-synthesis 全局关
    ].join('\n')
  },
})
```

**为什么暗色不进 `@theme`**：`@theme` 是 Tailwind 的编译期常量表，主题切换必须走运行时选择器。所以 `tokens.css` 自己就是完整的三段式（裸 `:root` → `@media prefers-color-scheme` → `:root[data-theme="dark"]`，与基准 §6.2 完全一致），Tailwind 只在其上做别名。

Rust formatter 直接输出 `(u8,u8,u8)`，不让 Rust 在运行时解析 hex（新建窗口是热路径）：

```js
const hex2rgb = h => [1, 3, 5].map(i => parseInt(h.slice(i, i + 2), 16))

StyleDictionary.registerFormat({
  name: 'rust/consts',
  format: ({ dictionary }) => {
    const pick = pred => dictionary.allTokens.filter(pred)
    const notePapers = theme => pick(t =>
      t.path[t.path[0] === 'dark' ? 1 : 0] === 'note' && t.path.at(-1) === 'paper' &&
      (theme === 'dark') === isDark(t))
    const row = t => {
      const name = t.name.replace(/^p-/, '')
      return `        ("${name}", (${hex2rgb(t.$value).join(', ')})),`
    }
    const surfaces = pick(t => /^c-(canvas|surface-1|overlay)$/.test(t.name))
      .map(t => `    pub const ${t.name.toUpperCase().replace(/-/g, '_')}${isDark(t) ? '_DARK' : '_LIGHT'}: (u8,u8,u8) = (${hex2rgb(t.$value).join(', ')});`)
    return [
      '// @generated by style-dictionary — DO NOT EDIT',
      'pub mod tokens {',
```

### 2.5 对比度矩阵 formatter（基准 §2.1 要求的 CI 门禁，实际代码）

基准 §2.1 / §7 要求"输出一份「每个前景 × 每个背景」的 WCAG 矩阵报告，CI 中任何一对跌破即 fail build"。这里给出完整实现。三个工程要点：

1. **半透明必须先合成再测**。暗色的 `--c-hover:rgba(255,255,255,.045)`、`--c-border:rgba(255,255,255,.10)` 直接量对比度是无意义的，必须先 `over()` 压在它实际所处的表面上。
2. **阈值按"对类"给，不是全局 4.5**。基准自己就写了三档不同要求（正文 ≥10:1 on 纸、次级 ≥4.5、图标/色点 ≥3:1），并且明确 `--c-text-disabled`（3.30:1）"仅禁用态，不承载信息"。用一条 4.5 扫全表会把基准自己的合法值判失败。
3. **报告全量、门禁按白名单**。矩阵输出所有组合（含"禁用组合"），但只对声明过的对类 fail build——否则报告会退化成噪音，没人看。

```js
// packages/tokens/contrast.mjs —— 零依赖，可单测
const HEX  = /^#([0-9a-f]{3}|[0-9a-f]{6})$/i
const RGBA = /^rgba?\(\s*([\d.]+)[\s,]+([\d.]+)[\s,]+([\d.]+)(?:[\s,/]+([\d.]+%?))?\s*\)$/i

export function parseColor(v) {
  if (typeof v !== 'string') return null
  const s = v.trim()
  if (HEX.test(s)) {
    const h = s.slice(1)
    const f = h.length === 3 ? [...h].map(c => c + c) : h.match(/../g)
    return { r: parseInt(f[0], 16), g: parseInt(f[1], 16), b: parseInt(f[2], 16), a: 1 }
  }
  const m = s.match(RGBA)
  if (!m) return null
  const a = m[4] == null ? 1 : (m[4].endsWith('%') ? parseFloat(m[4]) / 100 : parseFloat(m[4]))
  return { r: +m[1], g: +m[2], b: +m[3], a }
}

/** source-over 合成：把 fg 压在已不透明的 bg 上 */
export const over = (fg, bg) => fg.a >= 1 ? fg : {
  r: fg.r * fg.a + bg.r * (1 - fg.a),
  g: fg.g * fg.a + bg.g * (1 - fg.a),
  b: fg.b * fg.a + bg.b * (1 - fg.a),
  a: 1,
}

const lin = v => { const s = v / 255; return s <= 0.04045 ? s / 12.92 : ((s + 0.055) / 1.055) ** 2.4 }
export const luminance = c => 0.2126 * lin(c.r) + 0.7152 * lin(c.g) + 0.0722 * lin(c.b)

/** WCAG 2.2 对比度。base = 半透明背景所处的底面（亮色为 canvas，暗色为 canvas）。 */
export function ratio(fgRaw, bgRaw, base) {
  const bg = over(bgRaw, base)
  const fg = over(fgRaw, bg)
  const [hi, lo] = [luminance(fg), luminance(bg)].sort((a, b) => b - a)
  return (hi + 0.05) / (lo + 0.05)
}

const NOTES = ['graphite','rose','coral','amber','citron','fern','teal','azure','violet','fuchsia']
/** --c-text-3 的合法底面白名单：它按设计恰好卡在 4.55 on surface-3，任何更暗的底都会跌破 */
const T3_BG = ['c-canvas','c-surface-1','c-surface-2','c-surface-3','c-overlay','c-selected']
const ALL_BG = [...T3_BG, 'c-hover', 'c-active']
const x = (fgs, bgs) => fgs.flatMap(f => bgs.map(b => [f, b]))

export const GATES = [
  { id: 'body-text',     min: 4.5, why: '正文/次级文字',
    pairs: () => x(['c-text-1','c-text-2'], ALL_BG) },
  { id: 'tertiary-text', min: 4.5, why: '三级文字（白名单底面）',
    pairs: () => x(['c-text-3'], T3_BG) },
  { id: 'note-ink',      min: 10,  why: '便笺正文，余光扫读场景（基准 §7）',
    pairs: () => NOTES.map(n => [`p-${n}-ink`, `p-${n}`]) },
  { id: 'note-ink2',     min: 4.5, why: '便笺次级（meta / 时间戳）',
    pairs: () => NOTES.map(n => [`p-${n}-ink2`, `p-${n}`]) },
  { id: 'note-dot',      min: 3,   why: '色点/3px 色条，图形元素',
    pairs: () => NOTES.flatMap(n => [[`p-${n}-dot`, `p-${n}`], [`p-${n}-dot`, 'c-overlay']]) },
  { id: 'focus-ring',    min: 3,   why: '一个环走遍全色板（基准 §7）',
    pairs: () => [...NOTES.map(n => ['c-focus', `p-${n}`]), ...x(['c-focus'], T3_BG)] },
  { id: 'on-accent',     min: 4.5, why: '实心按钮上的文字',
    pairs: () => ['c-accent','c-accent-hover','c-accent-active','c-danger','c-success','c-warning','c-info']
      .map(b => ['c-text-on-accent', b]) },
  { id: 'semantic-text', min: 4.5, why: '语义色作文字色',
    pairs: () => x(['c-accent','c-danger','c-success','c-warning','c-info'],
                   ['c-canvas','c-surface-1','c-surface-3','c-accent-subtle','c-danger-subtle','c-success-subtle','c-warning-subtle']) },
  // 以下只报告不门禁：非信息承载
  { id: 'disabled',  min: 0, report: true, why: '禁用态，不承载信息（基准 §2.2 注）',
    pairs: () => x(['c-text-disabled'], T3_BG) },
  { id: 'borders',   min: 0, report: true, why: '分隔线，1.4.11 不适用于纯装饰分隔',
    pairs: () => x(['c-border-subtle','c-border','c-border-strong'], ['c-canvas','c-surface-1','c-surface-3']) },
  { id: 'note-line', min: 0, report: true, why: '同色相实色描边，低对比是设计意图（基准 §5.2）',
    pairs: () => NOTES.map(n => [`p-${n}-line`, `p-${n}`]) },
]

export const gateFailures = []

export function runMatrix(get, mode) {
  const base = parseColor(get('c-canvas'))
  const rows = []
  for (const gate of GATES) {
    for (const [fgName, bgName] of gate.pairs()) {
      const fg = parseColor(get(fgName)), bg = parseColor(get(bgName))
      if (!fg || !bg) continue                 // 该模式下未定义（如亮色无 paper-dim）
      const v = ratio(fg, bg, base)
      const ok = gate.report || v >= gate.min
      rows.push({ mode, gate: gate.id, fg: fgName, bg: bgName, ratio: +v.toFixed(2), min: gate.min, ok, report: !!gate.report })
      if (!ok) gateFailures.push(`[${mode}] ${gate.id}: --${fgName} on --${bgName} = ${v.toFixed(2)}:1 < ${gate.min}:1 （${gate.why}）`)
    }
  }
  return rows
}
```

### 2.7 CSS 特性基线

目标 webview：Windows = WebView2 Evergreen（Chromium 140+）；macOS 13+ = WKWebView / Safari 16.4+。

**可直接用**：`:has()`、container queries（基准 §5.6 的断点全靠它）、`@layer`、原生嵌套、`oklch()`、`color-mix()`（基准 §5.2 的 `--note-rule/-sel/-mark` 依赖它）、`@property`、`text-wrap: balance`、`overflow: clip`。

**明确不作渐进增强、两平台同开或同关**（基准 §3.3 最硬的一条）：

| 特性 | 决定 | 理由 |
|---|---|---|
| `text-autospace` | 两平台都写 `no-autospace` | Safari 18.4+ 已 ship 但初值就是 `no-autospace`，Chromium 只有实验子集。显式钉死，防未来默认值漂移 |
| `text-spacing-trim` | 两平台都写 `space-all` | 关掉 Chromium 的引擎级全角挤压，交给 BF Punct 字体层。Safari 未 ship → 忽略即等价于不挤压，**两边结果一致** |
| `font-feature-settings: "palt"/"halt"/"chws"` | **全面禁用，stylelint 硬拦 + CI grep** | 苹方有、雅黑无，开了必然两平台换行位置错位。见 §9 门禁 |
| `hanging-punctuation` | 不用 | 只有 WebKit 有，用了就是单边分叉 |
| `text-box-trim` | 仅用于 `.btn/.tab/.badge` 等西文为主的 UI 元素 | 它改的是行盒上下裁切，不改宽度，不影响换行；中文正文禁用 |
| `light-dark()` | 不作为唯一机制 | macOS 14.5 以下 WKWebView 不支持；主题走三段式选择器 |
| `field-sizing` | 不用 | Safari 未支持；便笺自增高改 `contenteditable` |
| CSS anchor positioning | 不用 | Safari 26 才有；浮动菜单继续用 Floating UI |
| `scrollbar-width` / `scrollbar-color` | **stylelint 全局禁止** | 一旦出现，Chromium 会整体忽略所有 `::-webkit-scrollbar` 规则，两平台滚动条当场分叉；且 `scrollbar-color` 在 macOS Safari 26.3 实测无效 |

**结论：Base UI 1.7.0 作为 primitive，用 `shadcn@4.20.1` CLI 把组件源码生成进 `packages/ui/src/primitives/`，之后自己维护，不作为长期黑盒依赖。**

三条硬理由：

1. 无边框桌面窗口要大量魔改 primitive —— `data-tauri-drag-region` 与 Popover 的指针事件冲突、置顶窗口的 z-index 层级（必须落在基准 `--z-*` 的 9 档里，不许组件自带 9999）、便笺 220×220 下 Dialog 要退化成整窗覆盖。vendored 源码可以直接改，npm 依赖只能 patch。
2. Base UI 是 Radix 的事实继任者，2026-07 起是 shadcn 默认，a11y 血统最正（焦点陷阱、`aria-activedescendant`、RTL、屏幕阅读器公告都已验证）。
3. Ark UI 的跨框架能力对我们**没有价值**（已锁定 React），却要付 Zag.js 状态机的体积。

只 vendored 这些：`Dialog / Popover / Menu / Tooltip / Select / Switch / Checkbox / Tabs / ScrollArea / Toast`。其余（Button、Badge、Input、Card）**全部自建**——它们不需要 a11y 状态机，vendored 反而制造无意义的抽象层。

**vendoring 时必须做的三处统一改造**（写进 `VENDORED.md` 的改动清单）：

1. **删掉每个 primitive 自带的 focus 样式**。全 app 只有一条 focus ring，来自基准 §4：
   ```css
   :focus{ outline:none }
   :focus-visible{ outline:2px solid var(--c-focus); outline-offset:2px; border-radius:inherit; }
   .note :focus-visible{ outline-offset:1px; box-shadow:0 0 0 1px var(--note-paper); }
   ```
   `grep -rn "outline:" src/primitives/` 除这一处外必须为空。
2. **z-index 全部换成 `var(--z-menu)` / `var(--z-modal)` / `var(--z-toast)`**，禁止字面数字。
3. **所有 hover-only 的触发器同时绑 `:focus-within`**（基准 §7）。Base UI 的 Popover trigger 默认只管 `:hover`/`:focus`，便笺工具栏这类容器级 hover 要我们自己补。

## 4. 图标

**结论：Lucide 1.40.0，构建期生成 SVG sprite，运行时用 `<use>`，不用 React 组件。**

实测：30 个 `lucide-react` 组件 tree-shake 后 3.5 KB gzip —— 体积不是问题，**每窗口重复解析 30 个 React 组件**才是。sprite 方案下这 3.5 KB 变成 0 KB JS + 一个约 8 KB 的静态 `icons.svg`，被 15 个 webview 共享同一份 HTTP 缓存条目，且不进 React 调和。

```tsx
// packages/ui/src/Icon.tsx —— 全部图标的唯一运行时成本
import type { IconName } from './icons.gen'   // 构建期生成的联合类型
export function Icon({ name, size = 16, className }:
  { name: IconName; size?: number; className?: string }) {
  return (
    <svg width={size} height={size} className={className} aria-hidden focusable="false">
      <use href={`/icons.svg#i-${name}`} />
    </svg>
  )
}
```

Vite 插件扫描 `packages/ui/src/icons/*.svg`（从 `lucide` 包按名单 copy），输出 `icons.svg` + `icons.gen.ts`。名单文件 `icons.manifest.txt` 进 git，新增图标必须显式登记 —— 这就是防止图标风格失控的机制。

**规格**：16px / **`stroke-width: 1.5`**（基准 §4；Lucide 默认 2 在 13px UI 字号旁边偏重）。sprite 生成脚本在写入前统一把 `stroke-width` 改写为 1.5，并断言所有 symbol 的 `viewBox` 都是 `0 0 24 24`——尺寸不一致会让"16px 图标"实际光学大小不一。图标颜色一律 `stroke: currentColor`，禁止 `fill` 硬编码，这样它在便笺里自动继承 `--note-ink`、在中性 UI 里继承 `--c-text-*`。

**不做 SF Symbols + Fluent System Icons 双原生。** SF Symbols 有 Apple 授权限制且不能在 web 层直接引用；`@fluentui/svg-icons@1.1.339` 只覆盖 Windows 语义。维护两套 = 两套设计评审 + 两套视觉回归，对 1–3 人团队是净亏。仅在**系统窗口控件**（Win11 便笺窗 40×28 的 `─ ✕`、主窗 46×32 三枚；macOS 主窗原生红绿灯、便笺小窗自绘单个 12px 关闭点）用平台原生绘制——这属于基准 §8 红线三允许的 chrome 层分叉，代码必须落在 `src/platform/` 并在清单登记。

## 5. 字体

### 5.1 体积现实（实测）

Noto Sans SC 单字重（400），Google Fonts 官方 unicode-range 切片：**101 片，合计 2.30 MB woff2，平均 23 KB/片**；按切片序累计，前 30 片 257 KB，前 50 片 787 KB。四个字重全量 ≈ **9.2 MB**。而 Tauri 的卖点就是安装包 5–15 MB。**内嵌全量中文字体等于把安装包翻倍**。

### 5.2 结论：系统中文字体 + 只内嵌 BF Punct

桌面应用与网页的关键差异：**用户系统里一定有一个好的中文 UI 字体**（Win11 = Microsoft YaHei UI，macOS = PingFang SC），且它正是用户在系统其它地方看到的字体。用它 = 零体积 + 原生一致性。

字体栈**逐字使用基准 §2.2 的 `--f-sans` / `--f-mono`**，不在本章重定义：

```css
/* tokens.css 生成，来自 typography.json 的 font.family.* */
--f-sans:"BF Punct",-apple-system,BlinkMacSystemFont,"Segoe UI Variable Text","Segoe UI",
         "PingFang SC","Microsoft YaHei UI","Microsoft YaHei","Noto Sans SC","Hiragino Sans GB",Arial,sans-serif;
--f-mono:ui-monospace,"SF Mono",Menlo,"Cascadia Mono",Consolas,"Sarasa Mono SC",monospace;
```

三条容易踩的坑：

* **西文必须排在中文之前**。否则英文和数字会用苹方/雅黑自带的西文字形渲染，字宽明显更松。
* **不要把 `system-ui` 放在栈首。** 中文 Windows 上 `system-ui` 解析为 Microsoft YaHei UI，它的拉丁字形明显劣于 Segoe UI，中英混排会立刻难看。基准的栈里没有 `system-ui`，这是有意的。
* **字重只有 400 / 700 两个实体（Windows）**。`Microsoft YaHei` 没有 500/600，写 `font-weight:600` 会触发合成假粗，13px 中文笔画糊成一团。因此全局 `font-synthesis-weight:none; font-synthesis-style:none;`，`[data-os="windows"]` 下 `--fw-medium:400`（用颜色提一级补偿）、`--fw-strong:700`。**层级靠「字号 + 颜色 + 字距」建立，不靠字重**，这条推论必须一起接受。

### 5.3 BF Punct 构建管线（唯一内嵌的中文相关字体）

基准 §3.3 把中文标点挤压从"CSS 特性"移到"字体层"，这是整个排版方案里唯一能让 WebView2 与 WKWebView 逐像素一致的做法。构建步骤在 `packages/fonts/build.mjs` 里，产物进 `src-tauri/resources/fonts/`：

```bash
# 1. 子集：从 Noto Sans SC（OFL）裁出 52 个中文标点
pyftsubset NotoSansSC-Regular.otf \
  --unicodes="U+3001-3002,U+3008-300F,U+3010-3011,U+3014-3017,U+2018-201D,U+2025-2026,\
U+00B7,U+FF01,U+FF08-FF09,U+FF0C,U+FF0E,U+FF1A-FF1B,U+FF1F,U+FF5E,U+FF5F-FF60" \
  --layout-features='' --no-hinting --desubroutinize \
  --flavor=woff2 --output-file=bf-punct.woff2
# 2. 静态改 advance：闭合类标点 advance = 0.5em 并调 LSB（脚本 tools/halfwidth.py）
#    —— 因为是静态字宽而非 OpenType feature，不依赖 text-spacing-trim / chws 激活
```

```css
/* packages/ui/src/styles/base.css */
@font-face{
  font-family:"BF Punct";
  src:url("asset://localhost/fonts/bf-punct.woff2") format("woff2");
  font-display:block;                 /* 标点必须避免 FOUT 抖行 */
  font-weight:400 700;                /* 单实例覆盖两档，雅黑/苹方的粗体由系统字体接管其余字符 */
  unicode-range:U+3001-3002,U+3008-300F,U+3010-3011,U+3014-3017,U+2018-201D,

                U+FF1F,U+FF5E,U+FF5F-FF60;
```

`unicode-range` 是必须的：没有它，`"BF Punct"` 排在栈首会试图承担所有字符的匹配检查；有它，WebView 只在这 52 个码位上取它，其余一个字节都不读。

**产物预算 6.4 KB（实测），硬上限 8 KB**，超了 CI 红。`.display`（≥24px 的大字场景）关闭 BF Punct，避免 Noto 标点与雅黑/苹方正文的笔画粗细在大字号下露馅——这一条在 `prose.css` 里实现为 `.display{ font-family:-apple-system,"Segoe UI","PingFang SC","Microsoft YaHei UI",sans-serif; }`。

**第 1 周必做 spike**（基准 §3.3）：WebView2 与 WKWebView 各渲染 `他说：「明天（周三）14:00 开会。」`，像素比对 + 换行位置比对。不成立就退回"两平台都不挤压"（删掉 BF Punct，`--f-sans` 去掉栈首一项），**绝不单边开**。这个 spike 的输出直接进 `packages/fonts/tests/punct.spec.ts`，用 Playwright 在 Linux+Chromium 与 macOS+WebKit 各截一张 `<pre>` 图，断言换行索引数组相同。

### 5.4 Inter 拉丁子集：已实现，默认关闭

基准 §3.1 把 Inter 拉丁子集标为「可选，统一两平台数字字面」。管线做好了（`pyftsubset` 到 U+0000–00FF + 常用符号 + `tnum`，单字重 400，实测 46.2 KB），但**v1 默认不打包**，由构建开关 `BF_EMBED_INTER=1` 控制：

* 打开时，生成器在 `font.family.sans` 的 `"Segoe UI"` 之后插入 `"Inter"`，内嵌总量 = 6.4 + 46.2 = **52.6 KB**，仍在基准的 ≤55 KB 上限内。
* 默认关闭的理由：在 macOS `-apple-system` 与 Windows `Segoe UI` 都命中的前提下，Inter 实际只在 Linux 与缺字兜底时才绘制，46.2 KB 换不到可见收益；而"数字对齐"这个真实需求已经由基准的 `font-variant-numeric: tabular-nums`（所有时间戳/计数/字数强制）解决了。
* 若将来要求两平台拉丁**度量**完全一致（那会连带让拉丁段落的换行位置也一致，是红线三的加分项），把 Inter 提到 `-apple-system` 之前并打开开关——那时需要重测 Windows 13px 下的 hinting 质量。

### 5.5 不内嵌中文正文字体：做成门禁

口头约定会被"就这一次"破坏，所以写进 CI：

## 6. 状态管理与数据层（多窗口核心）

### 6.1 分层

```
Rust (SQLite, rusqlite 0.40.2)      ← 唯一真相源，含单调递增 rev
        ↓ invoke (写)   ↑ emit "db:changed" (广播)
TanStack Query 5.102.8              ← 每窗口一份服务端状态缓存
        ↓
Zustand 5.0.15                      ← 每窗口本地 UI 状态（不跨窗口）
```

* **不要 Jotai/Signals 做数据层**。数据的真相在 SQLite，不在 JS 堆；需要的是缓存失效协议，不是响应式原子。Zustand 5.0.15 只管"这个便笺窗口的工具栏展开了没"这类纯 UI 态。
* **不引入 `@tanstack/db@0.8.7` / LiveStore 0.4.0 / Zero 1.9.0**。它们把真相源搬到前端（各窗口一份），在 15 个 webview 下就是 15 份内存副本 + 15 路同步——正好是我们要避免的。

### 6.2 跨窗口同步：只用 Tauri event，不用 BroadcastChannel

**明确否决 BroadcastChannel / `storage` 事件 / localStorage 轮询**：

* Linux WebKitGTK 下 localStorage 在多 webview 间不同步（tauri-apps/tauri#10981，未修）。
* macOS WKWebView 不支持自定义 data directory，各 webview 的 `WKWebsiteDataStore` 行为依赖 macOS 版本，跨版本不保证 BroadcastChannel 投递。
* Tauri event 走 Rust IPC，三平台行为**完全一致**，且能带发送方 window label 做回声抑制。

### 6.3 协议

```rust
// src-tauri/src/db/events.rs
#[derive(Clone, serde::Serialize)]
pub struct DbChanged {
    pub rev: u64,                 // 全局单调，事务提交时 +1
    pub origin: String,           // 发起窗口 label，用于回声抑制
    pub tables: Vec<&'static str>,
    pub ids: Vec<String>,
}

#[tauri::command]
pub async fn update_note(
    app: tauri::AppHandle, db: tauri::State<'_, Db>,
    window: tauri::Window, id: String, patch: NotePatch,
) -> Result<Note, String> {
    // 写与 rev 自增在同一事务内，保证 rev 与数据一致
    let (note, rev) = db.tx(|tx| {
        let n = notes::apply_patch(tx, &id, &patch)?;
        let rev = meta::bump_rev(tx)?;
        Ok((n, rev))
    }).map_err(|e| e.to_string())?;

    // 换色时同步刷新原生窗口底色，否则拖动/resize 露出的是旧纸色
    if let Some(color) = patch.color.as_deref() {
        let (r, g, b) = crate::tokens::note_paper(color, theme::is_dark(&app));
        if let Some(w) = app.get_webview_window(&format!("note-{id}")) {
            w.set_background_color(Some(tauri::window::Color(r, g, b, 255)))?;
        }
    }

    app.emit("db:changed", DbChanged {
        rev, origin: window.label().to_string(),
        tables: vec!["notes"], ids: vec![id],
    }).map_err(|e| e.to_string())?;
    Ok(note)
}
```

```ts
// packages/data/src/bridge.ts
import { listen } from '@tauri-apps/api/event'                  // @tauri-apps/api 2.11.1
import { getCurrentWebviewWindow } from '@tauri-apps/api/webviewWindow'
import type { QueryClient } from '@tanstack/react-query'

const self = getCurrentWebviewWindow().label
let seenRev = 0

export function wireDbEvents(qc: QueryClient) {
  return listen<DbChanged>('db:changed', ({ payload }) => {
    if (payload.origin === self) return          // 自己的写，乐观更新已生效
    if (payload.rev <= seenRev) return           // 乱序 / 重放保护
    seenRev = payload.rev

    for (const id of payload.ids) qc.invalidateQueries({ queryKey: ['note', id] })
    if (payload.tables.includes('notes')) {
      qc.invalidateQueries({ queryKey: ['notes', 'list'] })     // 主窗口才有订阅者
    }
  })
}
```

**为什么是"失效 + 拉取"而不是"推送整条数据"**：便笺窗口只订阅 `['note', id]`，主窗口才订阅 `['notes','list']`。推送 payload 会让 15 个窗口都反序列化一份它们不关心的数据；失效协议下未订阅的 query key 是 no-op，零成本。

**输入路径的写节流**：便笺正文用 400 ms debounce + `useMutation` 乐观更新；`invalidate` 在本窗口被 `origin === self` 短路，所以打字时不会自我抖动。

**"轻量全局态"**（主题、`--ui-scale` 四档、置顶偏好）走 `tauri-plugin-store@2.4.4`（Rust 侧持久化）+ 同一 event 通道，不进 SQLite。

### 6.4 主题同帧切换（基准 §6.2 的实现）

主题不是普通全局态，它有一个"十几个窗口不能一半亮一半暗"的硬要求，所以走独立通道且**不经过 TanStack Query**：

```ts
// packages/data/src/theme.ts
import { listen, emit } from '@tauri-apps/api/event'

export function wireTheme() {
  return listen<{ theme: 'light' | 'dark' }>('theme-changed', ({ payload }) => {
    const root = document.documentElement
    root.setAttribute('data-theme-switching', '')        // 200ms 内禁一切 transition
    requestAnimationFrame(() => {                        // 全部窗口在同一帧改属性
      root.setAttribute('data-theme', payload.theme)
      setTimeout(() => root.removeAttribute('data-theme-switching'), 200)
    })
  })
}
```

```css
/* base.css */
[data-theme-switching] *{ transition:none !important; animation:none !important; }
```

Rust 侧监听系统主题（Win `WM_SETTINGCHANGE` / mac `AppleInterfaceThemeChangedNotification`），先调 `window.set_theme()` 同步原生右键菜单/IME 候选框/滚动条与 `set_background_color()`，再一次性 `app.emit("theme-changed", …)`。**没有这条 200ms 的 transition 禁令，15 个窗口各跑一遍 `--dur-3` 的颜色补间会直接掉帧**——这是把基准 §6.2 第 3 点落到代码的唯一位置。

**实时性要求更高的场景**（团队便笺墙的协作光标）走独立通道：WebSocket 直连 Rust，Rust 再 `emitTo({ kind: 'WebviewWindow', label: 'wall' }, ...)` 定向投递，不广播。

## 7. 富文本编辑器集成

Tiptap 3.31.2（MIT；付费仅限 Cloud/Comments/AI 等服务，本地编辑器功能全免费）。

### 7.1 两级编辑器（对抗 §0 的 99 KB 地板）

15 个便笺窗口各挂一个 ProseMirror 实例 = 15 × 330 KB 解析 + 15 份 EditorState/plugin 树。方案：

* **未聚焦的便笺**：渲染 `@tiptap/static-renderer@3.31.2` 在写入时预生成的静态 HTML 字符串（存 SQLite 的 `body_html` 列）。零 JS。
* **窗口获得焦点**（`tauri://focus`）：`import('./editor')` 动态加载 editor chunk，挂载 Editor，把光标定位到点击处。冷启延迟实测目标 ≤ 60 ms（chunk 已在 HTTP 缓存，只需解析）。
* **失焦 5 s 后**：`editor.destroy()`，回落静态 HTML，释放 ~2 MB 堆；同时 `cancelAnimationFrame` 全部句柄（基准 §8 红线二：失焦 3s 后停止所有 `animation` 与 `rAF`——编辑器销毁给到 5s，动画/rAF 的停止提前到 3s，两个时限分开配置）。

这样常驻的 ProseMirror 实例通常只有 1–2 个。

**这个方案有一条必须测的隐含契约**：静态 HTML 与编辑器挂载后的 DOM，**必须逐像素同形**。它们由同一份 `.bf-prose` 样式驱动，但 ProseMirror 会额外加 `contenteditable`、`ProseMirror` class、以及尾部的 trailing `<br class="ProseMirror-trailingBreak">`。任何一处差异都会在聚焦瞬间造成文字跳动——在 220px 宽的窗口里，一次重排就是几行内容位移。所以：

```ts
// packages/ui/tests/visual/editor-swap.spec.ts
// 同一份 JSON doc：① static-renderer 输出 ② Editor 挂载后 outerHTML
// 断言两者在同一容器里的 getClientRects() 逐行 top/left/width 全等（容差 0）
```

这条测试同时守住了基准 §8 红线三的一半——**平台分叉不得改变换行结果**，而"静态/编辑两态不得改变换行结果"是它在时间维度上的同构要求。


**为什么 `.bf-prose` 用 `--note-*` 带 fallback 而不是直接用 `--c-*`**：同一份 prose 样式服务三个语境（基准 §1 的着色分界表）——便笺窗口（整面淡彩，`--note-*` 已由 JS 赋值）、主列表预览卡（中性卡片，`--note-*` 未定义，落到 `--c-*`）、AI 面板（**纯中性零着色**，故意不设 `--note-*`）。一条 `var(--note-ink, var(--c-text-1))` 同时覆盖三者，不需要三套 class。

**行高**：`--lh-body` = 1.70（14px → 23.8px 行距）。这不是审美选择，基准 §5.1 的 220×220 尺寸账（可用高 178px ≈ 7.47 行 ≈ 108 汉字）是按 23.8px 算的；改成 1.75 会让每张便笺少 0.2 行，容量宣称当场失效。不要给拉丁字母单独设 `line-height`，会造成同段内基线跳动。

**`≥700px` 高时正文 14→15px / `--lh-loose`**（基准 §5.6 断点表）由容器查询驱动，写在 `note.css` 而不是 `prose.css`：

```css
@container note (min-height:700px){ .bf-prose{ font-size:var(--fs-lg); line-height:var(--lh-loose); } }
@container note (max-width:200px){ .bf-prose{ font-size:var(--fs-sm); line-height:var(--lh-cjk); } }
```

编辑器内容的 typography 只允许来自 `.bf-prose`；Tiptap 的所有 node view 一律不带内联样式，全靠 `data-type` 属性钩住上面的规则。**stylelint 规则 `declaration-property-value-disallowed-list` 禁止在 `packages/ui/src/` 任何位置出现 `font-feature-settings`**——这是基准 §3.3 那条禁令在代码层的实体。

### 8.1 窗口创建的平台分叉（基准 §6.3 红线一）

```rust
// src-tauri/src/window/note.rs（节选）—— 分叉集中在此文件，清单登记
#[cfg(target_os = "windows")]
const NOTE_TRANSPARENT: bool = false;   // 带 alpha 的合成面 → Chromium 退回灰度抗锯齿，
                                        // 放弃 ClearType，13px 中文明显变虚。红线，不可配置。
#[cfg(target_os = "macos")]
const NOTE_TRANSPARENT: bool = true;    // 系统级早无亚像素 AA，透明零成本
```

前端对应 `document.documentElement.dataset.os = await platform()`，`[data-os="windows"]{ --r-window:0 }` 由 `static-tail.css` 提供。**便笺窗口的圆角是 CSS 的 `--r-window`，不是 Rust 的**——Windows 下 `decorations:false` 的窗口 DWM 不保证给圆角且无 API 可查，所以 Windows 是直角，这是既定结果，不得为了圆角开透明。毛玻璃（`NSVisualEffectView` / `backdrop-filter`）只允许出现在设置窗口与 AI 面板。

CI 拦截：

```bash
grep -rn 'transparent: *true\|transparent(true)' src-tauri/src/ \
  | grep -v 'settings.rs\|ai_panel.rs\|#\[cfg(target_os = "macos")\]' \
  && { echo "便笺窗口不得透明（基准 §8 红线一）"; exit 1; }
```

## 9. 设计交付流程（1–3 人）

**不做 Storybook。** Storybook 10 确实变轻了（ESM-only，安装体积 −29%），但它解决的是"跨团队组件沟通"，而 1–3 人的团队里沟通成本本来就接近零，剩下的全是维护成本：每个组件写 story、story 与真实用法漂移、CI 多一条构建链。

**做应用内 `/dev` 面板。** 挂在 `settings.html?dev=1` 下（生产构建通过 `import.meta.env.DEV` + 环境变量双开关剔除，不进产物）：

1. **`/dev/tokens`** —— 全部 token 的实时色板/字阶/间距/动效曲线预览，直接读 `getComputedStyle(document.documentElement)`，所以它展示的是**真实生效值**，不是文档里的值。漂移一眼可见。右栏并排渲染 `contrast-matrix.json`，把 `dist/` 里算出的对比度和浏览器里实际生效的色值再对一次——两者不一致就说明有人在 CSS 里覆盖了 token。
2. **`/dev/gallery`** —— 组件在真实主题、真实字体栈下的画廊，带 **亮/暗 × 中文/英文/中英混排 × `--ui-scale` 90%/100%/115%/130%** 的矩阵切换（四档与基准 §7 一致，不是浏览器缩放的 100/125/150）。
3. **`/dev/sizes`** —— 便笺窗口尺寸模拟器，滑杆从 **180×140**（基准 §5.6 的最小窗口）到 640×480，实时看每个容器查询断点的切换点、工具栏在哪个尺寸溢出。这是这个产品最容易出问题的地方，Storybook 给不了。
4. **`/dev/punct`** —— 中英混排与标点渲染的对照台：同一段文本分别在「BF Punct 开 / 关」「`text-spacing-trim: space-all` / `normal`」下渲染，并把换行位置索引打印出来。§5.3 的 spike 与后续回归都靠它。

**做视觉回归，但克制。** Playwright 1.62.1，`toHaveScreenshot({ maxDiffPixelRatio: 0.01 })`，**只 8 张关键截图**：便笺（亮/暗 × 220×220 与 400×360，共 4 张）、主窗口列表、AI 面板流式中间态、设置、以及一张 20 色便笺全色板对照图（浅/浓两档各一条色块带，保证色板改动一定被看到）。

* 跑在 `vite preview` 起的**纯 web 版**，不跑 Tauri 壳 —— 壳的窗口装饰在 CI 里不稳定。
* 只跑 **一个平台一个引擎**（Linux + Chromium，Docker 镜像内固定安装 Noto Sans SC + Noto Sans），避免三平台字体差异导致的假失败。
* **例外**：§5.3 的换行位置比对必须跨引擎（Linux Chromium + macOS WebKit），但它断言的不是像素而是 `getClientRects()` 的换行索引数组——这是数值断言，不受字体差异影响。
* 快照文件进 git，PR 里 diff 图直接可见。基线更新必须是**独立 commit**，不许和功能改动混在一起。
