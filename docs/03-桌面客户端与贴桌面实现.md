## 第 2 章　桌面客户端技术选型与窗口层级实现

本章只解决两件事：**用什么框架**，以及**"贴在桌面上"到底怎么实现**。第二件是整个项目技术风险最高的部分——它没有跨平台抽象层可用，必须逐平台写 native 代码，而且 Windows 11 24H2 之后经典做法已经半失效。

> **核实说明**：本章所有版本号、API 名称均于 2026-09-04 联网核实（crates.io / npm registry / GitHub 源码）。**未能核实**的三项已在正文中显式标注为"下单前自行复核"：Azure Artifact Signing 定价与地域资格、EV 证书 SmartScreen 政策、CA/B Forum 证书有效期上限。这三项的信息源（azure.microsoft.com、cabforum.org、CA 官网）在本次运行的网络环境中不可达，**不要把本章写的数字当作已核实事实去做采购决策**。

#### 2.1.3 结论：选 Tauri 2.11.5

三条理由，按权重排序：

1. **多窗口内存**。便笺是天然多窗口应用。Electron 每个 `BrowserWindow` 起一个 renderer 进程；Tauri 在 Windows 上所有 webview 共用同一个 user data folder，WebView2 复用同一个 `msedgewebview2.exe` browser process，同源页面在 site isolation 下共享 renderer。**注意这是机制推断，不是实测**：wry 每次建 webview 都调 `CreateCoreWebView2EnvironmentWithOptions(NULL, &data_directory, ...)`，复用发生在 WebView2 运行时层（同 user data folder + 同 options ⇒ 同 browser process）。§2.3 把"1/10/30 张便笺 RSS 实测"列为发版前必做项，就是为了验证这一条。
2. **native 代码是编译链一等公民**。`src-tauri/src/platform/{windows,macos}.rs` 两个文件，`cargo build` 顺手编出来，不需要 prebuild 矩阵、不需要 node-gyp、不需要跟 Electron 大版本重编译。
3. **官方签名/更新链完整**。Tauri 官方文档直接给 Azure Artifact Signing 的 `signCommand` 写法（§2.4.1），不需要自己拼 electron-builder 插件。

#### 2.1.4 反驳一：Electron 真的"必须写 C++ N-API addon"吗？

**反方立场（成立的部分）**：不需要。Electron 的 `BrowserWindow.getNativeWindowHandle()` 返回 HWND 的 Buffer，用 `koffi` 这类现代 FFI 可以纯 JS 调 `SetWindowPos` / `SetWindowLongPtrW` / `DwmSetWindowAttribute`，一行 C++ 都不用写。macOS 侧 `setAlwaysOnTop(true, 'floating')` 和 `setVisibleOnAllWorkspaces(true, { visibleOnFullScreen: true })` 是 Electron 官方 API，比 Tauri 还省事。**初稿说"必须维护 C++ addon + 四份 prebuild"是夸大，这一条论据不成立，予以删除。**

**维持原结论，理由换成三条更硬的**：

- **`SetWinEventHook` 的回调**。§2.2.3 的方案要求系统从**它自己的线程**回调进我们的代码。koffi 的 `koffi.register()` 支持回调，但跨线程回调进 V8 需要走 N-API thread-safe function；从系统 hook 线程直接调 JS 回调会崩。Electron 里做这个，还是得回到 native addon。Tauri 里 `unsafe extern "system" fn` 就是一个普通 Rust 函数。
- **z-order 需要周期性重放**（§2.2.3），是高频调用；FFI 每次跨语言边界的开销和类型编组在这里是纯负担。
- **体积和内存**（第 1 条）。这条与 FFI 无关，Electron 改不了。

**翻转条件（明确列出，只有这四条会推翻结论）：**

1. **要支持 Linux 且要求像素级一致** → 换 Electron。WebKitGTK 在字体渲染、`backdrop-filter`、IME 上和另两端对不齐。本项目需求只有 Windows + macOS，不触发。
2. **富文本要支持手写/压感** → 换 Electron。
3. **要用 Chromium 专有能力**（WebCodecs 全量、`OffscreenCanvas` + WebGPU 一致行为）→ 换 Electron。
4. **团队完全无法维护 Rust** → 仍不建议换 Electron（见上）。这种情况下正确做法是**砍掉"贴桌面"，只保留置顶**，然后 Electron 是合理选择——因为剩下的全是 Electron 官方 API。

**明确排除：** Flutter Desktop（多窗口 API 仍 experimental + 无 ProseMirror 级富文本）；双原生（1–3 人写两套 UI + 两套同步，2 倍工作量）。

### 2.2 【核心】"贴在桌面上"的三种语义

#### 2.2.0 先问一句，可能省两周

用户说"像便笺一样贴在桌面"，实际混了三种技术需求：

| 语义 | 用户感知 | Windows | macOS | 风险 |
|---|---|---|---|---|
| **A. 置顶** | 永远盖在别的窗口上面 | `SetWindowPos(HWND_TOPMOST)` | `NSWindow.level = 3` | 低 |
| **B. 贴桌面** | Win+D / 显示桌面时**不消失**，但平时不挡工作窗口 | 见 §2.2.3 | `level = desktopIcon+1` + `.stationary` | **高，约 2 周** |
| **C. 贴边 AppBar** | 吸附屏幕边缘挤开其他窗口 | `SHAppBarMessage` | 无对等 API | 中，**不做** |

**关键事实：Windows 自带便笺其实是普通窗口，Win+D 会把它一起最小化。** 所以语义 B 不是"复刻原版"，是**相对原版的增量功能**。如果用户要的只是"便笺散落在桌面上不被工作窗口挡住"，那么 A + 普通两档就够了，§2.2.3 整节可以砍掉。**这是本章第一优先级的待确认项。**

产品上给三档 z-order 开关（借鉴 Rainmeter）：`置顶 / 普通 / 贴桌面`，存在便笺属性 `z_mode` 里。

#### 2.2.1 拿到 HWND / NSWindow

```toml
# src-tauri/Cargo.toml
[target.'cfg(windows)'.dependencies]
windows = { version = "0.62.2", features = [
  "Win32_Foundation", "Win32_UI_WindowsAndMessaging",
  "Win32_UI_Accessibility", "Win32_Graphics_Dwm", "Win32_System_LibraryLoader",
]}
[target.'cfg(target_os = "macos")'.dependencies]
objc2 = "0.6.4"
objc2-app-kit = "0.3.2"
```

> **坑 1（一定会踩）**：`WebviewWindow::hwnd()` 的签名是 `pub fn hwnd(&self) -> crate::Result<HWND>`，这个 `HWND` 来自 **tauri 自己依赖的那个 `windows` crate 版本**。版本不同则类型不兼容，报错看起来毫无道理。永远走裸指针重建：
> ```rust
> let raw = win.hwnd()?.0 as isize;                              // 降级
> let hwnd = windows::Win32::Foundation::HWND(raw as *mut _);    // 用自己的版本重建
> ```
> **坑 2（Tauri 源码里明写的）**：`with_webview` 的文档注释原文是 —— "Note that `webview2-com`, `webkit2gtk`, `objc2_web_kit` and similar crates may be updated in **minor** releases of Tauri. Therefore it's recommended to **pin Tauri to at least a minor version** when you're using `with_webview`."。所以 `Cargo.toml` 里必须写 `tauri = "=2.11.5"` 或 `"~2.11"`，**不能写 `"2"`**，否则一次 `cargo update` 就可能编译不过。

macOS 侧 `ns_window()` 返回 `crate::Result<*mut c_void>`，AppKit 调用必须在主线程：

```rust
// src-tauri/src/platform/macos.rs
use objc2::{msg_send, runtime::AnyObject};
struct SendPtr(*mut AnyObject);
unsafe impl Send for SendPtr {}          // 裸指针不是 Send，必须包一层

pub fn apply(win: &tauri::WebviewWindow, level: isize, behavior: usize) -> tauri::Result<()> {
    let p = SendPtr(win.ns_window()? as *mut AnyObject);
    win.run_on_main_thread(move || unsafe {
        let _: () = msg_send![p.0, setLevel: level];
        let _: () = msg_send![p.0, setCollectionBehavior: behavior];
    })
}
```

用 `msg_send!` 裸消息而不是 `objc2-app-kit` 的类型化 API，是因为后者的 `NSWindow` 标了 `MainThreadOnly`，从裸指针构造 `Retained<NSWindow>` 的样板在 objc2 小版本间会变（objc2 0.6.x 期间已经变过）；`msg_send!` 跨版本稳定。

#### 2.2.2 语义 A：置顶

Tauri 有现成 API `window.set_always_on_top(true)`，但**在 macOS 上开箱是残的**，必须补 `collectionBehavior`。以下位掩码值已逐个对照 AppKit 头文件核实：

```rust
// NSWindowCollectionBehavior
const CAN_JOIN_ALL_SPACES: usize = 1 << 0;   //   1
const STATIONARY:          usize = 1 << 4;   //  16  Mission Control 不扫走
const IGNORES_CYCLE:       usize = 1 << 6;   //  64  不进 Cmd+` 循环
const FULLSCREEN_AUX:      usize = 1 << 8;   // 256  可浮在别的 App 全屏之上

// NSWindow.Level
const LEVEL_NORMAL:    isize = 0;
const LEVEL_FLOATING:  isize = 3;
const LEVEL_STATUSBAR: isize = 25;

apply(&win, LEVEL_FLOATING, CAN_JOIN_ALL_SPACES | STATIONARY | FULLSCREEN_AUX)?;
```

平台注意事项：

- **Windows**：`HWND_TOPMOST` 挡不住 DirectX 独占全屏，也挡不住 UAC 安全桌面。系统行为，不要绕。
- **Windows 虚拟桌面**：Tauri 源码里 `set_visible_on_all_workspaces` 的平台注释原文是 `**Windows / iOS / Android:** Unsupported.`（已核实 `crates/tauri/src/window/mod.rs`）。真要做需要未公开的 `IVirtualDesktopManagerInternal` COM 接口，GUID 每个 Windows 版本都变。**决定不做**，在设置里写明"置顶便笺仅在当前虚拟桌面显示"。
- **macOS**：不要拿 `LEVEL_STATUSBAR`(25) 当默认置顶，它会盖住菜单栏和 Dock，用户会当 bug 报。只在"专注模式"下作为可选项。
- **macOS 全屏**：不加 `FULLSCREEN_AUX`，用户进别的 App 全屏时便笺会消失——最常见的 bug 来源。

#### 2.2.3 语义 B：Windows 上的"贴桌面"

**方案 A：`SetParent` 到 WorkerW（Wallpaper Engine / Lively 的做法）——不采用**

经典配方：`FindWindowW("Progman")` → `SendMessageTimeoutW(progman, 0x052C, 0xD, 0x1, ...)` 逼 Explorer 生成 WorkerW → `EnumWindows` 找含 `SHELLDLL_DefView` 子窗口的那个 → 取它的同级下一个 `WorkerW` → `SetParent`。

**否决理由（第 1 条是决定性的）：**

1. **输入被废掉——致命。** `SetParent` 后窗口变成 `WS_CHILD`，脱离顶层激活链，键盘焦点要靠 `AttachThreadInput` 挂到 Explorer 输入队列才可能拿到，IME 候选框定位基本没救。Wallpaper Engine 的壁纸是**只读**的，Rainmeter 皮肤只处理鼠标。**一个必须打字的便笺不能用这个方案。**
2. **24H2 起结构变了。** Rainmeter 源码 `Library/System.cpp` 里的注释原文：*"So if we're on 24H2+, we should be using the shell window (Progman) instead of WorkerW."*，判定方式是 `GetProcAddress(GetModuleHandle(L"user32"), "GetCurrentMonitorTopologyId") != nullptr`，注释写明该导出 *"should be present only on Windows 11 build 10.0.26100.2454"*。这条路现在需要**版本嗅探 + 两套分支**。
3. Explorer 崩溃/重启后 WorkerW 被销毁，必须监听 `RegisterWindowMessage("TaskbarCreated")` 重新 attach。
4. 坐标变成父窗口客户区相对坐标；每显示器 DPI 变化时 `WM_DPICHANGED` 送达不可靠。
5. 任务栏缩略图、Alt+Tab、Aero Peek 全部消失。
6. 跨进程 `SetParent` 到 shell 窗口，部分企业 EDR 判为注入。

**方案 B（采用）：z-order 沉底 + 显示桌面 z-order 探针**

窗口始终是正常顶层窗口，不 `SetParent`。核心是三段：

**(1) 排除出 Alt+Tab 和任务栏**（这条是文档保证的）：

```rust
let ex = GetWindowLongPtrW(hwnd, GWL_EXSTYLE);
SetWindowLongPtrW(hwnd, GWL_EXSTYLE, ex | WS_EX_TOOLWINDOW.0 as isize);
// 注意：不要加 WS_EX_NOACTIVATE，它会让窗口永远拿不到键盘焦点。
// 只有未来的"纯展示挂件"（日历、天气）才加。
```

**(2) 沉底，且必须周期性重放。** 这是初稿漏掉的关键点：`HWND_BOTTOM` **不是一次性设置**，是一个会被打破的瞬时状态——用户点击便笺时系统会自动把它激活并提到 z-order 顶部，其它程序调 `SetWindowPos` 也会把你顶掉。Rainmeter 为此有一个 z-position 重放定时器。

```rust
const ZPOS_FLAGS: SET_WINDOW_POS_FLAGS =
    SWP_NOMOVE | SWP_NOSIZE | SWP_NOOWNERZORDER | SWP_NOACTIVATE | SWP_NOSENDCHANGING;
// ↑ 与 Rainmeter Skin.cpp 的 ZPOS_FLAGS 定义逐位一致

SetWindowPos(hwnd, Some(HWND_BOTTOM), 0,0,0,0, ZPOS_FLAGS)?;
```

**(3) 用 z-order 探针检测"显示桌面"，不要用前台窗口类名。** 初稿写的"取前台窗口类名，若是 WorkerW/Progman 就认为桌面被显示"是不可靠的近似。Rainmeter 实际的判定（`System::CheckDesktopState`）是一个 z-order 探针：

```rust
// 我们注册一个 0×0 的隐藏顶层探针窗口，类名 "BianfaZProbe"。
// FindWindowExW(None, Some(host), ...) 在 z-order 中「host 之后」= host 之下 搜索。
// 找到探针 ⇒ 桌面宿主窗口已被提到探针之上 ⇒ "显示桌面"正在生效。
unsafe fn is_show_desktop(host: HWND) -> bool {
    if host.is_invalid() || !IsWindowVisible(host).as_bool() { return false; }
    FindWindowExW(None, Some(host), w!("BianfaZProbe"), PCWSTR::null()).is_ok()
}

// host 的获取：24H2+ 直接用 Progman(GetShellWindow())；之前版本找宿主 SHELLDLL_DefView 的 WorkerW
fn desktop_icons_host() -> HWND {
    static IS_24H2: OnceLock<bool> = OnceLock::new();
    let is_24h2 = *IS_24H2.get_or_init(|| unsafe {
        GetProcAddress(GetModuleHandleW(w!("user32")).unwrap(),
                       s!("GetCurrentMonitorTopologyId")).is_some()
    });
    if is_24h2 { unsafe { GetShellWindow() } } else { find_workerw_hosting_defview() }
}
```

hook 注册（参数与 Rainmeter 完全一致，已核实）：

```rust
SetWinEventHook(EVENT_SYSTEM_FOREGROUND, EVENT_SYSTEM_FOREGROUND,
                None, Some(on_foreground), 0, 0,
                WINEVENT_OUTOFCONTEXT | WINEVENT_SKIPOWNPROCESS);
```

回调里带重试——Rainmeter 的循环是 `while (loop < 5 && !CheckDesktopState(hwnd)) { Sleep(2); ++loop; }`，即 **最多 5 次 × 2 ms**，用来吃掉 24H2 显示桌面动画的时序竞争。`SetWinEventHook` 要求调用线程有消息循环并在该线程注册；Tauri 主线程满足条件，**必须在 `setup()` 里、主线程注册**。

**(4) 状态机（初稿完全没有，实现时会卡在这里）：**

| 当前状态 | 触发 | 动作 |
|---|---|---|
| `Docked`（贴桌面静默） | 用户点击便笺 → 系统自动激活提前 | **不对抗**，进 `Editing` |
| `Editing` | `WindowEvent::Focused(false)` | 防抖 200 ms 后 `SetWindowPos(HWND_BOTTOM)`，回 `Docked` |
| `Docked` / `Editing` | 探针判定 show-desktop = true | 提到 topmost band 底部，进 `ShowDesktop` |
| `ShowDesktop` | 探针判定 false | 回 `Docked`（重放 `HWND_BOTTOM`） |
| 任意 | 每 2 s 定时器 | 若状态为 `Docked` 且当前 z-order 已被顶起，重放 `HWND_BOTTOM` |

进入 `ShowDesktop` 时，直接 `HWND_TOPMOST` 是可行的简化；Rainmeter 更精细的做法是插到**topmost band 中最靠后的那个窗口之后**（`GetBackmostTopWindow()`），这样不会盖住用户真正的置顶窗口。我们只有一个 App，v1 用 `HWND_TOPMOST`，若用户反馈"贴桌面便笺盖住了我的置顶播放器"再升级到 backmost 插入。

**两方案对比：**

| | 方案 A `SetParent` | **方案 B z-order + 探针** |
|---|---|---|
| 能打字 / IME | 基本不能 | ✅ 完全正常 |
| 24H2+ 兼容 | 需版本嗅探双分支，仍不稳 | 只有 `desktop_icons_host()` 需要嗅探，判定逻辑不变 |
| Explorer 重启 | 必须重新 attach | 只需重取 host 句柄 |
| 多显示器 / DPI | 坐标自己换算，易错 | ✅ 系统托管 |
| Win+D 保持可见 | ✅ 天然 | ✅ 探针补偿，有 1–2 帧闪烁 |
| 真正在图标之下 | ✅ | ❌ 在图标之上、普通窗口之下 |
| 代码量 | ~400 行 + 长期维护 | ~180 行（含状态机与重放定时器） |

**决策：方案 B 作为"贴桌面"默认实现。方案 A 只在未来做"只读壁纸型便笺墙"时作为 feature flag 引入。**

#### 2.2.4 语义 B：macOS 上的"贴桌面"

macOS 有正牌 API，比 Windows 干净得多。窗口层级在**运行时**取，不要硬编码：

```rust
#[link(name = "CoreGraphics", kind = "framework")]
unsafe extern "C" { fn CGWindowLevelForKey(key: i32) -> i32; }

const K_DESKTOP_ICON: i32 = 18;  // kCGDesktopIconWindowLevelKey

let level = unsafe { CGWindowLevelForKey(K_DESKTOP_ICON) } as isize + 1;
apply(&win, level, CAN_JOIN_ALL_SPACES | STATIONARY | IGNORES_CYCLE)?;
```

`kCGDesktopIconWindowLevelKey = 18` 已对照 `CGWindowLevel.h` 核实。实际数值约为 `-2147483602`（`INT_MIN + 常量偏移`），但**这个数值本身不要写进代码**——Apple 从未承诺它稳定，第一次跑起来时 `dbg!` 打印一次记录到文档即可。

- `STATIONARY` 让 Mission Control / Exposé 不扫走它；macOS Sonoma 起"点击壁纸显示桌面"会把普通窗口滑出屏幕，带 `STATIONARY` 的窗口不受影响——**这正好对应 Windows 的 Win+D 需求，且是系统原生行为，零 hack**。macOS 侧的实现工作量只有 Windows 的 1/5。
- **Stage Manager**：带 `CAN_JOIN_ALL_SPACES | STATIONARY` 的窗口不参与分组，表现像桌面挂件。这是我们要的。
- **风险点（必须实测，不要假设）**：level 低于 normal(0) 的窗口能否可靠成为 key window 接受键盘输入，取决于点击命中测试落在我们窗口还是 Finder 的桌面视图上。**验证任务：macOS 26.3+ 上实测 点击 → 光标是否出现 → 中文 IME 候选框定位是否正确。** 不通过时的降级方案已定：贴桌面模式下窗口只读，`mouseDown` 时把 level 临时提到 `LEVEL_NORMAL(0)` 进入编辑，`WindowEvent::Focused(false)` 后放回。这个降级路径要在 v1 里就写好开关，不要等实测失败再补。

#### 2.2.5 语义 C：AppBar —— 不做

`SHAppBarMessage(ABM_NEW / ABM_SETPOS)` 可让窗口像任务栏一样占住屏幕一边、挤开最大化窗口。macOS 无对等能力（`NSScreen.visibleFrame` 只能骗，做不到真正预留）。**决定不做**：跨端不对称，且和任务栏自动隐藏、多显示器组合出一堆边缘 case。想要"侧边栏"就做一个普通的置顶窄窗口。

### 2.3 其它窗口能力

**无边框 + 自绘标题栏。** `tauri.conf.json` 里 `"decorations": false`，HTML 上 `data-tauri-drag-region`。

> **初稿这里有两条已过时的"坑"，已删除并更正**（对照 `crates/tauri/src/window/scripts/drag.js` 核实）：
> - ~~"拖拽区域不能覆盖 contenteditable"~~ —— Tauri v2 的 drag.js **已内置排除**：`contenteditable`（除非显式 `="false"`）、`tabindex`（除 `-1`）、`CLICKABLE_TAGS = {A, BUTTON, INPUT, SELECT, TEXTAREA, LABEL, SUMMARY}`、以及 `role` 为 button/link/menuitem/tab/checkbox/radio/switch/option 的元素，全部不触发拖窗口。
> - ~~"双击标题栏最大化要自己监听 dblclick"~~ —— **已内置**，Windows/Linux 双击立即最大化，macOS 延迟到 mouseup 且移动光标可取消。

真正要做的决策是：`data-tauri-drag-region` 支持三个值——bare/`"true"`（只有直接点击本元素才拖）、`"deep"`（整个子树都拖）、`"false"`（本元素及祖先都禁止拖）。**便笺 header 用 bare**（不是 `deep`），编辑区不需要额外处理。另外**便笺应该禁用最大化**（`"maximizable": false`），一张最大化的便笺没有意义，同时也顺手规避了双击行为。Windows 上无边框窗口的边缘拉伸自 Tauri 2 起由原生处理（PR #9862），不需要 JS hack。

**圆角与材质。**

| | Windows 11 | macOS |
|---|---|---|
| 圆角 | `DwmSetWindowAttribute(hwnd, 33 /*DWMWA_WINDOW_CORNER_PREFERENCE*/, &2u32 /*DWMWCP_ROUND*/ as *const _ as _, 4)` | 无边框默认直角，用 CSS `border-radius` + `"transparent": true` |
| 材质 | `window-vibrancy` 0.8.0 的 `apply_mica()` / `apply_acrylic()` | `apply_vibrancy(NSVisualEffectMaterial::HudWindow)` |

**决策：便笺窗口不用 Mica/Acrylic/Vibrancy。** 便笺是实色纸片（黄/粉/蓝），毛玻璃会让文字对比度崩掉；Windows 上 acrylic 与圆角有已知冲突。材质只用在 **AI 侧边面板** 和 **便笺列表窗口**。

**每张便笺独立窗口。** 选独立 `WebviewWindow`，这是复刻原版体验的前提。工程约束（对 1–3 人团队做了减法）：

1. **v1 不做"窗口池"抽象。** 初稿的"池大小 8 + 硬上限 15 + CI 性能回归门禁"对 1–3 人团队是过度设计，予以推翻。v1 只做两件事：**懒创建**（`is_open=1` 的便笺才建窗口）、**关闭即 `hide()` 不 `close()`**（Webview 创建 150–400 ms，用户能感知复用与否）。这本质就是池，但不需要池这个抽象和它的生命周期 bug。
2. **软上限 20 + 硬上限 40。** 打开第 21 张时提示"已打开较多便笺，可能影响性能"，第 41 张拒绝并引导用列表窗口。两个数字都做成设置项。
3. **后台降内存（Windows）**：失焦超过 60 s 的便笺，通过 `webview.with_webview(|w| { let ctrl = w.controller(); /* cast ICoreWebView2_19, SetMemoryUsageTargetLevel(LOW) */ })` 降级。底层能力已在 wry 中确认存在（`WebViewExtWindows::set_memory_usage_level(MemoryUsageLevel)`，wry PR #1090），但 Tauri 未直接转发，需自己经 `PlatformWebview::controller()` 拿 `ICoreWebView2Controller` 再 `cast::<ICoreWebView2_19>()`。macOS 无对等 API。
4. **发版前手工实测**（不是 CI 门禁）：1 / 10 / 30 张便笺在 Windows 与 macOS 上的 RSS，记进 `docs/perf-baseline.md`。macOS 的 WKWebView 每实例一个 WebContent 进程，增量显著高于 Windows，这是两端唯一可能出现"数量级差异"的地方。

**窗口位置持久化。** 不用 `tauri-plugin-window-state`：已核实其实现是 `HashMap<String /*window label*/, WindowState>` 序列化进 `.window-state.json`，**没有任何 stale label 清理逻辑**；我们的 label 是便笺 UUID，会随便笺创建删除无限增长。（该插件确实提供 `map_label` 回调，但把所有便笺映射成一个 key 反而丢掉了我们需要的 per-note 位置。）自己在本地 SQLite 存：

```sql
CREATE TABLE note_window_state (
  note_id     TEXT PRIMARY KEY,
  x INTEGER, y INTEGER, w INTEGER, h INTEGER,   -- 全部存 PhysicalPosition/PhysicalSize
  monitor_key TEXT,                             -- hash(name + 分辨率 + 该显示器在虚拟桌面中的原点)
  scale       REAL,                             -- 保存时的 DPI 缩放因子
  z_mode      INTEGER NOT NULL DEFAULT 0,       -- 0 普通 / 1 置顶 / 2 贴桌面
  collapsed   INTEGER NOT NULL DEFAULT 0,
  is_open     INTEGER NOT NULL DEFAULT 1,
  updated_at  INTEGER NOT NULL
);
```

四条硬规则：

- **坐标只存 Physical，不存 Logical。** 混用是多显示器混合 DPI 场景下 90% bug 的来源。
- **坐标不上云。** 不同电脑显示器不同，同步过去只会错位。云端只同步 `z_mode`、`collapsed` 这类语义属性。
- **恢复时必须做屏幕内校验。** 遍历 `app.available_monitors()`，若保存矩形的中心点不落在任何显示器工作区内，夹到主显示器并居中——否则用户拔掉外接屏后便笺会"消失"在 (-1920, 300)。
- **监听 `WindowEvent::ScaleFactorChanged`**（Tauri 源码注明触发于：改分辨率、改缩放比、窗口移到不同缩放的显示器），按新 `scale_factor` 重算尺寸再写回。

**系统托盘。** Tauri v2 已把托盘并入 core：`tauri::tray::TrayIconBuilder`（已核实存在于 `crates/tauri/src/tray/mod.rs`），需开 `tray-icon` feature。菜单：新建便笺 / 显示全部 / 隐藏全部 / 便笺列表 / 设置 / 退出。macOS 上必须提供 template image（黑白 + alpha）才能跟随深浅色。

**开机自启。** `tauri-plugin-autostart` 2.5.1，两端都要改：

- **Windows**：插件默认写 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`，够用且不需要管理员权限。启动参数加 `--autostart`，据此静默启动（不弹主窗口，只恢复 `is_open=1` 的便笺）。**不用**启动文件夹（用户易误删、路径含空格易错），**不用**任务计划程序（我们不需要延迟启动或提权，且它在"设置→启动项"里显示为不可关闭）。若将来上 Microsoft Store，MSIX 不允许写 Run 键，必须换成清单里的 `windows.startupTask` 扩展。
- **macOS**：插件的 `MacosLauncher::LaunchAgent` 往 `~/Library/LaunchAgents/` 写 plist——**不要用**。Ventura 起系统把这类 plist 显示成"允许在后台"的匿名条目，用户在"登录项"里看不到 App 名字。正确做法是 `SMAppService.mainApp.register()`（macOS 13+），前提是 App 已签名 + 公证。**注意 `smappservice-rs` 只有 0.1.3（2025-05-27，单人维护、0.1.x 未定型）**——它只是 3 个 Objective-C 调用的薄包装，建议直接抄进 `platform/macos.rs` 用 `msg_send!` 自己写，不引入这个依赖，避免一个 20 行的功能挂在一个可能停更的 crate 上。

**全局快捷键。** `tauri-plugin-global-shortcut` 2.3.2。默认 `Ctrl/Cmd+Alt+N` 新建、`Ctrl/Cmd+Alt+A` 唤起 AI 面板。注册失败（被占用）时插件返回 `Err` 但不会主动告诉用户——必须在设置页显式显示"该快捷键已被占用"并允许重绑。macOS 上这类热键走 Carbon `RegisterEventHotKey`，**不需要辅助功能权限**；不要为了热键用 `CGEventTap`，那会弹权限框且上不了 Mac App Store。

**单实例。** `tauri-plugin-single-instance` 2.4.4，必须**第一个**注册到 builder 链，否则第二实例会先跑一遍别的插件初始化。回调里拿第二实例的 argv，处理 `bianfa://note/<uuid>` 深链。

#### 2.4.2 macOS

Apple Developer Program $99/年 → `Developer ID Application` 证书 → Hardened Runtime → `notarytool` 公证 → `stapler` 装订。Tauri 在设置环境变量后自动跑完整条链：

```bash
APPLE_SIGNING_IDENTITY="Developer ID Application: XXX (TEAMID)"
APPLE_API_KEY=<Key ID>          # App Store Connect API Key，不要用 app-specific password
APPLE_API_ISSUER=<Issuer UUID>
APPLE_API_KEY_PATH=./AuthKey_XXX.p8
pnpm tauri build --target universal-apple-darwin
```

用 API Key 而非 `APPLE_ID` + `APPLE_PASSWORD`，因为后者绑 2FA、密码轮换会静默打断 CI。

**分发格式选 `.dmg`（Tauri 默认），不做 `.pkg`。** 初稿把理由写成"macOS 26.3 Tahoe 上已公证的 `.pkg` 被 Gatekeeper 拒绝"——**这个论据不成立，已推翻**。我核实了 Apple 开发者论坛 thread 817887：现象属实（macOS 26.3 build 25D125，`spctl -a --type install` 拒绝、双击只给"移到废纸篓"），但 Apple DTS 工程师 Quinn 的判断是提问者自己的签名链断了（`productbuild` 输出了 `Warning: unable to build chain to self-signed root`），**并非 Gatekeeper 对 `.pkg` 的普遍回归**。

**维持 `.dmg` 结论，换成成立的理由**：(1) `.dmg` 是 Tauri 默认产物，零额外配置；(2) `.pkg` 需要**第二张证书**（`Developer ID Installer`，与 Application 证书不同），多一条独立的过期/续期/链完整性失败路径——thread 817887 恰好是这条路径出问题的实例；(3) updater 要的 `.app.tar.gz` 无论如何都要单独产出，`.pkg` 不能复用；(4) 我们没有安装脚本、没有系统级组件，`.pkg` 唯一的能力（preinstall/postinstall）用不上。

#### 2.4.3 自动更新

`tauri-plugin-updater` 2.11.0（2026-08-31），Ed25519 / minisign 签名。

```bash
pnpm tauri signer generate -w ~/.tauri/bianfa.key
# 私钥 → GitHub Secret: TAURI_SIGNING_PRIVATE_KEY / TAURI_SIGNING_PRIVATE_KEY_PASSWORD
# 公钥 → tauri.conf.json > plugins.updater.pubkey（编译进二进制）
```

**这是全项目唯一的不可恢复单点故障：公钥被编译进已发出去的二进制，私钥丢了就永远无法给存量用户推更新，只能让他们手动重装。** 私钥必须备份在至少两处离线介质 + 一个密码管理器，并写进交接文档。这件事在第一次发版前做，不要拖。

**更新服务器：Cloudflare R2 存二进制 + Worker 出 `latest.json`，不放 Hostinger VPS。** 理由是带宽：一次全量更新推给 1 万用户 ≈ 100 GB 出站，R2 出站免费，VPS 的带宽配额会被打爆并连累同步服务。endpoint 配 `https://update.<domain>/{{target}}/{{arch}}/{{current_version}}`：

```json
{ "version": "1.4.2", "pub_date": "2026-09-04T10:00:00Z", "notes": "...",
  "platforms": {
    "windows-x86_64": { "signature": "<minisign>", "url": "https://cdn.../bianfa_1.4.2_x64-setup.exe" },
    "darwin-aarch64": { "signature": "<minisign>", "url": "https://cdn.../bianfa_1.4.2_aarch64.app.tar.gz" }
  }}
```

Worker 里做灰度：按 `installId` 哈希取模决定放不放新版本，出问题改一个 KV 值即可全量回滚。

#### 2.4.4 安装包格式与 WebView2 安装模式

初稿把 `webviewInstallMode` 的体积数字写反了。以下四个值直接摘自 `tauri-utils/src/config.rs` 的 doc comment：

| 值 | 体积增量 | 说明 |
|---|---|---|
| `downloadBootstrapper`（**默认，采用**） | 无增量 | 联网下载 bootstrapper。**Tauri 源码注明：updater bundle 恒定使用此模式**，无论主配置怎么设 |
| `embedBootstrapper` | **+1.8 MB** | 内嵌 bootstrapper，仍需联网 |
| `offlineInstaller` | **+127 MB** | 内嵌离线安装包，**完全不需要联网**——企业离线包用这个 |
| `fixedRuntime` | **+180 MB** | 内嵌固定版 WebView2 运行时 |

- **Windows：NSIS（`.exe`）为主。** 支持 per-user 安装（无需管理员）、支持 arm64、体积小、updater 直接支持。
- **MSI（WiX v3）**：只在企业客户明确要求 GPO 部署时出，不当主渠道。
- **macOS：`.dmg` 主发布 + `.app.tar.gz` 供 updater。** `universal-apple-darwin` 出通用二进制，不分两个下载链接。

#### 2.4.5 应用商店会不会杀掉"贴桌面"

| | Microsoft Store | Mac App Store |
|---|---|---|
| 沙箱是否阻断窗口层级 | 否。MSIX + `runFullTrust` 仍可调 Win32；Lively Wallpaper 已在 Store 上架 | 否。`NSWindow.level` / `collectionBehavior` 不属于沙箱受限操作 |
| 会被杀掉的能力 | 注册表 Run 自启（改 `windows.startupTask`）；updater 必须关（Store 接管）；**Tauri 无 MSIX 打包目标，要自己包一层** | LaunchAgent 自启（改 `SMAppService`，MAS 允许）；updater 必须关；`CGEventTap` 不可用（我们用 Carbon 热键，不受影响）；需额外沙箱 entitlements |
| 结论 | 可上，需第二套 build 配置 | 可上，需第二套 build 配置 + 沙箱适配 |

**发布策略：v1 只做官网直接下载（两端）。** 商店的收益是发现性和"官方感"，成本是第二套构建配置 + 审核周期，1–3 人团队 v1 阶段不划算。v1.x 稳定后先上 Microsoft Store（改动小），Mac App Store 放到 v2 再评估。
