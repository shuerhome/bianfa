# 第 13 章 · 信息架构与逐屏布局

> 逐屏线框图、导航模型、交互规范

---

> 本章视觉基线为 **「淡彩纸 Tinted Paper」**（见《设计系统规范》§1–§8），强制吸收其三项光学移植 —— ① 墨色继承纸色相；② 接触阴影层（blur ≤ 1px）+ 大模糊层带负 spread、阴影色 `rgba(24,24,20)` 非纯黑；③ 聚焦窗口的本色辉光。
>
> 本章只给**布局与交互**的具体值。所有颜色/字号/间距/圆角/阴影/动效一律引用基准的 L2 语义 token（`--c-* --fs-* --lh-* --sp-* --r-* --sh-* --dur-* --z-*`）；本章不定义任何新的 L1/L2，确需的实例变量走 L3（`--note-*`）并注明所引用的 L2。

| 数字 | 所有时间戳、字数、计数、额度一律 `font-variant-numeric:tabular-nums`——列表里数字跳动会直接破坏静态感 |

**断点用 Container Query，不用 Media Query。** 多窗口应用里 `@media` 量的是屏幕，毫无意义。根容器 `container: note / size`（同时量宽与高，因为便笺的行数由高决定）：

| 名 | 宽度 | 出现在 |
|---|---|---|
| `xs` | ≤ 199px | 便笺窗 compact 态（用户手动拖到最小） |
| `sm` | 200–379 | 便笺窗常规（默认 220×220） |
| `md` | 380–719 | 便笺窗宽态 / 主窗单栏 / 设置窄态 |
| `lg` | 720–1079 | 主窗侧栏 + 内容 |
| `xl` | ≥ 1080 | 主窗三栏 / 便笺墙 |

便笺窗内部另有基准 §5.6 的细分阈值，直接叠加在上表之上，不另起一套命名：`≥300px` padding 提到 16/18、标题 15→17px；`≥320px 高` 顶栏 28→32px 且右侧长出 meta；`≥380px` 底部工具栏转常驻并长出 Markdown 组；`≥420px 高` 首行标题 `position:sticky; top:28px`；`≥640px` 右侧推出 320px AI 面板；`≥700px 高` 正文 14→15px、`padding-inline` 提到 32px。**顶栏高度不随窗口线性缩放**（只有 ≥320px 高时一次性 28→32），window chrome 是 OS 级一致性。

## 1. 导航模型：窗口是空间，不是栈

桌面多窗口没有「返回」，因为**没有前进过**。bianfa 的导航模型是三条规则：

1. **四类窗口，两种基数。** 便笺窗（多实例，无上限）、主窗（单例）、设置窗（单例）、登录窗（单例、临时）。**不做独立 AI 窗**——它会变成第五个要管理的东西。
2. **命令面板是唯一的全局跳转器。** `Cmd/Ctrl+K` 在任何窗口都能唤起，能到达任何东西（便笺、笔记本、标签、设置项、AI 动作）。它替代了侧边栏导航、面包屑、返回键三者。
3. **层级只存在于主窗内部，且用「范围条」而非面包屑表达。** 主窗顶部一行可点击的范围 chip：`全部便笺 › 工作 › #设计 › 搜索"评审"`，点任一段即回退到该段，点 × 清除该段。这是「返回」在空间型界面里的正确形态——**它是过滤器栈，不是页面栈**。

**关窗语义必须明确且唯一：`Cmd/Ctrl+W` = 收起，永不删除。** 删除只有一个入口（更多菜单 / `Cmd+Shift+Delete`）且必然进回收站。这条不容许有第二种解释。

## 2. 单张便笺窗口（核心）

### 2.1 尺寸与结构

**最小 `180×140`，默认新建 `220×220`**（两者都随 `--ui-scale` 90/100/115/130% 一起缩放，避免 130% 下正文只剩 4 行）。记忆每张便笺自己的尺寸与位置。最大化不铺满屏幕，钳制在 `min(720, 屏宽×0.5) × min(900, 屏高×0.8)`——便笺全屏是概念错误。

内容区 `padding: 30px 8px 12px 14px`（右侧 8px 即滚动条槽，内容宽恒定 198px），底部 44px 渐隐遮罩避免硬切文字。**220×220 的容量账**：可用宽 198px ≈ 14.1 中文字/行，可用高 178px ≈ 7.47 行，即「首行标题 15px + 6.7 行 × 14 字 ≈ 108 汉字」，对照 Windows 便笺同尺寸 75–80 字（12px），**密度 +35% 且字号更大**。常驻 chrome = 28 + 12 + 2 = 42px，在 60px 地板之下。

### 2.2 两条工具栏必须分开讲（本章此前最大的歧义源）

便笺窗里有**两条**独立的工具栏，触发条件、位置、职责完全不同，任何一条都不许写成「hover 就出来」：

| | **操作工具栏**（底部） | **格式工具栏**（浮动） |
|---|---|---|
| 管什么 | 便笺这个**对象**：换色 / 置顶 / AI / 更多 | 选中的**文字**：粗斜下划、待办、列表、AI 改写 |
| 位置 | `position:absolute; bottom:0`，高 `--note-toolbar-h` 32px，`--z-float` | CSS Anchor Positioning 锚在选区上方 8px，`--z-float` |
| 触发 | **双条件**：`窗口已聚焦 AND (鼠标在窗内 OR 有文本选区 OR 光标在编辑器内且 3s 内有输入)` | **选区驱动**：选区长度 ≥ 1 字符，`mouseup` / 键盘选择停止后 `--dur-2` 出现 |
| 隐藏 | 失焦 200ms 后；或鼠标离开且无选区 800ms 后 | 选区清空即刻；`Esc` 关闭 |
| ≥380px 时 | 转为**常驻**（`opacity:1; position:static`，高 40px，`border-top:1px var(--note-rule)`），撤掉渐隐遮罩，并在右半区并入 Markdown 组 `B • ☐ </> 🔗` | 降级：常驻条已含格式项，浮动条只保留 `✦AI` + 二级项，不再重复出 `B I U S` |

`聚焦 AND 悬停`两个条件都要——这一条直接解掉「鼠标横扫桌面触发 15 次淡入淡出」的波浪效应，800ms 延迟防边缘闪烁。**格式条不受这条约束**：有选区就意味着窗口必然已聚焦，它天然满足双条件的第一项。

**顶栏 28px 常驻，不做 hover-only。** 评审对 hover-only chrome 的两条批评成立：15 个窗口鼠标扫过会产生波浪；工具栏浮起会盖住最底部 1.5 行，而便笺是「往下追加」的写作模式。但常驻 ≠ 全显示：静息态顶栏只画两个像素级元素——左侧 14px 颜色点（`opacity:.55`）、右侧 6px 同步点；`⊙ ⋯` 在 `:hover / :focus-within` 时 `--dur-2` 淡入，**位置预留 56px 固定不变，零 layout shift**。顶栏整条 `data-tauri-drag-region`（按钮 `no-drag`），无标题文字（第一行即标题），无分隔线。

底部操作工具栏用 `absolute` 覆盖、不参与布局；**只有当内容已滚到底时才给正文加 `padding-bottom:32px`**，这样它出现时永远不会盖住正在写的那一行。220px 宽只放 4 个 26×26：`◉换色 ⇧置顶 ✦AI ⋯更多`。

**触屏分支（`pointer:coarse`）**：无 hover，顶栏常驻 `⋯`，长按 500ms 唤出全部操作的 sheet；resize 手柄常驻 `opacity:.5`。

### 2.3 格式工具栏细则

- 定位：CSS Anchor Positioning（Safari 26.0 起支持，26.2 补齐 `position-try-fallback` 的 `flip-x/flip-y`），锚在选区上方 `8px`，空间不足自动翻转到下方。**不用 JS 算坐标。**
- 尺寸：高 `32px`（= `--h-ctl-lg`），图标 16px，项间距 `--sp-1`(2px)，`--r-md` 圆角，`--c-overlay` 底 + `--bw-hair` `--c-border-subtle` + `--sh-2`。**格式条是中性表面，不染色**——它浮在彩纸上，染色会和纸面糊在一起。
- `xs` 容器（≤199px）下折叠为 `B I ≔ ⋯ ✦` 五项。
- `Cmd/Ctrl+E` 临时唤起常驻条（未到 380px 时）：贴底 32px，内容区 `padding-bottom` 相应 `+32px`；再按一次收起。**不再提供「常驻格式条」设置项**——380px 断点已经自动兑现它，默认态解决得了的问题不许外包给设置。

### 2.5 三态

- **空状态（新建）**：光标已在内容区，第一行显示占位「写点什么…」（`--note-ink2`，不用 opacity 压色），**不画插图、不给引导**。新建便笺唯一正确的状态是「已经可以打字」。
- **加载态**：便笺从本地 SQLite 读，正常 < 16ms，**不做 skeleton**。仅当 > 300ms（云端冷取）才显示三条骨架行：条高 `11px`（对应 14px 正文），行距同正文 23.8px，`--r-xs`，底 `--c-surface-3`，动画 `1.2s var(--ease-in-out) infinite alternate` 的 `opacity .55→1`。**不用 shimmer 渐变位移**——它会强制创建合成层，直接违反「静止态零 GPU 成本」红线；reduced-motion 下改静态。
- **错误态**：内容区不变（本地副本永远可读），顶栏同步点转冲突态 + 底部出现一行 `--fs-2xs` 内联条：`离线中，改动已存在本机 · 重试`。**绝不弹窗、绝不阻止输入。**

### 2.6 键盘

`Cmd/Ctrl+N` 或 `Cmd/Ctrl+Shift+N` 新建（两个组合都注册到同一动作，见 §12 反向裁定）· `Cmd/Ctrl+W` 收起 · `Cmd/Ctrl+P` 置顶 · **`Cmd/Ctrl+1…9` + `Cmd/Ctrl+0` 换色（10 色）** · `Cmd/Ctrl+K` 命令面板 · `Cmd/Ctrl+/` AI 抽屉 · `Cmd/Ctrl+E` 格式条 · `Cmd/Ctrl+Shift+L` 待办列表 · `Ctrl+Tab` 在便笺窗之间循环（带缩略图 HUD）。

### 3.1 布局决策（给结论）

**等高卡片网格，不做瀑布流。** 瀑布流在三处输赢：① 视线路径是 Z 型断裂的，扫 128 张卡片时定位成本显著上升；② 与虚拟滚动天然冲突——高度不定意味着必须逐项测量，1 万条时首屏计算量爆炸；③ 便笺内容长度方差极大（3 字到 3000 字），瀑布流会产出高度比 1:40 的畸形列。

卡片规格：`min-width 208px`，`grid-template-columns: repeat(auto-fill, minmax(208px, 1fr))`，`gap: var(--sp-5)`(12)，**固定高 `180px`**，`--r-md` 圆角，`--bw-hair` `--c-border-subtle` 描边 + `--sh-1`，hover 抬到 `--sh-2`。

卡片内（padding 12，左侧让出 3px 色条 → `padding-left: 12px`，色条 `position:absolute; left:0; width:3px; inset-block:0; background: var(--p-<color>-dot)`）：

```
标题  --fs-lg 15 × --lh-cjk 1.62 = 24.3px   1 行   --c-text-1 --fw-medium
gap   --sp-2 4
正文  --fs-sm 13 × --lh-cjk 1.62 = 21.1px   5 行   --c-text-2   → 105
gap   --sp-3 6
元信息 8px 色点 + 标签 chip + 相对时间  --fs-2xs 11 × 1.45 ≈ 16   --c-text-3
合计  24 + 24.3 + 4 + 105 + 6 + 16 ≈ 179 → 固定 180px
```

正文超出用 `-webkit-line-clamp:5` 截断 + 底部 24px 渐隐（渐隐色 = 卡片底色，不是纸色）。列表视图行高 `44px`，单行摘要，色条同样 3px。**8px 色点必带 `aria-label` 颜色名**，颜色不做唯一线索。

### 3.2 筛选 / 排序 / 批量

- **排序**（顶栏 `⇅`）：修改时间 ↓（默认）/ 创建时间 / 标题 / 颜色 / 手动。置顶项永远浮在最前，与排序无关。按颜色排序时用固定色序（石墨 → 玫瑰 → … → 品红，即快捷键序）。
- **筛选**收进范围条，不做独立面板。侧栏点击 = 加一段范围；`Alt+点击` = 多选同级（`#设计 或 #后端`）。
- **多选**：`Cmd/Ctrl+点击` 加减、`Shift+点击` 范围、`Cmd/Ctrl+A` 全选、`Space` Quick Look 预览、方向键移动焦点 + `Shift+方向键` 扩展选区。选中态用 `--c-selected` 底 + 2px `--c-accent` 描边（不靠颜色单载：同时给 `aria-selected` 与左上角 ✓）。
- **批量条**：底部居中悬浮 pill，`52px` 高，`--r-full`，`--c-overlay` + `--sh-3`，`--dur-3 --ease-out` 从 `translateY(16px)+opacity` 升起。删除走「先执行 + 撤销提示」，**不弹确认框**——Toast 带撤销停 `8s`（基准：默认 4s，带撤销 8s），`Cmd/Ctrl+Z` 可撤。

### 3.3 一万张便笺的虚拟滚动

- **TanStack Virtual v3**（2026-05 性能版：10 万项冷挂载 4.5ms，修好了 iOS 惯性滚动与动态高度的向上跳动）。网格模式 `estimateSize: () => 192`（180 + 12），`lanes` = 当前列数，`overscan: 2` 行。
- 因为卡片等高，**走 fixed-size 路径，完全跳过 `measureElement`**。这是 §3.1 决策的直接兑现。
- 数据侧：Rust 只回 `{id, title, excerpt(120字), color, tags[3], mtime}`，单条 ≈ 260B，1 万条 ≈ 2.6MB，可全量驻留内存；正文按需取。`color` 是 10 色枚举名（`graphite|rose|coral|amber|citron|fern|teal|azure|violet|fuchsia`），前端映射到 `--p-*-dot`，**不传 hex**。
- 搜索/筛选在 Rust 侧用 SQLite **FTS5**（中文用 trigram tokenizer，避免分词器歧义），返回 id 数组，前端只做映射。目标：1 万条下键入到首屏更新 **< 80ms**。
- 滚动条右侧叠一条 4px 的时间刻度（月份分隔），滚动时显示浮动日期胶囊（`--r-full`，`--c-overlay` + `--sh-2`，`tabular-nums`）。

### 3.4 三态

- **空（全新用户）**：画布居中，一行 `--fs-2xl`(20) 文案 + 一个 `--h-ctl-lg`(32) 主按钮 + 一行快捷键提示。见 §10。
- **空（筛选无结果）**：`--fs-sm` 文案 + 「清除筛选」文字按钮，**保留侧栏和范围条**（用户要知道自己在哪）。
- **加载**：首屏渲染 12 个卡片骨架（等高，所以骨架和真实布局完全一致，无跳动）。骨架条 10px（对应 13px 文本）/ 11px（14–15px 文本），`opacity .55→1` 呼吸，**不用 shimmer**，`aria-busy="true"`。
- **错误**：顶栏下方 32px 内联横幅，`--c-warning-subtle` 底 + `--c-warning` 图标 + `--c-text-1` 文字（不靠色底单载信息）：`同步失败：连接超时 · 重试 · 查看详情`。列表继续显示本地数据。

## 6. AI 助手面板（给结论）

**结论：形态随宿主变，且只有两种 + 一个容器查询分界。**

| 宿主 | 形态 | 理由 |
|---|---|---|
| 便笺窗口 `< 640px` 宽 | **底部抽屉** | 220px 宽放不下侧栏（剩 60px 无法排版）；独立浮窗会丢失「这张便笺」的上下文，还多一个要管理的窗口 |
| 便笺窗口 `≥ 640px` 宽 | **右侧面板 320px**（基准 §5.6 断点）| 此时正文区仍有 ≥320px 保底行宽，抽屉反而会把正文压成 3 行 |
| 主窗 / 便笺墙 | **右侧栏 340px** | 宽度富裕，且需要同时看列表与结果 |

**AI 面板一律用中性表面，零着色**（`--c-surface-1` / `--c-overlay`，与彩纸之间用 `--bw-hair` `--c-border-subtle` + `--sh-2` 分离）——流式长文在中性灰底上最好读，这是基准 §1 的着色语境表直接规定的。

**独立浮窗方案否决。** 它把「AI 是便笺的一个能力」变成「AI 是另一个应用」，且在多窗口环境里必然出现「浮窗跟着哪张便笺」的归属歧义。

### 6.1 便笺内抽屉

```
┌────────────────────────────────────────┐
│●        便笺内容（被压缩）         · │
│  周五前把设计评审的三份线框发给 Lin   │
├────────────────────────────────────────┤ ← 拖动分隔线 4px
│ ✦ Claude Sonnet 4.5 ▾        ⋯   ✕ │ 32  模型条
├────────────────────────────────────────┤
│ 帮我把这段改写得更正式一些            │ 用户 13px 右对齐气泡
│                                        │
│ 请于本周五前将设计评审所需的三份       │ 输出 14px/1.70
│ 线框图交付至 Lin。▊                    │ ▊=2×17 光标 1.06s
│                                        │
│ ┌────────────────────────────────────┐ │
│ │ ⏹ 停止生成                  esc  │ │ 生成中
│ └────────────────────────────────────┘ │
├────────────────────────────────────────┤
│ ⏎替换  ⇧⏎追加  ⌘R重写  esc丢弃  1.2k │ 32 结果操作条
└────────────────────────────────────────┘
```

- 高度 `min(60% 窗口高, 280px)`，可拖分隔线调整。**窗口高 < 380 时自动临时扩窗到 420，关闭抽屉后回弹到原高度**（记住原值，别丢）。420 这个值不是随手取的：它同时越过基准的「≥420px 高 → 首行标题 sticky」阈值，抽屉打开时标题会自动钉住，用户不会写着写着丢掉上下文。
- **AI 输出字号 = 便笺正文字号 `--fs-md` 14px / `--lh-body` 1.70**。理由是硬的：这段文字最终会被 `⏎` 替换进便笺，字号不一致就等于所见非所得，替换瞬间整段重排。用户气泡用 `--fs-sm` 13px 区分（层级靠字号 + 颜色，不靠字重）。
- **模型选择器**：26px ghost 按钮（便笺窗内 26×26 例外），显示 `供应商图标 + 短名 + ▾`。下拉列表每项两行：`模型名`（`--fs-sm` `--fw-medium`）+ `速度点·成本点·上下文`（`--fs-2xs` `--c-text-3`）。分组：`常用` / `全部`。**不显示模型 ID**，只在设置里显示。
- **流式排版**：首 token 前显示三行骨架（条高 11px，行距同 14px 正文，`opacity .55→1` 1.2s，**不用 shimmer**）。首 token 后骨架消失，逐块 append，**用 `requestAnimationFrame` 批量刷新（每帧最多一次 DOM 写入）**，避免逐 token reflow。Markdown 边流边渲染，未闭合的代码块先按纯文本渲染，闭合后再高亮——**不能因为等闭合就整段不显示**。段间距 `--sp-4`(8)，代码块 `--c-surface-3` 底 + `--sp-5`(12) padding + `--f-mono` + `letter-spacing:0`。
- **流式光标**：`2×17px` 实心块，`1.06s` 闪烁，**仅在生成期间运行**；生成结束或窗口失焦 3s 即停（红线 2）。reduced-motion 下改静止实心块。
- **生成中/中断**：主按钮变「⏹ 停止生成」，`Esc` 同效。已生成部分**保留**，操作条变为 `已停止 · ⏎接受这部分 · ⌘R 继续`。
- **结果处置**：`⏎` 替换选区 / `⇧⏎` 追加到便笺末尾 / `⌘R` 重写（带一个 `重写要求…` 单行输入）/ `Esc` 丢弃。**替换必然可 `Cmd+Z` 一次撤回全部**，这是 AI 功能可信度的地基。
- **斜杠命令**：正文空行输入 `/` 唤起，锚定在光标（CSS Anchor Positioning + `position-try-fallback: flip-block`）。宽 260px，项高 32，最多 7 项可滚，`--z-menu`。默认项：`/续写 /总结 /翻译 /改写 /提取待办 /排版 /解释`。输入非匹配字符两次即自动关闭并还原 `/` 字面量。
- **选中文字浮动 AI 菜单**：即 §2.3 格式浮动条最右的 `✦`。点击展开二级浮层（200px 宽），项为「改写 / 缩短 / 扩写 / 翻译成英文 / 解释 / 问 AI…」。**只在选区 ≥ 4 个字符时才显示 `✦`**，选中两个字问 AI 是误触。
- **token 用量**：结果条最右 `--fs-2xs` `--c-text-3` `tabular-nums`：`1.2k`。悬停显示 `本次 1,243 · 本月 12.4k / 50k`。达 80% 变 `--c-warning` 并加进度条底纹；达 100% 时模型选择器里超额模型置灰 + 一行「本月额度用完，换个模型或升级」。**平时绝不显示进度条**——每天看额度条会让人不敢用。

### 6.2 三态

- **空**：抽屉刚打开显示 4 个建议 chip（基于便笺内容：有待办 →「整理待办」；纯文本 →「总结要点」），每个 `--h-ctl-md`(28) 高，`--r-full`。**不显示「你好，我是 AI 助手」。**
- **加载**：见流式骨架。首 token 超 `4s` 未到 → 骨架下加一行 `--fs-2xs`「模型响应较慢，可换用 …」。
- **错误**：整块替换为 `--c-danger` 左边框（2px）+ `--c-danger-subtle` 底的内联块：`标题（本次请求失败）+ 一行人话原因 + 两个按钮（重试 / 换模型）`。**错误码折叠在「详情」里**，默认不显示 `429`。

## 7. 设置窗口

默认 `840×620`，最小 `680×520`。单例、非模态（用户要一边改一边看便笺）。设置窗是**纯中性、零着色**语境，也是全 app 仅有的两处允许 `backdrop-filter` 的地方之一（另一处是 AI 面板）。

```
┌────────────────────────────────────────────────────────────────┐
│ 设置                                              ⌕ 搜索设置 │ 44
├──────────────┬─────────────────────────────────────────────────┤
│ 200px        │  AI 模型                                        │ --fs-2xl 20
│  账号        │  ─────────────────────────────────────────────  │
│  同步        │  供应商                                    ＋ │
│  团队        │  ┌───────────────────────────────────────────┐ │
│ ▸AI 模型     │  │⣿ Anthropic          ●已连接    ⋯       │ │ 56
│  外观        │  │  sk-ant-••••4f2a  ·  3 个模型可用        │ │
│  快捷键      │  └───────────────────────────────────────────┘ │
│  数据        │  ┌───────────────────────────────────────────┐ │
│  关于        │  │⣿ OpenAI             ⚠ 密钥无效  ⋯       │ │ 56
│              │  └───────────────────────────────────────────┘ │
│              │  已启用的模型（拖动排序，第一个为默认）        │
│              │  ⠿ ● Claude Sonnet 4.5      默认   [切换 ●] │ 44
│              │  ⠿ ● Claude Haiku 4.5              [切换 ●] │ 44
│              │  ⠿ ○ GPT-5.1                       [切换 ○] │ 44
└──────────────┴─────────────────────────────────────────────────┘
```

- **导航**：8 组，扁平不折叠。`md` 容器（< 720）下侧栏塌缩为顶部下拉。顶部「搜索设置」（`Cmd+F`）跨组搜索项标题与关键词，命中项高亮闪烁 2 次（`--dur-3` × 2，reduced-motion 下改为静态 `--c-accent-subtle` 底停留 2s）。
- **账号**：头像 48px + 名/邮箱 + 套餐 + 「退出登录」（次级危险样式，右下角）。
- **同步与冲突**：状态行（`上次同步 2 分钟前 · 12 项待上传`）+「立即同步」+ **冲突列表**。每条冲突一行 52px：便笺标题 + 两个版本的时间与作者 +「并排比较」。比较视图左右分栏、逐段高亮差异、底部三个按钮：`保留我的` / `保留对方` / `合并为两张便笺`（第三项是最安全的默认，冲突解决绝不能只有二选一）。
- **团队**：成员表（头像/名/角色/加入时间/⋯），角色下拉（拥有者/编辑/只读），底部「邀请成员」生成链接 + 有效期。
- **AI 模型管理**：两层。上层「供应商」卡片（增删改 key，key 只显示后 4 位，编辑时整体替换不做部分编辑；右侧 `⋯` = 测试连接 / 编辑 / 删除）。下层「已启用模型」列表，`⠿` 拖柄排序（顺序即选择器里的顺序，第一个为默认），右侧 Switch（track 32×18 `--r-full`，knob 14）。**新增供应商后自动拉取模型列表，失败则手填模型 ID**。
- **外观**（这一组按基准重写过，见 §12）：
  - **主题** 三档：跟随系统 / 浅色 / 深色 → `<html>` 上分别为无属性 / `data-theme="light"` / `data-theme="dark"`。
  - **界面缩放** 四档：`90% / 100% / 115% / 130%` → `--ui-scale`。缩放同时驱动窗口最小尺寸（`180×140 × scale`）与默认新建尺寸（`220×220 × scale`）。**没有独立的「正文字号」设置项**——便笺正文字号地板 14px @100%，字号由缩放统一驱动，避免出现「14px 地板被用户手动调到 13px」的口子。
  - **用图案区分便笺颜色**（开关）：开启后 10 色色点叠加 10 种 4×4px 微纹理。这是色觉障碍补丁，**必做项，不是审美偏好**。
  - **减少透明度**：默认跟随系统（WebKit 未实现 `prefers-reduced-transparency`，由 Rust 侧读系统设置下发 `data-reduce-transparency="1"`）。旁边一行说明：**便笺窗口在任何设置下都不透明**，此开关只影响设置窗与 AI 面板的 `backdrop-filter`。
  - **没有「Tint 等级」，没有「中文字体」自定义**——见 §12 的删除理由。
  - **每一项右侧都有一个 `160×120` 的实时预览便笺**，不是文字描述。预览用真的 `.note` 组件（容器查询让它自动进 compact 态），改主题/缩放/图案立刻可见。
- **快捷键**：两列表格（动作 / 组合键），点击录制，冲突时该行底 `--c-warning-subtle` + 一行 `--c-text-1` 文字提示占用者（不靠色底单载）。「恢复默认」在页脚。换色一组固定展示为 `Ctrl/Cmd+1…9` + `Ctrl/Cmd+0`，10 行，每行带色点与色名。
- **数据**：导出（Markdown 文件夹 / JSON / 单文件 HTML）、导入（Windows 便笺 .sqlite、Apple 备忘录、Markdown 文件夹）、本地数据位置 +「在文件管理器中显示」、危险区（清空回收站 / 注销并删除本机数据，`--c-danger-border` 描边 + `--c-danger` 标题，需输入确认）。
- **保存语义**：**全部即时生效，无「保存」按钮**。改动后对应行右侧闪一次 `✓`（`--dur-4` 淡出，共 600ms）。
- **三态**：无供应商 → 卡片区显示虚线框「还没有连接任何 AI 服务 / 添加一个」；测试连接中 → 卡片右侧 12px 转圈 + 按钮禁用（`aria-disabled`）；key 无效 → 卡片左边框 2px `--c-danger` + 一行「密钥无效或已过期 · 重新输入」。

## 8. 登录 / 注册 / Onboarding

### 8.1 OAuth 跳浏览器的等待态（重点）

技术路径：**loopback 主 + deep link 兜底**。`127.0.0.1:{随机端口}/callback` 为主（Google/GitHub 不接受自定义 scheme），`bianfa://auth` 作为浏览器拦截时的备用（Tauri `plugin-deep-link`，macOS 需在 `Info.plist` 编译期注册）。全程 PKCE，不传 token 只传 code。

等待态分五段，**每段都必须有出路**：

```
┌──────────────────────────────────────────┐ 420×360
│                                          │
│              ⣿ bianfa                    │
│                                          │
│   ┌────────────────────────────────┐    │ 段②
│   │  ◌  已在浏览器中打开…          │    │ 36
│   └────────────────────────────────┘    │
│                                          │
│   在浏览器里完成登录，然后回到这里。    │ --fs-sm --c-text-2
│                                          │
│   没有自动打开？复制链接 ⧉              │ --fs-xs 文字按钮
│                                          │
│   ──────────────────────────────────    │  ← 20s 后出现
│   等太久了？改用邮箱验证码登录 →        │ --fs-xs
│                                          │
└──────────────────────────────────────────┘
```

| 段 | 时机 | 呈现 |
|---|---|---|
| ① 触发 | 点击「用 Google 继续」 | 按钮内 `--dur-2` 变为 `◌ 正在打开浏览器` |
| ② 等待 | 浏览器已拉起 | 主区如上。**窗口保持前台可交互**，不做遮罩不做 modal |
| ③ 兜底 | `20s` 无回调 | 淡入「复制链接」+「改用邮箱验证码」两条出路 |
| ④ 超时 | `120s` | 状态换为「这次没成功 · 重试 / 换个方式」，**不自动重试**（会重复拉浏览器，极其烦人） |
| ⑤ 成功 | 收到 code | 窗口 `--dur-2` 内切换为 `✓ 欢迎回来，Lin`，`700ms` 后自动进入引导。**同时通过 Tauri `set_focus()` 把窗口抢回前台**——这是最容易被忘、也最影响体感的一步 |

转圈 `◌` 是唯一允许的常驻旋转动画，且只存在于登录窗（不在便笺窗内，不违反红线 2）。

### 8.2 Onboarding：三步，可跳过，且第一步就产出真东西

1. **选一个用途**（工作/学习/个人，3 张 `160×120` 卡）→ 决定默认笔记本与示例内容。
2. **写下第一张便笺**：直接给一张 `220×220` 的真便笺（不是示意图，尺寸与默认新建完全一致——让用户第一眼看到的就是日常形态），占位文「随便写点什么，比如今天要做的事」。写完按 `⌘⏎` 保存。这一步顺带展示 10 色 popover 的第一次出现（默认色 = 石墨，用户可当场按 `Ctrl+4` 换成柠檬）。
3. **两个开关**：开机自启动 / 全局新建快捷键（显示已探测到的可用组合，`Ctrl+Alt+N` 或 `⌥⌘N`）。

页脚永远有 `跳过`（`--fs-xs` `--c-text-3`，左下）。**不做产品功能巡览（tour）**——便笺是三秒钟就该会用的东西，讲解本身就是设计失败的证据。

## 9. 系统托盘 / 菜单栏 + 全局快捷键

### 9.1 托盘菜单

Windows 托盘（右键）与 macOS 菜单栏（左键）行为不同，但用同一份菜单模型：

```
┌───────────────────────────────┐ 240
│  ＋ 新建便笺          ⌥⌘N   │ 28
├───────────────────────────────┤
│  最近                         │ 22 分组头 --fs-2xs
│  ▪ 周五前把设计评审的…       │ 26
│  ▪ API 限流方案 v2           │ 26
│  ▪ ☑ 买咖啡 ☐ 取快递         │ 26
├───────────────────────────────┤
│  ⊞ 打开便笺列表        ⌘⇧O  │ 28
│  ◫ 显示全部便笺              │ 28
│  ◲ 隐藏全部便笺              │ 28
├───────────────────────────────┤
│  ● 已同步 · 2 分钟前         │ 26 状态行(不可点)
│  ⚙ 设置…                ⌘,  │ 28
│  ⏻ 退出 bianfa               │ 28
└───────────────────────────────┘
```

- macOS：左键打开菜单；`Option+左键` 直接新建一张。用 `TrayIconBuilder` + `tauri-plugin-positioner` 的 `TrayCenter` 对齐。图标为模板图（自动适配深浅色菜单栏）。
- Windows 11：左键 = 新建便笺（最高频动作直给），右键 = 菜单。任务栏跳转列表（Jump List）同步提供「新建便笺 / 打开列表」。
- 「显示/隐藏全部便笺」是这个品类的关键动作：会议共享屏幕前一键收，`--dur-2`(140ms) 内全部窗口 `opacity → 0` 并 `set_visible(false)`，位置全部保留。因为只动 `opacity`，不触发合成层新建，15 个窗口同时收也不掉帧。

### 9.2 全局快捷键新建（`Ctrl+Alt+N` / `⌥⌘N`）

`tauri-plugin-global-shortcut` v2.3.x（`register` 支持传数组）。呈现规范：

1. 新窗口出现在**鼠标所在显示器**、光标右下偏移 `(16, 16)`，若越界则向内翻转。
2. 尺寸 `220×220 × --ui-scale`（= 默认新建尺寸），动画 `--dur-2` 140ms：`opacity 0→1` + `scale .96→1`，`transform-origin` 指向光标方向。落位那一下允许用 `--ease-spring`（全 app 三处 spring 之一）。
3. **先出壳后出内容**：窗口壳（纸底色 + `--sh-window`）在第一帧就画出来，webview 内容随后。避免白闪 → 窗口背景色在 Rust 侧就设为**当前主题下该便笺颜色的 `--note-paper` 值**（不是白色，也不是 canvas 灰）。
4. **硬指标：按键到可打字 ≤ 220ms（P95）。** 实现方式是**预热窗口池**——常驻 1 个隐藏的、已完成 webview 初始化的便笺窗口，用掉后立即在空闲时补一个。冷启动路径（应用未运行）不适用此快捷键。
5. 快捷键注册失败（被别的应用占用）时：托盘图标加一个 `--c-warning` 角标，点开菜单第一项变为「新建便笺的快捷键被占用 · 去设置」。**绝不弹窗**。

### 9.3 主题切换时的十几个窗口

托盘/系统改主题时，**全部窗口必须同帧切换**，否则一半亮一半暗极其刺眼：Rust 侧监听系统主题（Win `WM_SETTINGCHANGE` / mac `AppleInterfaceThemeChangedNotification`）→ 主进程一次性广播 `theme-changed` → 各窗口在同一个 `requestAnimationFrame` 里改 `data-theme`，并挂 200ms 的 `[data-theme-switching] *{transition:none!important}`，避免 15 个窗口各跑一遍颜色补间造成掉帧。

## 10. 空状态文案

原则：**一句陈述 + 一个动作，不要感叹号，不要「哎呀」「糟糕」，不要吉祥物。** 中文文案不用「您」（桌面工具用「你」更自然），不用「请」开头（那是求人）。

| 场景 | 主文案 | 动作 |
|---|---|---|
| 列表 · 全新 | 还没有便笺。 | `新建第一张`　·　次行 `--fs-2xs`：`随时按 ⌥⌘N 新建一张` |
| 列表 · 筛选无果 | 没有符合条件的便笺。 | `清除筛选` |
| 搜索无果 | 没有找到「设计评审」。 | `⏎ 以此新建一张` |
| 回收站 · 空 | 回收站是空的。 | 次行：`删除的便笺会在这里保留 30 天。` |
| 回收站 · 有内容 | —— | 顶部：`这些便笺会在删除 30 天后自动清除。`　按钮 `清空回收站` |
| 共享给我 · 空 | 还没有人分享便笺给你。 | 次行：`别人分享时会出现在这里。` |
| 团队墙 · 空 | 这面墙还没有便笺。 | `新建一张` + 拖放区 `或者把便笺拖进来` |
| 标签 · 空 | 还没有标签。 | 次行：`在便笺里输入 # 就能加标签。` |
| AI · 未配置 | 还没有连接 AI 服务。 | `添加供应商` |
| AI · 无历史 | （不显示空状态，直接显示 4 个建议 chip） | —— |
| 离线 | 现在是离线的，改动都存在这台电脑上。 | `重试连接` |
| 加载失败 | 没能读到你的便笺。本机数据还在。 | `重试`　·　`导出本地数据` |

空状态的排版一律：主文案 `--fs-2xl`(20) `--c-text-1`（列表级）或 `--fs-sm` `--c-text-2`（面板级），次行 `--fs-2xs` `--c-text-3`，二者间距 `--sp-3`，与按钮间距 `--sp-6`。

## 11. 微文案原则（中文要像人话）

1. **说人做的事，不说系统做的事。** ✗「同步操作已完成」 ✓「已同步」；✗「便笺创建成功」 ✓（什么都不说，便笺已经在那了）。
2. **成功不需要文案。** 状态本身就是反馈。只有「不可逆」和「延迟可见」的成功才需要 Toast。
3. **错误说三件事，且按这个顺序：发生了什么 → 你的东西还在不在 → 现在能做什么。** ✓「没能同步到云端。改动已存在这台电脑上。重试 / 稍后自动重试」。
4. **不翻译，重写。** ✗「操作无法完成，因为发生了未知错误」 ✓「这次没成功，再试一次看看」。术语只保留用户真的会说的：同步、标签、笔记本、便笺、快捷键。✗「实体」「条目」「资源」「校验」。
5. **按钮写动词短语，不写「确定/取消」。** ✗「确定」 ✓「删除 3 张」「保留我的版本」「先不删」。用户读完按钮就知道点下去会发生什么。
6. **数字要具体。** ✗「部分便笺未同步」 ✓「12 张便笺待上传」。
7. **禁用状态必须解释原因。** 灰掉的按钮旁边（或 tooltip）说清「本月额度已用完」，不留哑谜。
8. **删除类文案不吓唬人也不哄人。** ✗「此操作不可恢复，请谨慎操作！」 ✓「删除后会进回收站，30 天内可以找回。」——**说事实比说警告有效**。
9. **中英混排里的英文保持原样，不译不加空格靠字体处理**：`Markdown`、`Claude Sonnet 4.5`、`API key`。但 UI 动作词一律中文：「导出」不是「Export」。
10. **长度纪律**：按钮 ≤ 6 字，主文案 ≤ 20 字，次级说明 ≤ 40 字且必须是完整句（有句号）。超了就是没想清楚。
